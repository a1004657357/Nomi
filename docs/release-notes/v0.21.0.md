# Nomi v0.21.0

v0.21.0 把 Nomi 从“在画布上调用一次模型”继续推进为一套可控制、可暂停、可返工的 AI 视频制作流程。本次最直接的变化，是 ComfyUI 多输入工作流和一批 2026 现役图像/视频模型真正进入同一张创作画布；多镜制作、素材传输、MCP 与桌面运行地基也同步加固。

## 这次最值得用的能力

### 1. ComfyUI 多图与图视频工作流不再混线

- 导入工作流后，每一个图片或视频输入都有自己的槽位、连线和持久身份；多张参考图不会再被压成一个通用数组，也不会在重开项目后串位。
- 支持同一工作流中的多图、图 + 视频输入，以及按实际输出节点识别图片或视频结果。
- 长模型枚举可以搜索，工作流画布支持光标锚定缩放，并与生成画布共用 Mac 触控板偏好。
- 本轮真实应用走查覆盖 3 张图片，以及 3 张图片 + 1 段视频的独立上传、冷启动恢复、精确请求绑定和结果解码。

### 2. 新一代视频模型进入同一套创作方式

- **Wan 3.0**：支持 KIE 标准版 / 高速版和 APIMart，包含文生视频、首帧、首尾帧、全能参考四种模式；全能参考最多可放 10 张图、5 段视频和 5 段音频。
- **MiniMax H3**：支持 KIE 与 APIMart 的文生、首帧/首尾帧和多模态参考；APIMart 另提供 Context-IR 提示词增强与 768P → 2K 再生成入口。
- **火山方舟**：修复原生端点地址、供应商身份和模式切换参数三条链路；新增 Seedream 5.0 Pro 与 Seedance 2.5 档案。
- **2026 现役生图模型**：新增 Nano Banana 2 / Lite、Seedream 5 Pro / Lite、Qwen Image 3.0 / Pro、Flux 2 Pro 等档案，并保留不同渠道真实的参考图数量、字段和模式差异。
- **Gemini / Antigravity**：新增分组模型设置、Gemini 文本/视觉路由，以及 Antigravity 本地文本、视觉、异步生图和改图链路。

### 3. 多镜制作从“批量发任务”变成可管理的制作过程

- 生成前可以看到逐镜价格与本次计划，再统一确认是否执行。
- 批次支持预算停止、手动停止、恢复，以及先确认人物/场景形象再继续后续镜头。
- 已生成镜头可以定向返工，保留版本记录；暂停后可以从原位置继续。
- 结果进入时间轴收敛为一条受控采纳路径，不再由多个入口各自修改成片。

### 4. 素材与画布更适合真实项目

- 素材库支持原生文件粘贴与拖入，直接复制本地图片，不做无意义的二次编码。
- 本地媒体的 data URI、base64、文件扩展名和持久化路径更可靠；视频节点由用户主动播放时会保留声音。
- 窄窗口下的生成卡会自动寻找可用空间，提示词、模型和主按钮不再被压成不可操作的缝。
- 模型发现与选择器在刷新失败、结果为空和切换供应商时更能恢复，不容易卡在一个失效模型上。

## 这些能力为什么现在更可靠

- 本地能够判断的素材、模式和参数错误，会在请求发出前拦截，减少无效调用；APIMart MiniMax H3 的互斥素材与缺失参考等错误不会先进入网络请求。
- Antigravity 本地执行额外绑定 CLI 可执行文件身份、版本和能力验证；素材读取、解码和执行准备在任务受理前完成。
- MCP / IPC 增加 sender、owner、取消、并发确认和 schema 边界，降低外部 Agent 重复提交或跨任务操作的风险。
- Electron 升级到 43.4.1，并增加 Windows 走查、Mac 双架构打包和真实用户旅程证据。

## 升级说明

- 现有项目、设置、模型配置和本地素材继续沿用原数据目录。
- 正式包提供 macOS Apple Silicon、macOS Intel 和 Windows x64。
- **macOS 最低系统版本提高到 macOS 12 Monterey。** macOS 10.15 / 11 用户请继续使用 v0.20.1。
- macOS 包未签名、未公证；Windows 包未使用 Authenticode。首次安装请按 README 的系统提示操作。

## 诚实边界

- ComfyUI 多输入走查使用本地模拟 HTTP 服务和可解码媒体，验证的是槽位、传输、恢复与结果合同，不代表用户私有 GPU 工作流的推理画质。
- Wan 3.0 的 KIE 标准、KIE 高速、KIE 首帧与 APIMart 全能参考做过真实额度验收；火山 Seedream 5.0 Pro、Seedance 2.5 和部分 Gemini/Antigravity 能力仍受账号权限或上游额度限制，可用性以用户自己的渠道为准。
- 非硬切转场目前仍只保存为时间轴元数据；导出器尚未把 `dissolve`、`fade`、`match_cut` 或 `whip_pan` 渲染为视觉转场。
