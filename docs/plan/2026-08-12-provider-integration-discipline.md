# 供应商接入纪律：一次接完 + 出处可追

> 2026-08-12 用户拍板。触发事件：Seedance 2.5 档案里 4 个契约数字（参考图/视频/音频上限、
> 比例默认值）全是我们自己填的，而文件头注释白纸黑字写着「契约逐项对账自 kie 官方文档」。

## 一、根因不是「填错了」

填错随时会再发生。真正的根因是**「声称对过」与「真的对过」之间没有任何验证手段**：

- 注释是自由文本，写什么都行，没人能反证
- 文档地址散落在注释里，换了人／过了三个月，没人知道去哪复核
- 「接入」没有完成标准 —— 接到能跑就停，剩下的能力悄悄丢掉（白膜卡在第 4 段就是这么来的）

所以修在根因层 = **让出处变成结构化数据 + 加门岗**，而不是再写一句「下次要仔细」。

## 二、三条规则

### G1 文档地址必须落库，不落注释

每个档案声明 `sources: { url, checkedAt, vendorKey? }[]`——结构化字段，不是注释里的一行字。
好处：能被门岗检查、能被聚合成索引、复核时一眼知道去哪。

### G2 一次接完，不做「先接个能跑的」

接入一个模型 = 把该模型在该供应商下的**全部**能力对完，逐项列清单：

| 必对项 | 说明 |
|---|---|
| 端点 + 方法 + 鉴权 | 含 base 路径差异 |
| 全部参考通道 | 图/视频/音频/首尾帧，**各自的字段名与上限** |
| 全部标量参数 | 枚举值、默认值、取值范围 |
| 模式互斥约束 | 哪些不能同时用（如首尾帧 vs 多模态参考）|
| 供应商级硬约束 | 如 apimart「首尾帧模式 size 必须 adaptive」|
| 轮询端点 + 状态机 | 状态词表 |
| 产物位置 | 响应里 URL 的确切路径 |

**没查到的写「文档未写明」，不许填我们猜的。** 猜的数字比缺失更坏——缺失会被发现，猜的会被当成真的。

### G3 数字必须能追到出处

任何上限 / 枚举 / 默认值，注释要能指到文档的哪一项。改动契约数字的 PR 必须同时更新 `checkedAt`。

## 三、门岗（让规则自动执行）

`pnpm run check:archetype-sources`：

1. 每个 `ModelArchetype` 必须有非空 `sources`，每条含合法 `url` + `checkedAt`（ISO 日期）
2. 存量未登记的进白名单，**棘轮只减不增**（与 filesize / tokens / i18n 门岗同款纪律）
3. 门岗进 `pnpm run gates`

为什么是棘轮而不是一刀切：现存 40+ 档案不可能一次补全出处，一刀切会让门岗永远红、失去意义。
棘轮保证「新接的必须合规、老的只能变少」。

## 四、不做什么

- **不做 checkedAt 过期红灯**（如「超过 90 天就报错」）。文档不常变，过期红灯会变成噪音，
  最后大家习惯性跳过——门岗一旦被习惯性忽略就等于没有。复核由改动驱动，不由日历驱动。
- **不自动抓取文档比对**。供应商文档站结构各异、常有反爬（kie.ai 就返回 403），
  自动比对的假阴性会给出虚假的安全感，比没有更危险。

## 五、验收

- [x] `ModelArchetype.sources` 字段落地，seedance25 填上两家文档地址
- [x] 门岗脚本 + 棘轮基线 + 进 gates（三种失败模式都验证过会红）
- [x] 规则写进 `docs/engineering-rules.md`（R5 强化，G1/G2/G3）
- [x] 文档地址索引 `docs/integrations/provider-api-docs.md`
- [x] 应用第一例：apimart Seedance 2.5 完整接入（字段名与 kie 不同 + adaptive 硬约束）
- [x] 真机走查：四模式齐、首尾帧无比例控件、参数面板与文档一致
- [x] **真实生成 E2E（2026-08-12，用户提供的 apimart key，跑完即弃）**

### 真实生成结果（用生产执行器 + 我们 seed 里的 mapping，不是手搓请求）

| 用例 | 发出的关键字段 | 结果 |
|---|---|---|
| 文生视频 | `size:adaptive, resolution:480p, duration:4` | ✅ 120s 出片 |
| 全能参考 + 参考视频（**白膜走的就是这条**）| `video_urls:[...]` | ✅ 133s 出片 |
| 首尾帧 | `image_with_roles:[{url,role:first_frame}]`、**`size:"adaptive"`（盖住了节点上残留的 16:9）** | ✅ 出片 |

第三条是这次最该验的：节点从别的模型切过来会残留 `size:"16:9"`，档案 `fixedParams` 必须盖住它，
否则首尾帧会被 apimart 拒。**端到端确认发出去的确实是 `adaptive`。**

白膜结论落地：Seedance 2.5 的 3D 白膜没有专用字段，就是当参考视频（或参考图）喂进 `video_urls`
/ `image_urls`——真跑通了，不是推断。
