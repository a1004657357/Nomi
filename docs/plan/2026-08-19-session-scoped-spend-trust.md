# 会话级付费信任：治「反复去软件确认」

2026-08-19 · 用户拍板做（在「会话级信任 / 额度包 / 先只落地 #103」三选中选了会话级信任）

## 为什么做

2026-08-18 用户原话：「那这样反复去软件确认 不是太麻烦了」。重点在**反复**。

[PR #103](https://github.com/aqm857886159/Nomi/pull/103) 只解决了「在**哪儿**确认」（判据从「App 开没开」换成「客户端能不能替我们问真人」），没解决「**每次都要**确认」。就算 #103 落地、用户换去 Codex，每生成一次照样弹一次——只是弹的地方变了。

而且 #103 对用户当下的主力客户端 **Claude Code 完全不生效**（它不声明 elicitation，落回 App 卡片）。所以「少弹几次」是唯一能让用户**今天**就少点很多下的做法：它对**所有**客户端生效，包括走 App 卡片那条路。

## 做什么

一条 MCP 会话内，某项目**首次**付费生成照旧问真人；批准后记一次信任，该会话该项目后续生成不再逐次问。

- **信任粒度**：`projectId`（每条 MCP 连接一个协议实例 → session 天然隔离，键只需 projectId，与 `mcpPlanTrust` 同构）。
- **生命周期**：纯内存、挂协议实例闭包，连接断即亡，**不持久化**。
- **两条路都要生效**（关键，否则 Claude Code 用户又一次白等）：
  - 客户端支持 elicitation → 首次 elicit 批准后记信任；
  - 客户端不支持、走 App 确认卡 → **invoke 成功即意味着真人点过卡**（没点 → 无令牌 → `assertAndConsumeSpendGrant` 抛错 → invoke 失败），故成功后记信任。

## 三条不许省的边界

### 1 首次那一问必须说清它在授权什么（否则是骗同意）

用户以为自己批的是「这一张」，实际批的是「本会话这个项目往后都不问」。不写明 = 欺骗性同意，违反 D4「缺口明着标」。故首次提示词必须含「批准后本会话在这个项目里的后续生成不再逐次询问」。

App 确认卡那条路同理——卡上也要写明（`SpendConfirmInfo` 加一句副文案）。

### 2 要有再问阈值，不能真·无限

用户选的是「会话级信任」而非「额度包」，所以**不引入用户要理解的额度概念**；但一次批准换无限花钱，跑飞的 agent 循环能把额度烧干。折中：内部计数，同会话同项目连续放行到阈值就再问一次，提示里说明为什么又问。

`SESSION_TRUST_REASK_AFTER = 20`：够覆盖一次正常创作会话（一集分镜十几个镜头），又把单次批准的最坏损失钉在 20 次生成内。这是安全上限、不是用户要管的配额。

### 3 主进程硬闸一字不动

`assertAndConsumeSpendGrant` 照旧逐次校验；信任只免掉「问」，不免掉「令牌」。每次生成仍各自铸自己的 node-bound 令牌（不复用、不跨节点借用）。

## 为什么不与 mcpPlanTrust 合成一个

方案门是**免费可撤**、无阈值、无计数、文案不同；付费门要计数 + 再问 + 授权范围披露。硬合会做出一个带一半没人用的参数的抽象。共同点只有一个 `Set<projectId>`（8 行），不值得为它造抽象层。

## 验收门

- 单测覆盖：首次问 / 命中信任不问 / 换项目重问 / 拒绝不记信任 / 到阈值再问。**每条都要验它在旧代码下会失败**（不许恒真的假绿）。
- 真机走查：同项目连发两次生成 → 第二次**不弹卡、不 elicit**，仍真落资产（mock vendor 零额度）。
- `pnpm run gates` 全过。

## 已知缺口（诚实标出，不藏）

**这份standing授权用户看不见、也撤不掉**（只能断开 MCP 连接）。理想是 Nomi 里有个「本会话已授权此项目自动生成 · 撤销」的可见入口。那是 UI 改动，要走 R8 出样张 + 拍板，故不塞进本次；本次先靠「提示里说清 + 会话即亡 + 阈值再问」把风险按住。下一轮补。

## 回滚

信任查询是纯增量分支：`mcpSpendTrust.ts` 删掉 + `mcpProtocol.ts` 的信任分支还原，即回到 #103 的行为（每次都问）。无数据迁移、无持久化状态。
