# ComfyUI 工作流设置：滚轮缩放

> 本文保留首轮实现与验收记录。2026-08-26 后续用户确认补齐 Mac 手势并授权完成后提交 PR；最新交互合同与交付要求见 `2026-08-26-comfyui-mac-gestures.md`。下文「不提交」是当时的约束，已被新授权取代。

## 范围与交互合同

用户明确指定截图中的「工作流设置」节点图；沿用截图布局，不增加控件、不改生成画布的交互设置。
普通滚轮向上放大、向下缩小，不要求按 Ctrl；缩放以鼠标位置为锚点，保留 +/-、适应和空白拖动。
左侧参数、节点列表、节点菜单的滚动不被画布抢走。上下限沿用 30%–200%。
使用 brainstorming / systematic-debugging / test-driven-development 核对现状、固定边界、先红后绿；视觉基准为用户提供的真实截图，没有新增视觉设计。

## 现状与依据

- `WorkflowGraphCanvas.tsx` 只有 zoomBy 和 pointer 拖动，没有 wheel 监听。
- 生成画布已有 `getWheelZoomFactor`，按像素/行/页统一增量；抽到 utils 供两处使用，不复制算法，不引入图库。
- zoom 和 offset 改成一次函数式视口更新；拖动用增量，避免滚轮修正 offset 后被旧拖动起点覆盖。
- 图/列表切换会卸载 viewport，监听与适应必须跟真实挂载状态同步。
- React 官方 effect 清理/函数式更新：[useEffect](https://react.dev/reference/react/useEffect)（Context7 2026-08-26 查阅）。
- 原生 wheel 使用非 passive 监听防止页面随动：[MDN wheel](https://developer.mozilla.org/en-US/docs/Web/API/Element/wheel_event)；设备单位：[deltaMode](https://developer.mozilla.org/en-US/docs/Web/API/WheelEvent/deltaMode)（2026-08-26 查阅）。

## 验收矩阵

- 小图：在节点上连续滚轮，读清节点、打开菜单并修改暴露字段，保存后重开核对落库。
- 多节点：48 节点图定位、缩放、拖动；80 节点默认列表滚动，切换图后仍可缩放并适应。
- 边界：30%/200%不漂移，行/页/细粒度滚轮与 Ctrl 滚轮，水平滚轮不缩放，边拖边缩放不跳。
- 隔离：侧栏与菜单滚动不改变视口；重复图/列表切换、关闭重开不丢监听/不重复监听。
- 既有 +/-、适应、节点点击、深浅主题、前一轮视频/长模型名完整走查回归。

## 结果

走查发现同一入口的存量问题：点击非第一条工作流进入设置时，目录尚未加载的空数组会清掉 `initialModelKey`，随后错误选择第一条。浅色冷启动走查已复现（点击 48 节点行却打开 5 节点新导入工作流）。在目录层增加显式 ready 状态，选择/草稿加载只在对应后端目录完成后运行；不改变目录格式或远程协议。

独立体验复核指出：放大至 200% 后靠下节点的菜单可能被画布裁切。补菜单边界实测；菜单沿用原样式与内容，只按真实高度限制在可见画布内，过长时内部滚动，不重新设计控件。

最终：范围单测 29/29；全仓 gates exit 0（753 文件 / 6617 测试通过，1 文件 / 1 测试跳过）；正式 Electron 完整走查 exit 0。含 5/48/80 节点、长菜单内部滚动、列表菜单随滚动定位、冷启动后打开指定工作流、浅色模式和字段落库。完整证据见 `docs/research/2026-08-26-comfyui-wheel-zoom-report.md`。没有 commit/push/PR。
