## 本轮：分类桶根因 + 真实往返

### A. 模型分类分错桶（反馈「grok 接不进去」「MiniMax H3 想接」的直接障碍）

实测：`grok-imagine` → text、`MiniMax-H3` → text、`hunyuan3d-v3.1` → text。

- **症状层**：关键词表滞后于新模型族。补词能立刻止血，但下个月新模型族照样中招。
- **根因层**：猜错之后**用户没有可发现的纠正出口**。代码注释写着「UI 给下拉随手改」，
  但用户不会去改——因为生成失败时报的是「模型未配置」，没有一个字指向「它被登记成了文本」。
- **本轮做**：① 补齐已知模型族 + 补上缺失的 `model3d` 桶（止血，带回归钉）
  ② 分类结果进接入矩阵，新模型族漏了会被测试当场抓住
- **另开**：把「未配置」类报错改成指向真实缺口（属用户可见文案改动，走 R8）

### B. 真实往返测试（本轮主体）

矩阵目前只验「我们打算发出什么」，没验「真发出去会怎样」。补一层**起真实 HTTP 服务器**的往返：

| 覆盖 | 验什么 |
|---|---|
| 文本 | chat/completions 往返、流式、非流式 |
| 图片 | 同步出图 → 响应解析（`data[*].url` / base64 内联 / markdown 包裹） |
| 视频 | 异步 create → task_id → 轮询 → 状态流转 → 取产物 |
| 音频 | 二进制音频响应 |
| 异常 | 401/404/429/500、超时、返回形状不符、空 data |

重点怀疑区：**响应解析**目前靠「防御式试 11 种路径」兜底，从没被系统性验过。
