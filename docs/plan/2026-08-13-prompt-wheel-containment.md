# 提示词滚动不穿透画布

## 问题与根因

- 图片/视频生成节点的提示词编辑区可以正常内部滚动，但滚到顶部继续向上、或滚到底部继续向下时，画布会接管同一个滚轮手势并缩放/平移，导致节点从视野里跳走。
- 提示词区当前使用 React `onWheel` 停冒泡；画布在 stage 上使用原生 `addEventListener('wheel')`。原生 stage 监听先执行，React 合成事件随后才执行，因此局部拦截在边界处来不及。
- 画布的统一滚动判定还把“可滚容器已到边界”明确视为“不再由容器消费”，主动把手势交回画布。

## 范围

- 从画布滚轮入口统一识别“命中了真实可滚动区域”，不再按当前滚动位置把边界手势交给画布。
- 保留横向/纵向主轴判断：纵向提示词只保护纵向滚轮，横向时间轴只保护横向滚轮。
- 删除提示词节点上已证明时序无效的专用 `onWheel` 实现，避免两套并行防线。
- 补纯函数回归测试，并扩展真实长提示词 Electron 走查：内部能滚、顶部继续上滚不动画布、底部继续下滚不动画布。

## 不动项

- 不改变用户选择的画布滚轮模式（缩放优先 / 平移优先）。
- 不改变提示词编辑器尺寸、排版和滚动条样式。
- 不改变 Ctrl/Command + 滚轮的画布缩放语义。

## 验收

1. 长提示词在编辑区中间正常上下滚动。
2. 到顶部继续向上滚，提示词停在顶部且画布 transform 不变。
3. 到底部继续向下滚，提示词停在底部且画布 transform 不变。
4. 鼠标位于画布空白处时，滚轮仍按当前设置缩放或平移。
5. 单测、真实 Electron 走查与项目全门通过。

## 回滚

单独回滚本次提交即可恢复原来的方向性边界交接逻辑；不涉及数据迁移。
