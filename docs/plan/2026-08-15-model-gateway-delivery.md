# 模型网关接入完整交付计划

日期：2026-08-15
目标分支：`origin/main`

## 用户摩擦与根因

1. 局域网网关无需鉴权，但接入 UI 强制 Key，目录保存又拒绝空凭据。
2. 图片/视频模型验证失败后虽显示已启用，却没有可执行 mapping；用户无法自行试跑。
3. 公网中转抓不到文档时被直接判死；文档被错误地当成接入准入证。
4. 修复曾只存在于侧分支，却被描述为“已解决”；实现状态与交付状态混为一谈。

## 范围

- 自定义/中转预设提供“无需 API Key”开关，并将 `authType: none` 贯穿拉模型、测试、保存和目录持久化。
- 无鉴权保存时删除该 vendor 的旧凭据，避免历史 Key 继续生效。
- 新媒体模型即使自检失败也保存候选 mapping；已有 exact mapping 在失败重试时保持最后一次可用配置。
- 保留并验证无文档时的通用 OpenAI 兼容回退。
- 统一模型管理入口和设置弹层修复随同交付。
- 增加交付状态规则：只有验证通过且修复提交已进入远端目标分支，才允许称为“已解决”。

## 不动项

- 官方供应商默认仍要求 Key，不展示无鉴权选项。
- 文本模型继续走 AI SDK，不创建 HTTP mapping。
- 编译阶段没有生成候选调用契约的媒体模型，不凭空创建 mapping。
- 不修改模型自检失败的可见状态；保留失败信息供用户判断和自定义调用。

## 回滚边界

- UI、目录凭据、mapping promotion、规则文档分别形成可审计提交。
- 若完整门禁失败，不同步 `origin/main`，状态只能报告为“实现中/待交付”。
- 不删除原有侧分支，直到 `origin/main` 已确认包含修复提交。

## 验收门

- 无 Key 自定义 HTTP 网关可以拉模型、测试、保存并被视为可用；切到官方预设后恢复 Key 要求。
- 新图片/视频模型自检失败后仍有 enabled mapping；旧 mapping 不被失败草稿覆盖；文本没有 mapping。
- 无文档公网中转不因文档为空直接失败。
- 聚焦回归、全量单测、类型检查、构建、仓库 push 前全门、桌面真实 UI 走查全部通过。
- `git merge-base --is-ancestor <fix-commit> origin/main` 返回成功后，才报告“已解决”。
