# 提示词粘贴误复制节点修复（2026-08-09）

## 用户摩擦

用户从 Nomi 外部复制一段提示词，再粘贴到生成图节点的提示词编辑器时，文本能正常进入编辑器，但画布还会额外复制一个内部剪贴板中残留的图片节点。

根因是画布为 `Cmd/Ctrl+V` 安排了一个延迟 120ms 的节点粘贴兜底。真正的 `paste` 事件落到文本编辑器后，旧逻辑先判断“编辑器应放行”并直接返回，没有取消已经安排的兜底；此外只检查事件目标，没有用当前焦点补偿 Electron/富文本编辑器中的目标漂移。

## 范围

- 文本编辑上下文同时检查事件目标与 `document.activeElement`。
- 兼容 `input`、`textarea`、`select`、`contenteditable=true/plaintext-only` 和文本节点目标。
- 任何真实 `paste` 事件到来时先取消节点粘贴兜底，再决定交给文本编辑器还是画布。
- 保留画布空白处粘贴内部节点、外部图片、视频和媒体 URL 的现有行为。

## 不动项

- 不修改提示词编辑器的内容格式、素材引用 chip 或生成参数。
- 不引入新的剪贴板协议或并行粘贴入口。
- 不改变节点复制后的编号、位置避让和撤销语义。

## 结构保证

- 纯函数测试锁住事件目标、当前焦点和文本节点父元素三类编辑上下文。
- 源码中的真实 `paste` 处理器必须在编辑态早退前取消兜底。
- 定向测试、类型检查、lint 和完整 gates 通过。

## 验证结果

- 快捷键、系统剪贴板媒体和画布 store 定向回归通过。
- 隔离 Electron 真走查通过：内部先复制图片节点、系统剪贴板再写外部提示词，粘贴后节点数保持 `2 → 2`，提示词文本正常写入。
- 完整 `pnpm run gates` 通过：453 个测试文件、4016 个测试通过，renderer 与 Electron 构建成功。
