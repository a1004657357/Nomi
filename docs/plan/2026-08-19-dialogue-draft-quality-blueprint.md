# 对话生成高质量视频初稿：蓝图（2026-08-19）

> 北极星（用户原话提炼）：**和 AI 对话，生成质量足够高的 AI 视频初稿。**
> 质量的定义：**用户拿到初稿时，80% 的「崩坏问题」（脸漂移/景跳变/画面畸变/方向跑偏）已被流程消化，剩下的是 20% 的品味问题。**
> 依据：四路调研交叉验证——A `docs/research/2026-08-19-short-drama-pipelines.md`（业界 13 对象）、B `2026-08-19-script-to-video-frameworks.md`（ViMax 源码级 + FilmWorld）、C `2026-08-19-conversational-creation-ux.md`（对话交互）、D `2026-08-19-nomi-draft-capability-inventory.md`（本仓现状，file:line）。

## 一、三条交叉验证出的定理（蓝图的地基）

**T1 审片闭环是分水岭，且是我们的差异化空档。**
B：纯 plan-then-generate 开环被反复证明「文本对齐够、视觉一致性崩」，拉开质量的是「参考图注入 + VLM 判分 + 定向重试」闭环（schema 只是入场券）。A：商业产品（可灵/即梦/海螺/Runway/Vidu）**全部只有人眼质检**。D：我们的 `shotVerify`（3 轴 VLM：身份/构图/连贯 + 对账卡 + 回灌重生成）**已建成，但只挂在手动画布批量路径**，MCP/production run 零引用。→ **最高杠杆的一件事是接线，不是造新。**

**T2 一致性的抓手是「圣经冻结 + 参考图 I2V」，不是更长的文本描述。**
A：全行业 make-or-break 第一步 = 生成任何视频前先批准并**冻结**角色圣经（权威肖像/服装/禁改项），跳过 = 脸漂移 + ~25% 镜头返工；I2V 公认比 T2V 稳一个数量级。B：ViMax 的 static/dynamic 特征分离（身份只看 static，服装允许换）+ 参考图按时间倒序注入。D：我们有定妆卡/场景卡 + 参考边机制，但断在「锚必须先出图且要像」——没有「冻结/批准」仪式，也没有下游强制。

**T3 确认的正确形态：三档闸门 + 一屏收敛 + 定点改。**
C：业界共识 = 澄清最多 3 题一轮问全（或不问、直接给可改草案）；「两三处定点改 > 整体重生成」是 Suno/LTX/Claude artifacts 三方独立命中的铁律；HITL 配比「95% 自主 + 5% 拦截」。现役内容创作 MCP server **无一有收敛或确认步**——开场收敛 + Block 档确认是我们的结构性护城河，且我们已有的付费路由 + 会话信任正是业界还没补的洞。

## 三、落地四波（依赖顺序，每波独立可交付）

**W1 · 审片接线（最高杠杆，全是接线/小刀）**
1. `shotVerify` 接进 MCP generate / production run 生成后路径（触发点对齐 `batchPlanPreview.ts:170-178` 的现有用法）；判分不过阈值 → ViMax 定向重试 prompt（「保背景只换角色」，B §3.5 原文）自动重滚，K≤3、k=2，预算计入确认闸披露。
2. 修 `production.plan-directions` 已建未接 bug（`capabilityApplyHandler.ts` 补 case，D#4）。
3. 审片结果进结果文案与进度帧（「审片：过/重试/标注」），诚实标注不达标镜头（D4）。
验收：J-MCP 生成旅程里人为投放一个崩脸镜头 → 自动检出并重试 → 交付物带标注；`shotVerify` 在两条路径（画布/MCP）行为一致。

**W2 · 一致性地基（圣经冻结 + I2V 默认）**
1. 角色圣经：定妆卡数据模型加 `static/dynamic` 特征字段 + `frozen` 状态；冻结门 = 样片门语义扩展（gate 机制已有）。**内容生成器 = 全资产大师 V3.0**（`assetMasterPrompt.ts`，素材规划模式已在用）：其角色概念表/场景七层/道具卡输出落进圣经结构化字段，不另写第二套拆资产 prompt（P1）；道具卡顺带补「道具锚无专用节点种类」缺口（D#7）。
2. 未冻结锚 → 批量生成拒发（结构强制，不靠 agent 自觉）；镜头生成默认两跳「参考图→首帧 I2I→I2V」，T2V 降级为无参考兜底。
3. 首尾帧锚定：StoryboardPlan 加 `ffDesc/lfDesc`（B §3.2），相邻镜续接用上镜尾帧。
验收：跨 12 镜同角色身份判分（shotVerify identity 轴）均值 ≥4/5；对照关掉冻结门的基线可量化提升。

**W3 · 对话交互层（收敛 + 三档 + 指改）**
1. 开场收敛：elicitation enum+enumNames 一屏 ≤3 题（C §1.3），每题带「按你判断」；不支持 elicitation 的客户端 → 文字候选列表（通道①）。
2. 三档闸门显式化：定点改（改 #3）= Auto + 一句回执；整体重来 = Notify；花钱/冻结/方向 = Block。写进工具结果文案与 agent 指引（工具 description）。
3. 中间产物一律编号镜头列表输出（story-order ID），编号即指改地址；每镜挂节点级深链（需深链粒度从 project 扩到 node——`mcpToolResults.ts:478`）。
验收：全程确认次数 ≤4 次（收敛 1 + 冻结 1 + 批次 1 + 可选方向 1）；「改 #3」不触发任何弹窗。

**W4 · schema 深化（后置，B 定理「schema 是入场券」）**
1. StoryboardPlan 补镜头语言字段：`variationType∈{large,medium,small}`（审片路由键）、`camIdx` 机位复用、运动描述禁角色名改外貌特征（校验器）。
2. `NodePromptOptimizer` 加 rubric：读 `director-shot-translation` 污染词铁律 + 运镜翻译表做校验（D#5）。
3. 剧本结构化（场/幕/角色表）+ drama.short playbook（短剧官方编排，走 W1-W3 的通用闸）。

## 四、核心取舍（已做的判断）

**做在哪一层：通用闸，不做进单一 playbook。** 冻结门/确认闸/审片环全部做成**结构机制**（网关/工具层强制，任何路径都过）——playbook 只是编排者之一，自由式画布同样受益。理由：P4 通用第一；A 报告显示同构竞品（DramaClaw/drama-skills）把纪律写在 skill 文本里靠 agent 自觉，而我们能在结构上强制——这是工程差异化。代价：比「先糊一条 drama playbook」慢一波，但不会出现「playbook 路径高质量、自由路径照旧崩」的并行版（P1）。

**审片花额度：默认开，预算写进确认闸。** 每镜 +1 次 VLM 判分 + 最多 1 次定向重试，换掉的是「用户人眼看完再手动重滚整轮」（业界实测 ~25% 返工率）。参数取实证值：k=2（更高引入选择噪声）、K≤3、单 judge 不投票（集体判分更差，B §4.3）。

**诚实边界（D4，管线修不了的）**：单镜时长上限（5-15s）与动作物理合理性由底模决定；Claude Code 终端用户肉眼看不到图（转述+深链补位）；本机壳形态不声明 elicitation → Block 档退 App 卡（会话信任已把它压到每项目一次）。

## 五、与既有体系的对接

- 五门模型（08-11 研究 §7.5）不变：本蓝图的「冻结门」= 样片门语义扩展，「确认闸」= 预算合同门的批次形态，「开场收敛」= 方向门的 elicitation 化。不新造第二套确认系统。
- R16 验收：新增 J-剧集 journey（一句话 → 六幕全程 → 初稿），指标沿用 mcp-journey JSONL（确认次数/审片检出率/重试率/身份判分）。
- 数据流原则：沿用「确认时一次性单向转换」（D §3），**不做**剧本↔分镜↔画布双向活同步（复杂度不换质量）；指改一律落在结构对象上再重转换。
