# Nomi 反馈与分享中心

日期：2026-09-01
状态：✅ 已交付；Tally 私密表单和 v0.21.0 应用入口均已验收，代码已提交 PR

## 目标

让用户在不改变 Nomi 本地优先承诺的前提下，随时完成三件事：

1. 分享官网和 GitHub；
2. 反馈模型接入、生成、上传等问题；
3. 在用户明确确认后附带截图和经过脱敏的诊断信息。

核心判断：反馈入口只有一个家（设置 → 关于 → 反馈与分享），错误卡只提供情境入口；不增加常驻顶栏按钮，不做后台遥测。

## 当前真实基线（v0.21.0）

- 当前仓库版本以 `package.json` 为准：`0.21.0`。样张中的版本号必须从这里读取，不能手写历史版本。
- 设置弹窗是 `src/workbench/settings/SettingsDialog.tsx` 的 760px 外壳，关于内容由 `src/workbench/settings/AboutSection.tsx` 承载。
- 现有 GitHub Issue Form 已收集系统、版本、复现步骤、截图和日志；空白 Issue 已关闭。GitHub 保留为公开反馈入口。
- 截图热键链路已经存在：Electron 整屏捕获 → 本地素材 → `ScreenshotCropOverlay` 选区裁剪；反馈中心只保留本地截图文件名，不把截图字节放进发件箱。私密表单和 GitHub 页面各自提供最终附件选择。
- 本地事件日志和 Agent trace 默认落在项目本机；当前不是遥测服务，也不应在本任务中改成后台上传。
- 私密表单：`https://tally.so/r/GxPrx2`，匿名可访问、附件上限 10 MB；Nomi 打开链接时通过 Tally hidden fields 自动带入版本、平台、架构、阶段和 Provider/Model 上下文，用户仍可在浏览器中改正。

## 设计方向（v2：先做一件事）

### design-thesis

- **受众与任务**：刚遇到问题、只想尽快告诉 Nomi 团队的创作者；或想把 Nomi 分享给朋友的人。
- **三秒信息**：我只需要先选“告诉我们一件事 / 分享 Nomi”中的一件事。
- **首要动作**：选择意图，而不是先选择 GitHub、Tally、诊断包和隐私选项。
- **内容节奏**：三项入口 → 一个轻量表单 → 选目的地、可展开查看将附带的脱敏字段，然后由用户在浏览器里最后提交（无独立的应用内二次确认弹窗）。
- **视觉方向**：冷静的诊断台（calm diagnostic desk）。沿用真实 `SettingsDialog` 的暖中性底、黑色主按钮、蓝紫 accent、密度优先；不使用营销式插画、渐变或卡片墙。
- **反模式**：首屏不放页签、不放双目的地单选、不放诊断字段清单、不放长隐私说明、不让用户先读技术条款。

真正的取舍是：**入口速度 vs. 立即展示全部治理细节**。本版选择入口速度，把数据范围、目的地和训练用途放到用户已经选择“报告问题”之后的渐进披露层。

样张文件：`docs/design/mockups/2026-09-01-feedback-share-center.html`。仓库已有的 `2026-08-02-u2-after/03-settings-about.png` 仅用于核对外壳几何，是历史截图，不代表当前版本号或当前功能状态。

## 用户路径

### 入口

- 规范入口：设置 → 关于 → 反馈与分享。
- 情境入口：模型接入或生成失败卡 → 反馈此问题，带入当前安全诊断摘要。
- 低频提示：一次成功或失败后仅提示一次，不阻断工作流；用户拒绝后本次会话不再提示。

### 渐进路径

- 反馈中心首页只显示两个意图入口：告诉我们一件事、分享 Nomi；问题/建议分类延后到反馈表单。
- 分享页只显示官网和 GitHub 两个链接，不混入反馈设置。
- 报告页先让用户选功能阶段并写一句话，截图和诊断信息都是可选项。
- “公开 GitHub / 私密 Tally”延后到提交前确认，不在第一屏制造目的地决策。Tally 只接收用户在浏览器中确认的反馈字段，以及 Nomi 明确限定的版本/环境/阶段/Provider/Model 上下文。
- 版本号、操作系统、架构和模型上下文由 Nomi 自动填入；表单保留可选修正字段，避免用户为机器已知信息重复劳动。

### 安全诊断包

默认可带：版本、系统、语言、功能阶段、Provider/模型类别、错误分类、HTTP 状态码/请求 ID（若安全）、延迟和文件大小区间、错误指纹。

默认不带：API Key、Authorization、完整 Prompt/Agent 对话、项目路径、原始素材和用户身份信息。对话、素材和截图必须各自独立确认，不能由一个总开关隐式包含。

## 交互契约

- idle：默认停在三个意图入口，不预选目的地，不预填诊断包。
- focus/hover：所有链接和提交控件有可见焦点和按下态。
- loading：打开外部页面或准备本地诊断包时显示真实 loading，不伪造上传进度。
- success：显示目的地、反馈 ID（若有）和“仍保留在本地发件箱”的事实。
- error：保留本地草稿（localStorage 发件箱），给出「重新打开目的地」的重试入口。
- offline：不丢草稿；提示“网络恢复后重新打开提交”，不后台自动上传。
- narrow：设置弹窗在 700px 以下保持横向可滚动 tab，反馈页内容单列，不出现横向滚动。
- reduced motion：关闭入场动画，仅保留状态变化。

## 明确不做

- 不做默认遥测、后台定时上传、自动截屏。
- 不直接把完整对话、素材或 API 凭证发到 GitHub/Tally。
- 不承诺国内外 100% 可访问、第三方免费层永久可用或每条反馈必达。
- 不在没有用户独立同意和法律审查前使用原始对话/素材训练模型。

## 验收门

1. 样张与真实 SettingsDialog 外壳、token、间距和关闭行为逐项对账。
2. `zh-CN` / `en` 文案不新增硬编码可见文字。
3. 单测覆盖 URL 真相源、目的地选择、脱敏 envelope、Outbox 重试和不上传断言。
4. Playwright/Electron 走查：设置入口、错误卡入口、截图预览、取消、离线草稿、重试、窄窗口、暗色模式。
5. 真实 Tally 表单公开后，验收匿名访问、字段和附件限制；不自动创建 Issue、不自动替用户提交反馈。
