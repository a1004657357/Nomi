# 画布复制后误触发网页媒体下载：根因修复计划

> 状态：✅ 已交付（`shouldPreferCanvasClipboard` 路由 + 回归测试已合入）

## 目标

修复“在画布复制节点后按粘贴，却把系统剪贴板里的旧网页 URL 当成媒体下载”的通用路由问题。用户在 Nomi 内复制的节点，下一次 Nomi 画布粘贴应优先恢复 Nomi 节点；只有系统剪贴板明确携带外部媒体文件或媒体元素时，才进入网页媒体导入链。

## 根因判断

- 症状：复制尚未生成结果的图片/视频节点后，画布显示“网页媒体下载失败”，并创建失败节点。
- 直接原因：`useCanvasShortcuts` 的 `paste` 事件无条件调用 `pasteClipboardMediaToGenerationCanvas`；Nomi 内部剪贴板只保存在进程内，系统剪贴板仍可能是上一次网页复制的 URL。
- 类根因：内部画布剪贴板与系统剪贴板都响应同一个粘贴手势，但缺少“明确外部媒体优先、否则内部节点优先”的共享路由不变量。

## 范围

- 修改键盘粘贴事件的共享路由。
- 为外部媒体判定提取可测试的纯函数。
- 覆盖图片、视频、HTML 媒体、普通 URL 与内部节点剪贴板的回归测试。
- 不改变节点复制数据模型、远程媒体导入协议、右键菜单的显式节点粘贴或素材库拖入。

## 验收

1. 内部节点剪贴板存在 + 系统剪贴板只有普通/旧网页 URL：只粘贴节点，不发起下载。
2. 内部节点剪贴板存在 + 系统剪贴板有真实媒体文件或 HTML 媒体元素：导入外部媒体。
3. 内部节点剪贴板不存在：原有网页图片/视频粘贴行为保持不变。
4. `clipboardImagePaste` 现有图片、视频、失败和远程导入测试继续通过。
5. 运行根因合同门禁与受影响的单测；不声称真实 Electron 走查已完成，除非实际走查并记录。

## 回滚

回滚本分支的单个提交即可恢复原粘贴路由；不涉及项目数据迁移或远程状态。
