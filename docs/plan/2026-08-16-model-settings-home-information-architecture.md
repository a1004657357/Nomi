# 模型设置首页信息架构与样张计划

日期：2026-08-16

阶段：样张已确认，产品实现按 `2026-08-16-model-settings-approved-implementation.md` 执行

真实外壳：`760 x 560` 设置弹窗，左栏 `196px`

## 1. 这次解决什么

当前模型首页把“已有调用脚本”放在正文最显眼位置，把首次用户真正要找的“添加中转站”抽象成右上角“添加连接”。同时，调用脚本、连接列表、其他接入方式和网络设置分别使用上下边线，多个区域相邻时出现没有归属的横线。

用户因此无法在三秒内回答三个问题：

1. 我要接入中转站，应该点哪里？
2. “其他接入方式”下面的横线是内容、禁用项还是分隔？
3. 调用脚本、已适配平台、ComfyUI 和网络设置，哪一个才是正常入口？

这次只重做模型首页的信息架构和样张，不修改产品代码，不扩大设置弹窗。唯一跨页调整是在“自动化与权限”中增加 MCP 连接入口；除此以外，文件与保存、AI 策略、自动化与权限的既有内容、通用、关于等非模型设置全部冻结，不改结构、排版、文案或控件。

## 2. Design Thesis

- **用户与任务**：第一次接入生成模型的普通用户，以及已经有连接、回来增删模型或处理失败的老用户。
- **三秒内要看懂**：第一次打开时，先看到“只填 Key 就能使用”的 APIMart 与 Kie.ai；已有连接时，先看到连接及其真实状态。
- **唯一主操作**：首次状态是“选择一个已适配平台并填写 Key”；已有连接状态是“处理待办”或“打开连接”，新增入口降到现有连接之后。
- **内容节奏**：页面标题 -> 已适配平台 -> 自定义或本地方式 -> 高级设置。已有连接时则是状态 -> 连接 -> 新增服务 -> 高级设置。
- **视觉方向**：沿用 Nomi 设置页的暖中性、单列阅读和 4px 间距网格；主要依靠标题、间距和组底色分层，只在“高级与连接设置”前保留一条有语义的分隔线。
- **禁止变成**：卡片墙、大空白 onboarding、供应商 logo 墙、表单墙、多个同权主按钮、靠横线代替分组名称。

核心取舍：**首次接入的可发现性**与**已有连接后的管理密度**不能靠同一套静态布局兼得，因此页面必须按用户状态改变主区，而不是让所有人都看到同一份列表。

## 3. 研究维度

| 维度 | 要回答的问题 | 设计结论 |
|---|---|---|
| 用户阶段 | 首次接入和日常管理是否是同一个任务？ | 不是。首次要引导，日常要扫描和处理状态。 |
| 心智词汇 | “官方平台”是否准确？ | APIMart/Kie.ai 是聚合服务，不是模型厂商官方接口；界面统一叫“已适配平台”，避免误导。 |
| 接入成本 | 哪种方式最容易成功？ | 已适配平台只填 Key，且模型档案与请求适配已内置，应成为首次主路径；自定义 API 是第二路径。 |
| 接入方式 | 已适配平台、自定义 API、ComfyUI、即梦会员、脚本是否同权？ | 不同权。已适配平台最优先；自定义 API 次之；本地与即梦会员按场景选择；脚本只兜底普通 HTTP 请求。 |
| 能力归属 | AI 编程助手是模型服务吗？ | 不是。Claude Code/Codex/Cursor 通过 MCP 控制 Nomi，归入“自动化与权限”；只有 Nomi 调用 Codex 出图仍属于模型。 |
| 状态诚实 | 保存、可用、未验证、失败是否混在一起？ | 行内显示真实状态；“已保存”不冒充“已可用”。 |
| 长任务 | 自动适配是否阻塞首页？ | 不阻塞。只在有任务时出现一条可重新进入的状态行。 |
| 信息密度 | 怎样避免大空白又不堆满线条？ | 用有标题的 section、间距和成组列表；普通 section 不加顶线，行线只存在于组内。 |
| 控件层级 | 哪些动作常驻？ | 每个状态只有一个主操作。脚本、网络和低频平台进入次级区域。 |
| 可恢复性 | `/models`、文档或验证失败后去哪？ | 连接保留；失败行直接给“继续设置”，而不是把用户送回起点。 |
| 响应式 | `390 x 844` 怎么处理？ | 设置外壳沿用现有窄屏结构；操作行可换行，按钮不低于 44px。 |
| 设计系统 | 是否需要新 token 或新组件？ | 不需要。使用现有 token、`DesignButton`、搜索框、状态点和标准行。 |

## 4. 现状证据

- 其他设置页采用“标题 + 有名称的内容段 + 单条 section 分隔”，阅读路径清楚。
- 模型页同时使用调用脚本 `border-y`、连接容器 `border-y`、逐行 `border-t` 和网络区 `border-t`，边线数量超过信息层级。
- 首次状态仍显示搜索框、`0 个可使用 / 0 个待设置`，这些信息没有行动价值。
- AI 助手当前显示为“0 个模型”的连接，语义不成立；`ConnectAssistantCard` 实际写入 Claude Code/Codex/Cursor 的 MCP 配置，而可信发起方已经位于“自动化与权限”，因此应彻底移出模型页。
- APIMart 与 Kie.ai 已有策展 catalog、预置模型档案和请求映射；它们的正常接入只需要 Key，不应该排在需要地址、模型发现和适配兜底的自定义 API 后面。
- 旧样张已经证明“添加模型作为正文动作行”比右上角孤立入口更容易发现，但旧稿的卡片化和供应商墙不适合当前设置外壳，不能直接复用。

## 5. 方案取舍

| 方案 | 用户看到什么 | 代价 | 结论 |
|---|---|---|---|
| A. 标题栏添加 | 右上角“添加连接”，正文继续展示列表 | 首次用户容易错过，词汇抽象 | 拒绝 |
| B. 大空状态 | 中央大图标、说明和主按钮 | 可发现，但浪费 `560px` 高度，破坏其他设置页密度 | 拒绝 |
| C. 状态感知的线性页面 | 首次正文直接接入；已有连接显示紧凑列表；高级方式沉底 | 需要明确状态投影，但不增加视觉系统 | 采用 |

## 6. 页面结构

### 6.1 首次接入

1. 标题“模型”，副文案“还没有接入生成模型”。
2. 主 section“已适配平台”，右侧写“前两项只需 Key”：
   - 第一行“APIMart”，标记“推荐”，说明“一个 Key，接入预置文本、图片、视频与音频模型”。
   - 第二行“Kie.ai”，说明“一个 Key，接入预置图片与视频模型”。
   - 第三行“更多已适配平台”，进入 Agnes AI、魔搭、火山方舟等平台列表。
3. 次 section“其他接入方式”：
   - “自定义 API / 中转站”：需要地址、Key 和模型选择，作为通用第二路径。
   - “连接本地 ComfyUI”：使用本机或局域网工作流。
   - “即梦会员”：安装即梦官方本机组件并扫码登录，使用即梦高级会员积分生成 Seedance 2.0 视频；不是任意平台会员的通用入口。
4. “调用脚本”和“网络设置”放在“高级与连接设置”。
5. 首次状态不显示搜索、空统计、已接入标题和顶部添加按钮。

### 6.2 已适配平台接入子页

1. APIMart/Kie.ai 子页只收集 API Key，不要求用户再填写预置地址、模型 ID 或接口文档。
2. 保存 Key 后直接启用该平台当前可用的预置模型；失败时明确指出 Key、网络或平台响应问题。
3. 平台模型以后仍从连接详情增删，新增模型目录不要求用户重新接入。

### 6.3 自定义 API / 中转站接入子页

1. 地址与 Key 的第一步只做本地保存，不把 `/models`、文档识别或自动适配作为保存门槛。
2. 保存完成后再让用户主动选择“获取模型列表”或“手动输入模型 ID”。
3. 获取失败、超时或用户返回时，连接都保留为“已保存、模型待选择”。
4. 模型列表成功后进入选择页；选完以后仍可从连接详情继续增删模型。
5. 连接诊断是可选工具，必须有真实结果，但不决定用户能否保存或手动继续。

### 6.4 已有连接

1. 标题副文案显示“2 个连接 · 7 个模型”。
2. 只有数据量足够时显示搜索。
3. 若存在待处理或后台任务，先显示一条状态行，可重新进入任务或继续设置。
4. “已接入”成组展示连接；组内允许行分隔，但外部不重复加边线。
5. 连接行明确进入详情，可查看、设置、添加或停用模型；不能让用户误以为只能新建连接。
6. 现有连接之后先展示尚未接入的已适配平台，再展示“自定义 API / 中转站”。
7. “其他接入方式”只包含本地运行时与即梦会员，不再出现泛化的“会员账号”或 AI 编程助手。
8. “调用脚本”和“网络设置”归入“高级与连接设置”。

### 6.5 需要处理

- 顶部状态行只表达一个明确问题，例如“2 个模型需要设置输入方式”。
- 主按钮为“继续设置”；后台自动适配是次级动作，不出现双 loading。
- 已成功模型继续可用，不因同连接内某个模型失败而整组降级。
- 恢复页必须同时给出“立即手动设置”“停止自动识别”“只重试当前模型”，并显示当前步骤、数量和最长等待。
- 三种首页状态使用同一套连接列表、添加入口、其他方式和高级设置骨架，产品实现不得复制成三张互相漂移的页面。

### 6.6 AI 助手（MCP）的归属

- “让 Claude Code / Codex / Cursor 使用 Nomi”移动到“自动化与权限”。
- 该页增加“AI 助手连接（MCP）”二级入口，负责安装、验证、重连和移除 MCP 配置。
- “可信发起方”继续负责是否允许已连接的助手发起任务；连接状态与授权开关不能混成同一个状态。
- 模型页删除 assistant connection、assistant available item 及其“0 个模型”统计。
- “Nomi 使用 Codex 出图”仍保留在模型页，因为它提供的是生成模型能力，方向与 MCP 相反。

## 7. Interaction Contract

- `Tab` 顺序按视觉顺序；所有行和按钮有可见焦点。
- 主行整行可点，但行尾按钮仍是唯一强视觉动作；不能出现点了无反应的区域。
- “更多接入方式”使用标准 disclosure，关闭时不渲染任何可见边框或空白行。
- 展开后箭头方向和 `aria-expanded` 同步。
- API 表单明确区分“未保存草稿”“连接已保存”“模型待选择”；返回或关闭不能把三种状态混为一谈。
- 已适配平台的 Key 表单不得显示自定义地址、文档识别或模型 ID；用户选择平台后一步完成。
- 已有连接行进入连接详情；详情页始终有“添加模型”，选完后仍能再次进入。
- 后台任务显示当前步骤、`完成数/总数`、最长等待，并允许停止、重试或立即手动接管。
- 切换样张状态不会改变设置弹窗尺寸，也不会修改其他设置页。
- 窄屏下行内容换行，按钮保持至少 44px 高，页面无横向滚动。
- 亮色和暗色只通过同一组 Nomi token 翻转。

## 8. System Contract

- **Token 变化**：无。
- **现有原语**：`DesignButton`、`DesignSearchInput`、Tabler 图标、Nomi 状态色、全局焦点环。
- **间距**：4/8/12/16/24；禁止 `gap-2.5`、`p-3.5` 等新碎值出现在模型新页面。
- **字号**：11/12/13/14/16；不引入任意字号。
- **圆角**：输入与动作行 6px，面板 10px，设置弹窗沿用现有 `rounded-nomi-lg` 14px。
- **图标**：Tabler，列表与设置场景 16px，stroke 1.5-1.8。
- **移除计划**：产品实现阶段应删除标题栏唯一添加入口、孤立的 direct-script `border-y`、available 容器的无语义外边线和 network 裸 `border-t`，不保留并行旧版。

## 9. HTML 样张范围

样张必须在真实 `760 x 560` 设置外壳中提供：

1. 首次接入状态，APIMart 与 Kie.ai 位于首屏最前。
2. 已有连接状态。
3. 需要处理状态。
4. “更多接入方式”的展开与收起。
5. APIMart/Kie.ai 进入只填 Key 的子页；自定义 API 仍有独立子页。
6. 连接先保存，再分别走“获取模型列表”和“手动输入模型 ID”。
7. 已有连接进入详情，并从详情再次添加模型。
8. 待处理任务进入恢复页，能停止、重试或转为手动设置。
9. 亮色 / 暗色切换。
10. 桌面与窄屏布局。
11. “自动化与权限”展示 AI 助手连接（MCP）入口与可信发起方，模型页不再出现 AI 编程助手。
12. 左栏其他设置分类按当前页面结构做静态复刻，证明它们没有因模型页重设计而扩大、重排或变空。

## 10. 样张验收

- 首次状态三秒内能找到 APIMart 与 Kie.ai，并看懂“只需 Key”。
- 自定义 API / 中转站仍可在首屏找到，但不与已适配平台竞争第一优先级。
- 模型页不存在 AI 编程助手/MCP；自动化与权限页存在唯一规范入口。
- 页面中不存在没有名称或归属的横线。
- “调用脚本”不与主接入路径竞争。
- 已有连接能找到“添加连接”，但不占标题栏唯一高权重位置。
- 首次接入、手动补模型、已有连接增删模型、卡住后恢复四条旅途都能走到明确结果。
- 折叠状态不泄漏隐藏列表的边框或空白。
- `1440 x 900` 与 `390 x 844` 无溢出、遮挡和文字截断。
- 亮暗色均使用 Nomi 暖中性底与蓝紫强调色。
- HTML 本身可直接打开，不需要开发服务器。

## 11. 产品代码执行边界

样张已由用户确认。产品实现必须保持本文件的优先级、状态与恢复契约；除在“自动化与权限”新增 MCP 连接管理外，其他非模型设置页面保持现状。具体文件范围、迁移顺序、测试矩阵和交付门禁见 `2026-08-16-model-settings-approved-implementation.md`。
