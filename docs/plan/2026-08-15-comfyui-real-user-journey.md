# ComfyUI 真实用户旅程

## 目标

用一台真实的官方 ComfyUI，从新用户第一次配置开始，走到 Nomi 画布拿到真实图片，并把这条路径固化成可重复执行的验收脚本。测试既检查用户可见反馈，也检查 ComfyUI `/history`、产物和任务归属，避免“界面没报错但实际没提交”的假通过。

真实任务格式：我已经在本机启动 ComfyUI，有一条在 ComfyUI 中保存的图片处理工作流；我想把它接入 Nomi，并在空白项目里直接生成；成功标准是地址配置和工作流在重启后保留，ComfyUI 收到且成功完成属于 Nomi 的任务，Nomi 节点展示真实结果，取消不会影响其他客户端的任务。

## 范围

- 首次连接、错误地址反馈和恢复。
- ComfyUI 界面格式 `workflow.json` 与 API 格式 `workflow_api.json` 的导入入口。
- 自动 UI workflow -> API prompt 转换、缺节点/文件对账、工作流原图持久化。
- 工作流设置页的字段暴露、保存、关闭重开和真实试跑。
- 空白项目中的模型选择、无提示词工作流生成、真实结果展示。
- Nomi/ComfyUI 重启后的配置、项目与结果恢复。
- 有任务归属能力时的定向取消，以及旧服务器的诚实降级。
- 中文和英文导入入口的可见文案与辅助技术标签。

## 不动项

- 不要求用户安装 checkpoint；主旅程使用官方内置的 `EmptyImage -> ImageInvert -> SaveImage`，保证干净 ComfyUI 也能跑。
- 不自写 ComfyUI UI workflow 转换器，继续复用官方 ComfyUI frontend 的 `graphToPrompt`。
- 不为测试提交 ComfyUI 自定义慢节点，也不通过高内存工作流制造取消窗口。
- 不改变其他供应商、云模型或通用生成状态机的行为。

## 三条真实任务

### T1：第一次连接失败后自行恢复

1. 使用全新的 settings/projects/userData 启动 Nomi。
2. 进入“设置 -> 模型 -> 本地 ComfyUI”。
3. 填入不可达地址 `127.0.0.1:8199` 并启用/重检。
4. 用户必须看到离线状态和实际检查的地址，且仍能直接修改地址。
5. 改为不带协议的 `127.0.0.1:8188`，保存并重检。
6. 必须显示已连接、真实 ComfyUI 版本和增强模式。

成功标准：用户不需要退出页面、删配置或猜 URL 格式即可恢复；连接状态来自真实 `/system_stats`，不是本地乐观状态。

### T2：导入普通工作流并配置

1. 在同一入口粘贴 ComfyUI 普通保存的 `workflow.json`。
2. Nomi 调用官方 frontend 完成 UI -> API 转换，识别图片输出且不虚构提示词绑定。
3. 本机对账显示零缺节点、零缺文件；命名并导入。
4. 进入工作流设置，暴露宽度和高度，保存后关闭再打开。
5. 参数、角色绑定、API prompt 和原始 UI workflow 必须全部保留。
6. 从设置页运行测试，ComfyUI 必须收到并成功完成任务。

成功标准：用户无需学习第二种 JSON 格式；普通 workflow 原图可继续追溯，运行使用转换后的 API prompt。

### T3：在真实项目里生成、重启和取消

1. 新建空白项目，进入生成画布，添加图片节点并选择刚导入的工作流。
2. 不输入提示词直接生成；本地运行不得弹云端额度确认。
3. 记录提交、ComfyUI 完成、Nomi 展示结果三个阶段的耗时。
4. 用相同 settings/projects/userData 重启 Nomi，重开项目。
5. 工作流选择、节点参数和已生成结果必须仍在。
6. UI 取消验证使用可控 mock 保证“只取消这一任务”；真实官方服务另以 jobs API 验证同一归属语义。

成功标准：ComfyUI `/history` 新增带本次 client id/workflow 的成功记录，Nomi 节点显示可读取的真实图片；重启后不用重新接入或重新生成；取消不调用会误伤全队列的全局中断。

## 每一步证据

- 用户目标和实际操作入口。
- 期望与实际的可见反馈。
- 操作开始、提交、终态和结果展示时间。
- 失败后的可发现恢复动作。
- ComfyUI `/history`、`/queue`、`/view` 或 jobs 事实。
- 关键状态截图；截图必须人工查看。
- 页面异常和 `console.error`。
- 重启前后持久化文件及 UI 状态对账。

## 失败判据

以下任一项都算失败，而不只限于程序报错：

- 用户不知道下一步，或文案要求学习实现并不需要的格式。
- 点击后没有忙碌、成功、失败或恢复反馈。
- Nomi 显示成功，但 ComfyUI history 没有对应任务或结果不可读取。
- 普通 `workflow.json` 被入口文案误导为不支持，或转换后丢失原图。
- 保存/重启后地址、绑定、字段、工作流或项目结果丢失。
- 本地 ComfyUI 被错误描述成会消耗云端模型额度。
- 取消调用全局 `/interrupt`，或取消了另一个客户端的任务。
- 关键交互态遮挡、溢出、不可读，或中英文任一语言不完整。

## 自动化结构

- `scripts/comfyui-real-user-journey.mjs`：生产构建上的 Electron 用户旅程，连接真实 `127.0.0.1:8188`，复用同一组临时目录执行 T1-T3，并输出截图、JSON 报告和失败断言。
- `scripts/comfyui-real-server-verify.mjs`：真实官方协议、feature negotiation、history/view、缓存和 jobs 定向取消。
- `scripts/comfyui-progress-walkthrough.mjs`：可控任务时序下的 UI 进度与取消归属。
- 聚焦单元/集成测试：UI workflow 转换、catalog 持久化、无提示词生成、ComfyUI runtime。

## 验收门

1. `pnpm build` 后，从 `dist` 启动 Electron，不使用旧 dev chunk。
2. T1-T3 全部通过，真实服务端事实与 UI 结果一致。
3. 中文和英文各检查一次导入入口；关键截图逐张人工查看。
4. 发现的问题修根因后，完整重跑而不是只重跑失败一步。
5. `pnpm run check:filesize`、`check:tokens`、`check:i18n`、`lint:ci`、`typecheck`、`test`、`build` 全绿，`git diff --check` 通过。

## 回滚

- 文案修正可单独回滚，不影响已保存 workflow 数据。
- 旅程脚本和文档不进入产品运行时，可独立移除。
- 若用户路径暴露运行时缺陷，只在 ComfyUI vendor/runtime 分支修复；出现回归时回滚对应提交，其他供应商保持不变。

## 结果回填

### 真实执行结果

- 官方 ComfyUI：`0.33.0`，frontend `1.49.6`，CPU 模式，850 个节点类型，零 checkpoint。
- 首次开屏主动跳过：809 ms；设置打开 51 ms，模型页可见 70 ms，本地 ComfyUI 分组就绪 3 ms。
- 设置页真实试跑：738 ms。
- 画布点击到 ComfyUI 完成：536 ms；点击到 Nomi 展示真实结果：2958 ms。
- 完整重启并恢复工作流、项目和结果：8914 ms。
- 同一旅程共提交两次真实 ComfyUI 任务，`/history` 均为 `success`；页面错误、console 错误均为零。
- 机器可读报告：`.comfyui-real-user-journey/report.json`；截图：`.comfyui-real-user-journey/01-*.png` 至 `09-*.png`。两者均是本地证据，不入库。

### 旅程发现并修复的问题

- 首次测试看似设置页慢 14.8 秒，分段计时后确认根因是可跳过的 13 秒首次开屏，不是设置或模板加载；旅程改为模拟有明确任务的用户主动跳过。
- 导入入口原先只教用户提供 `workflow_api.json`，但产品已经能借官方 frontend 自动转换普通 `workflow.json`；入口、错误恢复文案和辅助技术标签已按真实能力修正。
- 不接收提示词的 ComfyUI 工作流仍展示提示词编辑、提示词库和优化器，形成无效操作；现按工作流 binding 隐藏并压缩 composer。
- 英文桌面顶栏在较窄窗口发生竞争；引导和任务中心文字在 1600 px 以下收为图标，1440 px 与窄桌面均无重叠。
- 进度/取消 mock 原先固定占用 8188，无法与真实 ComfyUI 并行；现支持 `COMFY_PROGRESS_PORT`，已在 8190 完成定向取消验证。
- 同步最新主线后，顶栏与设置弹窗同时存在名为“模型”的按钮；旅程曾点到被弹窗遮住的顶栏入口。最终选择器按真人可见层级限定在设置对话框内，避免强制点击造成假通过。

### 验证结果

- 真实用户旅程：通过，2/2 次真实生成成功。
- 官方协议与真实服务器验证：34/34 通过。
- ComfyUI 聚焦测试：22 个文件、233/233 通过；新增聚焦测试：26/26 通过。
- 仓库全量门禁：538 个测试文件通过、4689/4689 项测试通过，另有 1 项按仓库配置跳过；完整生产构建通过。
- 进度与取消旅程：只命中目标任务一次，遮罩恢复，页面与 console 错误为零。
- `typecheck`、`check:tokens`、`check:i18n`、`check:controls`、`build`、`git diff --check` 均通过。
- 视觉质量门：9 张主旅程截图与 2 张进度/取消截图已逐张检查，无剩余 P0/P1；Electron 是桌面应用，移动端不适用，另以窄桌面窗口检查布局。

### 仍有限制

- 当前真实机没有 checkpoint 且以 CPU 运行，所以主旅程选择 ComfyUI 内置 `EmptyImage -> ImageInvert -> SaveImage`，证明接入、执行、结果回传和持久化，但不代表大型 checkpoint 的 GPU 性能。
- 1024 px 窗口可能受 Electron 最小宽度约束；验收使用实际可渲染的窄桌面几何和截图确认无重叠。
- 自定义节点缺失、模型文件缺失已有对账覆盖；不同第三方节点自身的输入约定仍需按具体工作流做兼容验收。
