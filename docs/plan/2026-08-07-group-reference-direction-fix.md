# 编组参考连线方向修复（2026-08-07）

## 用户摩擦

用户从生成节点左侧输入端拖线到一个含两张成图的编组。画布画出了两根线，但生成节点没有切到参考图模式，顶部也没有出现两张参考图。

根因不是参考图组件漏渲染，而是连接方向只停留在视觉层：`pendingConnectionSourceSide` 只决定预览线从左还是右出发，落库始终把起拖节点当 `edge.source`。因此“目标节点左输入端 → 编组”被反存成“目标节点 → 两个组成员”。

## 范围

1. 左端口表示输入：从节点左侧起拖时，松手节点/编组成员是 source，起拖节点是 target；右端口继续表示输出。
2. 编组作为输入源时展开为 N 条普通 node→node 真边，不引入 group edge 平行图语义。
3. 第一条有效参考边自动把目标从文生图切到可消费参考的模式；参考槽直接从这些真边解析出组内图片。
4. 编组输出关系和现有编组输入关系一样持久化：新成员加入自动补边，成员移出自动撤掉仅由该组物化的边。
5. 待连时的组框提示按方向说清“连到整组”或“将整组作为输入”，不新增按钮或并行入口。
6. 连线命令从“命中的一条展开边”上升到用户创建的语义连接：编组连接点“断开”撤掉整次编组声明和其展开边，不留幽灵声明。
7. 普通边的唯一身份不再只由 `(source,target)` 决定；同两点的首帧/尾帧/角色等多语义边可以被分别点中、改标签和断开。旧快照重复 ID 在恢复时确定性修复。

## 不动项

- 不改参考图 UI 布局、模型档案或生成参数协议。
- 不让 `GenerationCanvasEdge.source/target` 接受 group id；组仍只是批量连线手势。
- 不改变右端口“一个来源喂给整组目标”的现有行为。
- 解散组仍保留已经物化的真实边；仅用户在连线菜单明确选“断开连接”时，才按整次编组连接撤销。

## 结构保证

- store 回归：左端口单节点反向、编组两图→目标、自动切模式、两个参考槽均可解析。
- 动态回归：加入编组自动补输出边，移出编组只撤组物化边、不误伤手工边。
- schema 回归：`outputLinks` 可选且旧快照继续可读。
- 边交互回归：同两点的多语义边 ID 不冲突；点某条普通边标签只改该边；点编组边“断开”撤掉同一编组声明的所有展开边与声明。
- 真机走查：从目标左输入端拖到两图编组，确认边方向、模式和两个参考缩略图一致；再真实点边、切标签、断开，确认界面和 store 同步。

## 回滚

单提交回滚本计划涉及的连接方向、编组声明、schema 与测试；旧项目没有 `outputLinks`，因此回滚不需要数据迁移。即使新版项目含该可选字段，旧 schema 的对象解析会忽略它，普通真边仍保留。
