## 一、两条输入通道 —— 我们只接了一条（有意为之）

`content[].image_url.url` 只有两种合法值：

| 通道 | 值 | 我们 |
|---|---|---|
| 直接甩 URL | 公网可达的 HTTPS 地址 | ✅ 已接（唯一在用） |
| 平台素材库 | `asset://<asset_id>` | ❌ **有意不接** |

`asset://` 要先走 Gateway（`:9444`，与视频 API 不同端口、同一枚 Token）。**素材组分两种，
约束完全不同**（初版把这两种搞混了，见下方「已证伪」）：

| 组 | GroupType | 怎么建 | 建素材要什么 |
|---|---|---|---|
| 普通素材（§7） | `AIGC` | 自己 POST 建组 | `GroupId` + 公网 HTTPS `URL` + `AssetType`。**无「必须是本人」约束** |
| 真人人像（§8） | `LivenessFace` | 只能由 H5 活体认证流程产出 `group_id` | 同上，但 §8.3.4 要求「文件内容必须属于**已完成人脸认证的本人**」 |

两种都是「建组 → 传素材 → 轮询到 `Active` → 拿 `asset_id`」。

**当前不接的理由**（2026-07-31 用户拍板「先只做 A 类，真人通道不碰」）：

1. **它救不了本机图。**（经得起核）素材创建接口的 `URL` 字段同样要求「上游可访问的公网 HTTPS
   文件地址」—— 素材库自己也要一个公网 URL。所以「本机图没有公网地址」这个问题
   （免费图床 litterbox/tmpfiles 挂了就断链）asset:// 一点忙都帮不上。
2. **真人通道（LivenessFace）对 Nomi 主场景无效。** 它要求素材属于已认证本人，而主场景是
   AI 原创角色跨镜一致 —— 虚构角色没有「本人」可认证。**注意这条只否掉真人通道，
   不否掉 AIGC 素材组**（初版在这里犯了错，把 §8 的约束安到了 §7 头上）。
3. **AIGC 素材组的收益未知，成本确定。** 成本是每张参考图两次额外往返 + 轮询等待；收益取决于
   一个**从未验证过的假设**：`asset://` 能不能软化输入图的人脸审核。文档对此只字未提。

> ⚠️ **这个决定的地基比初版描述的松。** 真正硬的只有第 1 条。第 3 条悬在一次没跑过的实测上 ——
> 拿到 Token 后**先测再谈**：AI 写实人像 → AIGC 组 → `asset://` → 建视频任务，看还拦不拦。
> 若不拦，「有意不接」应当立即重开。

**什么时候该回来重开真人通道（C 类）**：出现「用自己/授权演员的脸做数字人口播」这类真实用户需求时。

> ⚠️ 已证伪的方向：一度以为「方舟原生 `image_url` 收 base64 data URL 就能内联本机图、彻底摆脱第三方
> 图床」。**文档否掉了** —— `url` 字段只列 HTTPS URL 和 `asset://`，没有 base64。别再往这个方向走。

## 三、限流与轮询纪律（§5.1）—— 初版整段漏了，我们三条全违反

文档原文两句硬要求：

> 超过账号并发额度或触发请求频率限制时，接口返回 HTTP 429。调用方应采用**指数退避并加入随机抖动**，
> 不能无间隔重试。
> …建议复用 HTTP 连接，使用本地队列控制提交速度，并将任务查询间隔**分散到 3 至 5 秒以上**，
> 避免所有任务在同一时刻轮询。

| 要求 | 初版发现的实际行为 | 现在 |
|---|---|---|
| 查询间隔 ≥3–5 秒 | 固定 1500ms | ✅ 慢道（视频/本地后端）3s，快道云图像仍 1.5s（`resolvePollIntervalMs`） |
| 分散、避免同时刻轮询 | 零抖动；批量 6–8 个节点同 tick 起跑，poll 相位完全对齐 | ✅ ±30% 抖动（`nextPollDelayMs`） |
| 429 → 指数退避 + 抖动 | `catch {}` 吞掉，1.5 秒后原样再打 | ✅ 连击 2^n 退避、封顶 30s、查成功即复位（`isRateLimitedPollError`） |

后果不是理论上的：批量生成时我们对状态端点曾是「每 1.5 秒 6–8 发的同步脉冲」，正是文档点名要
避免的模式；撞了 429 还不退避只会撞得更狠。

**改在全局而非单一渠道**（所有 vendor 共用这个 poll 循环）—— 礼貌轮询对每一家都是净收益，
不给某一家开小灶（P4）。只放慢慢道：视频本身分钟级，1.5s→3s 用户零感知；云图像秒级，动了立刻
被察觉成「慢了」。分档判据复用既有的 `isSlowLaneBackend`，不另立第二套。

无头/MCP 那条循环在主进程（`electron/capabilityCore/core.ts`），跨进程边界 import 不到渲染层，
那边是**配对常量、改一处必改另一处**（同 `vendorErrorIpc` 的 MARKER 约定）；它一次只跑一个任务，
不存在批量同相位问题，故只对齐间隔、不叠抖动与退避。

## 四、错误语义（⚠️ 本节不来自本文档）

**本文档的错误表（§10）只到 HTTP 状态码这一层**：`400 | 请求字段或模型参数错误`、`401`、`403`、
`429`、`500/502`。**通篇没有 `InputImageSensitiveContentDetected` 这个码。**

所以下面这段的来源是第三方博客 + 用户真机报文，**不是文档背书**（初版把它排在对账文档里，
读起来像是文档说的 —— 违反 `api-doc-fetch-fail-ask-dont-substitute`，特此标明）：

- `InputImageSensitiveContentDetected.PrivacyInformation`（HTTP 400）看起来是生成前的输入图
  人脸审核；用户真机报文原话是 `input image 'content[1]' may contain real person`。
- 「写实人像基本都会被拦、与是不是 AI 生成的无关」是**博客说法，未经我们验证**。

已确证的只有一件事：**用户那张 AI 写实人像确实被 400 拒了，且报文里是这个码。** 分类与文案已在
[55d7c142](https://github.com/aqm857886159/Nomi/commit/55d7c142) 落地（`input-image-blocked` 类 +
主动作「换个模型」）。文案**有意不提**「去做真人认证」—— Nomi 里没有这个功能，提了等于把用户
支去别处（D1）。

## 五、其他被文档印证的既有结论

- §4.1「`content.video_url` 和 `content.last_frame_url` 通常只保留约 **24 小时**…任务成功后应立即
  下载到客户自己的对象存储；平台不承诺临时 URL 的长期可用性。」
  —— 这正是 [76db65f1](https://github.com/aqm857886159/Nomi/commit/76db65f1) 治的
  「生成的视频隔天播不了」。文档站我们这边，那个结构闸是对的。
- §4.1 还要求公网素材「URL 有效期应覆盖完整的素材预处理和视频生成周期」。
  **免费匿名图床不满足这条**：tmpfiles.org 默认 1 小时删除、litterbox 最短 1 小时，而视频排队 +
  生成经常吃掉大半小时。所以那条链不只是「会挂」，还会**在生成中途过期**。

2. **变体是否真开通**：切 fast / mini 各发一次，看是否 403。
3. **本次改动**：全能参考模式带 1 视频 + 1 音频 + 固定 seed，看是否正常受理、seed 是否原样回显。

   「asset:// 救不了 Nomi 主场景」。实际那句只约束 `LivenessFace` 组；`AIGC` 组（§7.4）没有这条要求，
   AI 原创角色走它完全合法。「有意不接」的地基因此比初版描述的松得多。
