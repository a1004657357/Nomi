# 提示词选择器 + 自定义提示词（2026-08-18）

来源：用户「系统提示词有了，但得留自定义的口子、而且得能被调用，我们现在找不到调用的地方」。
样张已拍板（2026-08-18，选择器落 composer 发送键左侧）。承接 `2026-08-17-creation-flow-fixes.md` 的 E 项。

## 根因：不是「少了个入口」，是入口把列表写死了

`onModeChange` 全仓只被调用过一次，参数是**硬编码字符串** `'assets'`
（`ActiveSkillChip.tsx:133`）。于是 `CREATION_AI_MODES` 的 7 个模式里：

| 模式 | 能否选到 |
|---|---|
| `general` | ✅ 「自动」 |
| `assets` | ✅ 「素材规划」 |
| `story` / `script` / `storyboard` / `seedance` / `review` | ❌ **UI 上不存在** |

`CreationAiPanel` 里留着「内部模式不再占一个难懂的下拉」的注释——那个下拉被主动删掉后，
5 个模式的提示词就此搁浅。上一轮做的设置页因此有一大半在编辑**根本调不起来**的提示词。

**所以真正要修的是「选择器凭什么知道该显示哪些」**：只要它继续手写条目，
下次新增模式还会搁浅。改成从 `CREATION_AI_MODES` derive + 结构测试钉死（见验收门 2）。

## 概念界线（这次要把话说破）

现在这个下拉里混着两种东西，没人讲清过：

- **提示词** = 一段文字，决定它**怎么说话**。无工具、无阶段。7 个内置 + 用户自建。
- **流程包（技能）** = 目录包（`SKILL.md` + `skill.json`），带工具白名单和阶段编排，
  决定它**怎么干活**。可导入导出，将来可进市场。

用户要的「自定义口子」属于**前者**。所以不新造第三个概念，也不逼用户为了存一段提示词去填 manifest
（D1：让用户学我们的格式 = 离谱）。想要可分享的，走列表里既有的「让 AI 帮我写技能」。

## 范围

### A 数据层：设置文件长出自定义条目
- `electron/settings/systemPromptsContract.ts`：形状从 `Record<modeId, string>` 扩成
  `{ overrides: Record<builtinModeId, string>; custom: Array<{ id, name, prompt }> }`，带 v1→v2 迁移
  （上一轮已落盘的旧形状要能读进来，不能让用户改过的提示词丢）。
- 自定义 id 生成一次即固定（选择记在 `creationAiModeId` 里，改名不能让选择失效）。
- 沿用既有净化口径：未知字段丢、非串丢、超长截断、名字去空白且非空。

### B 领域层：内置 + 自定义同一张表
- `creationAiModes.ts`：`getCreationAiMode(id)` 认得自定义 id；新增 `listCreationAiModes()`
  返回「内置 7 个 + 自定义 N 个」，**选择器和设置页都从它 derive**（单一真相源）。
- 自定义条目的能力声明（用户 2026-08-18 拍板：不给用户多一个开关）：
  - `chatOnly: false` —— 能写文稿，仍走既有的待批卡确认；
  - `dedicatedJob: true` —— 用户明确选了它，不被拆分镜意图路由劫走（承接 08-17 D 项）。
- `CreationAiModeId` 联合类型只保留内置 7 个；store 里的 `creationAiModeId` 放宽成 `string`
  （自定义 id 是运行时数据，不该进类型联合）。选中的自定义被删 → `getCreationAiMode` 回退 `general`。

### C 选择器：从头部挪到 composer，分三组
- `ActiveSkillChip` 从 header 挪进 composer 左簇，和 `AssistantModelPicker` 并排、在发送键左边。
  **头部那颗删掉**（P1 一功能一个家，不留两个入口）。
- 列表分三组：`提示词`（derive 自 `listCreationAiModes()`）/ `我的`（自定义 + 「新建提示词」）/
  `流程包`（既有 playbook + 「让 AI 帮我写技能」），末尾留「在设置里编辑全部提示词 →」。
- chip 标签跟当前选择走（现在恒显「通用助手」，读起来不像选择器）。
- `ConversationHistoryPopover`：向上翻转已有（`:35`），但右对齐是锚 `<header>` 右缘的
  （`:28-29`），composer 里没有 header 会退回按钮右缘 → 加对齐方向参数，composer 处左对齐。

### D 设置页：新建 / 改名 / 删除
- `SystemPromptSection` 的 chip 行接 `listCreationAiModes()`，自定义的排在分隔线后。
- 内置：编辑 +「恢复默认」（已有）。自定义：编辑 + 改名 + 删除（无「恢复默认」，它没有默认）。
- 「新建提示词」两个框：名字 + 正文。不要 manifest、不要版本号、不要 provider 声明。

### E i18n
所有新增可见文字进 `zh-CN` + `en`，零硬编码（有门岗）。

## 不动项

- 技能/流程包体系（`SKILL.md` + manifest + stages + 工具白名单）一概不改；
  「让 AI 帮我写技能」保持原样，它就是「想要可分享的」那条路。
- `ASSET_MASTER_PROMPT`（用户 2026-08-12 提供的 537 行规范）内容不动。
- 画布助手的 skill 选择（`workbench.generation.canvas-planner`）不动，本次只碰创作区。
- 电子侧 `buildSkillSystemPrompt` / `buildToolsForSkill` 不改：自定义 id 拼出的
  `workbench.creation.<id>` 会照旧前缀命中 `workbench-creation` 技能、拿到文档工具，无需新分支。

## 回滚

单分支，A–E 各自独立 commit。B/C/D 依赖 A 的数据形状，回滚需从后往前。
A 的 v2 形状读得懂 v1；真要回退到上一版代码，v2 文件会被 v1 净化器丢掉 `custom` 字段，
内置覆盖仍在——用户改过的内置提示词不会丢，只丢自定义条目。

## 验收门

1. 七门全过：`pnpm run gates`
2. **结构保证（治根因，不然新增模式还会搁浅）**：单测断言
   「`CREATION_AI_MODES` 里每一个内置模式都出现在选择器 derive 出的列表里」，
   且选择器不得出现硬编码模式名（照 `modelSelectStructure.test.ts` 的做法扫源码）。
3. 纯函数单测：v1→v2 迁移、净化、自定义增删改名、选中项被删后的回退。
4. **R13 真机走查**（截图自己 Read 过才算）：
   - composer 左侧能看到选择器，头部那颗已消失（截图对账样张）
   - 点开 → 7 个内置模式**全部**在列（尤其原来选不到的 5 个）
   - 新建一个自定义提示词 → 出现在「我的」组 → 选中 → chip 标签变成它
   - 选中自定义后发一句带「镜头」的话 → 不被拆分镜劫走（承接 08-17 D 项的回归）
   - 设置页能改名 + 删除；删掉当前选中的那个 → 回退到「自动」，不崩
5. R16：一条真实任务闭环——新建「口播带货体」→ 在对话里选它 → 让它写一段 → 产出符合该提示词

## 走查结果（2026-08-18 · `tests/ux/prompt-picker.walk.mjs`）

7/7 通过，截图在 `tests/ux/shots/prompt-picker/`，已人眼对账样张。

关键一条是 ②：**7 个内置提示词全部在列**（`general、story、script、assets、storyboard、seedance、review`）——
改动前只有 2 个能选到。这是「找不到调用的地方」的正面证明。

结构门岗首跑把自己打红了一次：扫源码找硬编码模式名时，**记录这个 bug 的注释本身**
（「旧代码硬编码 onModeChange('assets')」）命中了规则。已改成扫描前先剥注释——
不变量管的是代码行为不是文字，把讲清根因的注释逼删掉是让门岗反噬文档。

## R16 真实任务闭环（2026-08-18 · `tests/ux/custom-prompt-realtask.walk.mjs`）

6/6 通过，走真模型（Claude Fable 5）、真额度。凭据从用户真实 userData 复制
`model-catalog.json` 到隔离目录——用真 key，但不往用户正式配置里写测试提示词。

**有对照组才算数**：同一句「给这个保温杯写一段口播」，先用「通用」跑一遍，再用自定义提示词跑一遍。
没有对照的话，模型碰巧写得像口播稿也会被当成「提示词生效了」。

| | 产出 |
|---|---|
| 通用 | 「早上装一杯热水，到了下午依然温热…」——第三人称产品文案，无钩子、无场景、无促单 |
| 口播带货体 | 「你是不是每天通勤，都喝不上温度刚好的水？」→ 早 7 点半出门 / 8 点挤地铁 / 下午 3 点工位 → 「早买一天就早舒服一天」 |

提示词里那四条硬要求（钩子问句 / 具体通勤场景 / 促单理由 / 全程第二人称）逐条照做。
**自定义提示词确实端到端作用到了模型上**，不只是「选得到」。

走查自身的坑（第三次栽在同一类上，记下来）：完成信号一开始写成「气泡文本连续几次不变」，
而 pending 态气泡的文本恒为作者名「Nomi」——模型还没吐第一个字，判据就满足了，
于是拿 4 个字的作者名当产出去断言，四条全红，看起来像功能坏了。
正确信号是**停止键变回发送键**（turn 控制器的 sending 驱动）。
教训同前两次：**等待条件要盯真正的状态源，不要盯一个恰好也会静止的表象。**
