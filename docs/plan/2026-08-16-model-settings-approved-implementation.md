# 模型设置批准稿实施方案

日期：2026-08-16

状态：已完成

设计基线：`docs/design/mockups/2026-08-16-model-settings-home-information-architecture.html`

## 1. 交付结果

把已确认 HTML 的信息架构完整落到真实 React/Electron 产品，并保持现有 `760 x 560` 设置外壳。首次用户先看到 APIMart 与 Kie.ai 的 Key-only 接入；已有用户先看到连接、模型和待处理任务；任何网络、文档或自动适配失败都不会把用户卡死或丢失已保存连接。

唯一允许的非模型页变化是在“自动化与权限”增加外部 AI 助手 MCP 连接管理。文件与保存、AI 策略、通用、关于，以及自动化页既有的制作模式、风险、可信发起方和通知结构全部冻结。

## 2. 代码切片

### A. 模型首页

- `ModelSettingsHome` 改为状态感知的单一页面骨架，不复制首次、已有、待处理三套页面。
- 首次状态移除顶部添加按钮、搜索和空统计；依次展示已适配平台、其他接入方式、高级与连接设置。
- APIMart 固定第一、Kie.ai 固定第二；“更多已适配平台”承载其余已策展平台。
- 已有连接先展示连接和真实状态，再展示可添加平台；搜索只在连接/模型数量足够时出现。
- 运行中或待处理任务直接显示可重进的任务行，不藏在计数按钮后。
- ComfyUI、即梦会员、Codex 本地出图保持模型能力归属；MCP assistant 从模型数据投影和详情路由中删除。

### B. 接入子页

- APIMart/Kie.ai 使用专用 Key-only 页面，只收一个密文 Key；URL、模型目录、请求映射和预置模型由 Nomi 维护。
- 已知平台保存仍复用既有加密凭据与后台健康检查，不启动通用文档识别。
- 自定义 API 改为真正 save-first：合法名称/URL/Key 可以先写入 vendor，即使模型数组为空。
- 保存连接后保留两个并列出口：“获取模型列表”和“手动输入模型 ID”；列表失败、超时或用户退出都不删除连接。
- 已有连接详情继续提供“添加模型”，复用主进程保存凭据拉取，不把 Key 回传 renderer。

### C. MCP 归属迁移

- `ConnectAssistantCard` 的安装、验证、重连、移除能力迁到“自动化与权限”。
- MCP 连接状态与“可信发起方”权限开关分成两个 section；前者回答能否连接，后者回答连接后允许做什么。
- 模型页不再出现 assistant connection、可接入 assistant 或“0 个模型”。

### D. 自动适配恢复

- 每个任务持续暴露当前阶段、当前模型、完成数/总数、已用时间与截止时间。
- 单步和整批都有硬超时；任务支持真正取消，取消后不自动恢复。
- 首页关闭再打开仍能从持久化任务列表进入同一任务。
- 运行中即可手动接管当前模型；失败模型可独立重试，成功模型不回滚。

## 3. 数据与迁移契约

- `adapterRegister` 接受空 `models`，返回 `configured` connection 和空的 `selectedModelKeys/models`；验证与适配入口仍要求至少一个模型。
- catalog 注册空模型时只保存 vendor、加密凭据和 headers，不创建虚假模型。
- renderer 以 `selectedModelKeys.length === 0` 判断“连接已保存、模型待选择”，进入该连接的追加模型流程。
- 已接入平台和自定义连接不以健康检查、`/models`、文档发现或 AI 编译为保存事务的一部分。
- 不新增通用“任意模型自动接入”的虚假承诺；未知输入模式仍由能力编辑器或请求脚本继续完成。

## 4. 验收矩阵

| 旅途 | 必须验证的终点 |
|---|---|
| 首次打开模型页 | APIMart/Kie.ai 首屏可见；无搜索、空统计、顶部添加 |
| APIMart/Kie.ai | 页面只有一个 password input；空 Key 就地提示；有效 Key 保存预置模型 |
| 自定义 API 正常 `/models` | 先保存连接，再获取并选择模型，保存后进入连接/模型详情 |
| `/models` 404、超时或空列表 | 连接仍存在；可手动输入模型；关闭重开可继续 |
| 已有连接追加模型 | 不重新填写 Key；可多次进入、增删模型 |
| 文档缺失/AI 不可用 | 任务进入可理解终态；连接和模型保留；可手动接管 |
| 编译永不返回 | 在截止时间内 `timed_out`，不是永久“验证中” |
| 转到后台/重开设置 | 首页显示同一任务及真实进度，可重新进入 |
| 取消/重启 | 任务为 `cancelled`，不会被恢复执行 |
| 单模型失败 | 后续模型继续；成功结果可用；只重试失败模型 |
| MCP 管理 | 模型页无 MCP；自动化页能安装、验证、重连、移除，可信发起方独立 |
| 视觉回归 | 其他设置页截图结构不变；亮暗色、桌面与窄屏无溢出遮挡 |

## 5. 执行顺序

1. 先以测试锁定首页顺序、Key-only、save-first 和 MCP 归属。
2. 落模型首页与平台子页，再跑 renderer 定向测试与类型检查。
3. 放宽主进程空模型注册并补持久化测试，再串起保存后的追加模型页面。
4. 补齐/核验任务生命周期与手动接管测试。
5. 执行完整 `pnpm run gates`，随后在真实应用走首次、已有、失败恢复和 MCP 旅途。
6. 与最新 `origin/main` 合并，重新生成 Tailwind 产物，复跑门禁；通过 PR 合并到 `main`。

## 6. 回滚与交付

- UI 改动由单一任务分支和 PR 承载；不直接推送受保护分支。
- 新注册契约向后兼容：已有带模型调用保持不变，空模型仅新增 save-first 能力。
- 若 UI 旅途失败，保留已保存 vendor/credential，不自动删除用户数据。
- PR 合并前必须报告目标分支、提交、门禁、真实旅途和视觉检查结果。
