# Windows 拖拽区与浮层冲突修复（2026-08-09）

## 用户摩擦

Windows 无边框窗口里，浮层落在顶部附近时出现看得到但点不到、点一下变成拖动窗口的问题。

根因是两层结构叠加：独立的 32px 自绘窗口栏已经接管窗口拖拽，但下面 56px 的功能顶栏仍带 `app-drag`；同时任务面板、模型浮卡和通知把 64px 当作顶栏底部，忽略了 Windows 窗口栏，导致浮层与拖拽命中区重叠。

## 范围

- Windows 仅保留独立自绘窗口栏作为拖拽区，功能顶栏不再参与拖窗或双击最大化。
- 任务面板、模型浮卡、通知统一从“窗口栏 + 功能顶栏 + 间距”之后开始布局。
- 窗口栏内展开的上手清单面板也不得覆盖功能顶栏。
- 保持 macOS/Linux 原生窗口 chrome 和原有 64/68px 浮层基线不变。

## 不动项

- 不改变 Windows 窗口控制按钮、最小化/最大化/关闭 IPC 或窗口尺寸。
- 不改变浮层内容、宽度、右侧避让和关闭交互。
- 不给浮层新增遮罩或第二套窗口拖拽实现。

## 结构保证

- 纯函数测试锁住 Windows 与原生 chrome 平台的顶部基线。
- Windows 拖拽走查断言功能顶栏不是 `-webkit-app-region: drag`。
- 定向测试、类型检查、lint 和完整 gates 通过。

## 验证结果

- 顶部偏移与源码契约测试通过：Windows 浮层基线为 96px、通知为 100px；macOS/Linux 保持 64/68px。
- Electron smoke 14 条断言通过；批量生产真走查确认模型浮卡和通知互不遮挡。
- Windows 原生拖窗脚本在当前 macOS 机器按平台守卫跳过；脚本已新增“功能顶栏不得为 drag region”断言，供 Windows 环境执行。
- 完整 `pnpm run gates` 通过：453 个测试文件、4016 个测试通过，renderer 与 Electron 构建成功。
