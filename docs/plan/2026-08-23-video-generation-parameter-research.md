# 视频生成模式与参数调研计划

## 目标

回答一个用户价值问题：用户只描述想要的镜头效果时，Nomi 如何在不要求用户学习供应商参数的前提下，选择合适的生成模式、模型参数和参考素材，并且允许用户像编辑 UI 一样自由调整。

## 研究范围

1. TikHub 公开短视频样本：按“AI 视频提示词”“AI 运镜模式”“AI 短视频生成教程”搜索，抽取少量公开元数据和 540p 样本，分析真实用户反复表达的任务目标。
2. 顶尖产品官方文档：Google Veo、Runway、MiniMax、Luma 的模式、参数、输入约束和提示词建议。
3. 顶尖开源实现：Wan、Diffusers、ComfyUI/MotionCtrl 等，核对控制信号和模块边界。
4. 原始论文/基准：实体一致性、相机/主体运动控制、长片诊断、视频质量维度。
5. 结合 Nomi 当前生产运行与 MCP 方案，提出通用的意图层、能力层、参数选择层、质量验证层规格。
6. 盘点 APIMart 当前真实接入的视频模型、变体、模式、参考槽、字段名、枚举、互斥和默认值，并把盘点结果接入 Nomi 的纯推荐器测试。

## 任务边界（不能漂移）

本研究服务于 Nomi 的「用户输入 → 模式/参数/模型推荐 → 可编辑草稿 → 用户确认 → 生产提交」链路，
不是另做一个模型目录或供应商比较产品。P0 已完成的安全防火墙、草稿与已提交合同边界、确认前不触发 provider
副作用继续有效；本轮只补推荐层所需要的真实能力依据。

第一落点固定为 APIMart 已接入的视频档案。推荐器只消费现有 `ModelArchetype` / APIMart mapping 的能力声明，
不直接调用 provider、不铸 spend grant、不创建 ProductionRun job。推荐结果必须包含：命中的模型/变体、模式、实际可用参数
和给用户看的理由/限制；用户仍可以在提交前改模型、素材角色和参数。

推荐逻辑的硬约束：

- 先匹配素材与任务目标，再从当前模型真实存在的 mode/slot/param 中选择；没有对应能力就不推荐。
- 角色参考图优先选择能接收 `image_ref` 的图生/参考模式；首帧+尾帧优先 `firstlast`，不能退化成“仅凭 prompt 猜过渡”。
- 没有参考素材时才推荐 `t2v`；参考视频/音频只有在当前档案声明对应 slot 且满足依赖时才进入候选。
- 通用层只保存用户意图；`size`/`aspect_ratio`、`image_with_roles`/`first_frame_image`、分辨率/时长枚举和互斥关系留在模型/渠道档案。
- 任何未从官方接入文档逐项核对的字段标记为 unknown，不能凭同名模型或其他供应商经验补齐。

## 不做

- 不把某个供应商的字段直接变成 Nomi 公共 UI。
- 不凭 TikHub 热门教程的单条经验宣布某个参数普遍有效。
- 不在本轮接入真实付费生成或自动替换用户选择。
- 不把 `cameraIntent=orbit/path` 等用户意图当成 Seedance 的独立 API mode；相机语言只能按当前档案的 prompt/参考视频能力映射，否则明确标记为近似或不支持。

## 证据与验收

- 每条结论标记为观察到的事实、官方文档事实、论文结论或 Nomi 设计提案。
- 不保存 API key；原始 TikHub 数据和样本只放在 `/tmp/nomi-video-research-20260823`。
- 研究报告给出：模式/参数决策矩阵、供应商能力差异、缺失能力降级规则、真实用户任务测试矩阵和下一阶段决策点。
- 只在证据和用户价值链路明确后，另开实现计划；本轮不改生成代码。
