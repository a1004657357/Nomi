# 任务面板入口回归修复

## 背景与根因

`9893937b` 已把顶栏任务入口改为常驻，保证重启后即使内存队列为空，用户仍能打开任务面板和通知设置。后续 `519258b0` 从过期版本移植顶栏悬浮说明时，重新带回了 `TaskCenterButton` 的空队列 `return null`，并恢复了任务组的 `:has(button)` 隐藏规则，导致入口消失。

## 范围

- 新增常规 Vitest 结构契约：任务按钮不得返回 `null`，任务分组不得按按钮存在性隐藏。
- 恢复 `TaskCenterButton` 的非空返回契约。
- 恢复顶栏任务组常驻语义，保留现有图标、悬浮名称、状态色和数字徽标。
- 收口两份真机走查的旧判据：空队列入口常驻，四个意图分组对应三条可见分隔线。
- 联带修复同一真实旅程暴露的比例切换翻面：切换比例时保持 composer 当前连接侧，用户移动/缩放画布或可用空间变化后才重新评估上下翻转；折叠时间轴把手也计入真实遮挡边界。
- 修正空画布首个节点被“加载自动适应”误拉回中心：交互创建的首节点保留上半区落点，为下方 composer 预留完整空间；折叠时间轴入口固定右下，不再占据中央编辑通道。

## 不动项

- 不改变顶栏其他分组、比例选项、节点创建工具或任务队列数据语义。
