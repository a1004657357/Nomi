# Nomi 官网截图与版式配平

日期：2026-08-17
分支：`codex/marketing-media-balance`

## 问题

正式官网的产品截图虽然声明了横向 `aspect-ratio`，但图片元素同时带有 `height="1722"`，现有 CSS 没有覆盖这个确定高度。浏览器因此把 Hero、成本、工作流和 MCP 四处截图都渲染成 1722px 高：右图远高于左侧文案，移动端也出现连续长图。

## 目标

- 所有产品截图由固定画幅的父容器控制尺寸，图片只负责填充与裁切。
- 桌面端成本文案与证据图、工作流步骤与证据图共享高度基线。
- 移动端截图保持紧凑横向画幅，不形成超过一屏的单张长图。
- 保留现有信息架构、文案、截图资源、交互与中英文 SEO 契约。

## 设计方向

- Hero 截图回到正文栅格，采用宽银幕画幅，只展示足够理解产品的工作区证据。
- 成本与 MCP 截图采用约 `16:10` 画幅，与左侧文字列视觉重量接近。
- 工作流截图采用约 `21:10` 画幅，四个步骤拉伸到同一高度，形成明确的左右对照。
- 移动端统一为 `4:3` 画幅，通过 `object-fit: cover` 聚焦界面中心，不缩成无法阅读的整页缩略图。

## 实现

- 在 `scripts/marketing/template.mjs` 为工作流图片补充独立 frame。
- 在 `scripts/marketing/styles.mjs` 建立共享媒体 frame 规则并重设四处布局比例。
- 重新生成 `marketing/index.html` 与 `marketing/en/index.html`。
- 在 Playwright 走查中增加截图画幅、图片填充和桌面左右配平断言。

## 验收

- 中英文桌面 `1440x1000` 与移动端 `390x844`、英文 `320x760` 无横向溢出。
- 四处截图 frame 均为横向画幅，图片高度不再固定为 1722px。
- 桌面成本左右列、工作流左右列高度差不超过 2px。
- 移动端任一截图 frame 高度不超过其宽度。
- 下载、语言、二维码、tabs、dialog、无 JS 与 reduced-motion 行为保持不变。

## 回滚

回滚模板、样式、测试和生成 HTML 后执行 `pnpm run build:site`。
