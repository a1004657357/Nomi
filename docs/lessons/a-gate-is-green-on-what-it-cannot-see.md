# 门岗对它看不见的东西永远是绿的

> 📎 教训 · 首次记录 2026-09-28 · 状态：✅ 已固化（`check:mockup-contracts` 认文件夹样张）
> **触发场景**：一道门岗报「通过」，而你要确认的东西在它的扫描范围之外，比如换了一种文件布局、一种命名方式或一个新目录。

**结论**：门岗说「通过」，只证明它扫到的东西没问题。拿它当证据前，先确认你关心的那样东西在它的扫描范围里。新写一道门岗，先造一个它必须拦住的样本，看它红，再落地。

**为什么会踩**：
- 形态契约门岗 `scripts/check-mockup-contracts.mjs` 的职责是「有样张的功能面必须有契约」，契约要在真实应用的走查里跑。
- 可它只枚举 `docs/design/mockups/*.html` 这一种单文件样张。
- 2026-09-28 版本卡片的获批样张是一个文件夹（`2026-09-28-version-cards/index.html`，带截图和 README）。门岗根本没看见它，不要求写契约，一直显示绿。
- 结果：
  - 实现把「和节点一样大」的卡片做成了几十像素的缩略图，排法也不对，门岗一声没吭，直到协调会话人工对账才发现，白白多花一轮实现；
  - 同样漏掉的还有 7 份历史文件夹样张（分镜表 v6、剪辑面板、技能库卡片等）。
- 另一个同时存在的洞：做样张时写的 40 条交互断言是一次性脚本（`D:\tmp`，不进仓库），只拿样张自己跑过，没有变成在真实应用里跑的契约。

**怎么用**：
- 门岗枚举对象时，按「这类东西可能有哪几种形态」写：单文件、文件夹、多页，而不只写你手边那一种。
- 认领关系按对象的**身份**认（契约里声明的 `mockup` / `mechanizes.doc` 路径），别只靠文件名前缀猜。
- 样张一拍板，它的交互断言就进仓库、写成契约（`docs/design/mockups/contracts/<样张>.intent.mjs`），由走查在真实应用里跑。「只测样张自己」不算验收。
- 报完成前问一句：这次改动涉及的东西，哪几道门岗真的扫到了？

**出处**：
- 分支 `claude/mockup-contract-folders`：门岗改为认文件夹样张，按契约声明的路径认领；基线新增 7 份历史欠账；探针文件夹样张验证会红；
- 版本卡片 V2 验收记录（协调交接文档 09-28）。
