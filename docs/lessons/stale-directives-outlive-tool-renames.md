# 技能里的指令会跨代累积，模型服从的是过期那条

> 📎 教训 · 首次记录 2026-09-18 · 状态：现行
> **触发场景**：Agent「读完就只回一段文字、根本没调工具」；或者你刚改完一个动词的名字/语义，准备说「技能也同步了」。

**结论**：改动词时，除了同步技能里的**工具名**，还要同步技能里**关于这个工具的祈使句**。
名字对不上有门岗（`check:mcp-tool-refs` 会扫技能正文与 frontmatter）；
「该不该调用它」这类指令过期了，**今天没有任何机器看得见**——只有模型看得见，而模型会照做。

**为什么会踩**：

2026-09-18 真机，用户点「新建方案」让 Agent 照文稿出分镜，5 轮真模型 **4 轮没调任何工具**，
只把三个镜头写成了聊天文字。翻 `skills/workbench-storyboard-planner/SKILL.md`，相隔两行：

```
:202  - **首次**拆镜头：一次 `draft_shots` 产出整组草稿，不要拆成多次。
:203  - **绝不调用写画布/生成类工具**——你只产出方案对象，落画布与生成由用户确认后系统处理。
```

而 `draft_shots` 正是写画布的工具。frontmatter `:3` 的 description 也还写着「不直接落画布或生成」。

`git blame` 查出两代：
- `:203` 来自 2026-06-13 `44304dd42`，当时这技能配的是**只读**的 `propose_storyboard_plan`，
  那句话在当时**完全正确**。
- `draft_shots` 那几句来自 2026-09-15 `8bd61d0f4`。那次改了正文 19 行，
  **但没动 `:3` / `:203` / frontmatter 的 provenance 字段**。

两条都读起来像正经纪律，单看哪一条都不像 bug；只有并排看、并且知道 `draft_shots` 属于哪一类，
才看得出它们互斥。模型没有这个上下文，它选择了服从禁令——这是**最保守的读法**，不是模型的错。

关键区分：这**不是**「技能指着已删的工具名」那一类。那一类 2026-09-18 已经做成门岗
（`check:mcp-tool-refs` 扫 frontmatter 声明与正文里的退役名，退役名单 `scripts/retired-tool-names.json`
逐条带 git 证据）。本条里工具名一个字都没错，错的是**围绕它的行为约束**。
门岗能比对名字，比对不了祈使句的语义。

**怎么用**：

- 改动词的**语义类别**（只读 → 会写、免费 → 花钱、单次 → 批量）时，把引用它的技能**整篇读一遍**，
  不要只 grep 工具名。`grep draft_shots` 那次是绿的——名字全对。
- 删一条过期禁令前先拆开它：`:203` 里「不许写画布」过期了，「不许花钱」仍然成立。
  整句删掉会连带删掉花钱边界。正确处置是**只删过期那半**，改成
  「绝不调用花钱的工具——你只用 `draft_shots` 落草稿，`generate` 出报价卡是用户点头后的动作」。
- frontmatter 的 `description` 是**模型会读到的指令**，不是文档摘要。它和正文矛盾，等于多一条过期祈使句。
- 技能包里带 `source.revision` / `changes` 这类 provenance 字段的，改正文时一并校正。
  09-15 那次改了 19 行正文，`changes` 却还写着「the skill body is unchanged」——
  这行假声明会让下一个人以为正文是上游的、不该动。
- **判「Agent 坏了」之前先分三种**：没调工具 / 调了被拒 / 调用成功但读不到结果。
  三种的根因完全不同。这次 4 轮是第一种（指令），1 轮是第二种（宿主契约），
  而修完前两种之后露出来的是第三种（两套账本）。一次只看一层会反复误诊。
