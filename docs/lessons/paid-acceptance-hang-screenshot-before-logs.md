# 付费验收挂住时，第一步是截图，不是读日志

> 📎 教训 · 首次记录 2026-09-18 · 状态：现行
> **触发场景**：一条要真花钱的验收（付费 e2e / 真模型走查）迟迟不返回，你正准备去 `tail` 日志找原因。

**结论**：**先截一张屏，再读日志。** 付费验收挂住只有三种可能——网络在等、供应商在排队、界面上有个框在等人点。日志只能分开前两种，第三种在日志里长得和「还在等上游」一模一样；而一张截图一眼就能把三种分开。

**为什么会踩**：2026-09-18 档案批 lane 跑 APIMart 的 7 条真机封印时挂住，先读日志：请求已发出、无错误、无响应——看起来像供应商慢。实际是本机弹了一个需要点击的确认框，进程一直停在那里。日志里「等上游」与「等人点」都表现为「最后一行之后什么都没有」，因为**等待发生在我们这一侧的 UI 线程上，根本不会产生日志行**。同一批 lane 还发现仓里四个付费 e2e（`apimart-params` / `apimart-gemini-vision` / `happyhorse` / `modelscope-expand`）因为既不铸 spend grant 也不点确认框而长期默认 SKIP——「闸门加了、脚本没跟上」同样是日志看不见的一类。

**怎么用**：
- 付费/真机验收挂住超过一个正常轮询周期 → 立刻截图（`screencapture -x` 或走查里的 `screenshotSettled`），看完再决定读不读日志。
- 写付费验收脚本时，把「挂住即自动截图」做进超时分支，不要指望事后补。
- 判「供应商慢」之前必须有一张证明屏幕上没有等待框的截图；没有截图的「上游慢」结论不作数。
