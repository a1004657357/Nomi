# 不在任何 CI 链里的走查会**一批**腐烂：四条分镜走查同天全红，21 层过期里藏着 1 个真回归

> 📎 教训 · 首次记录 2026-09-18 · 状态：现行
> **触发场景**：某个面的多条走查同时红；报错是「点不到 X」「定位器过期」「等满 Ns 都没可见」；或者要判断「走查红 = 产品回归还是走查过期」。

**结论**：先在 `origin/main` 基线提交上复跑一遍拿到 delta=0，再按下面四种「死法」逐条归类；**每一条先打探针（截图 + DOM 属性 dump）再改**，改断言前必须能说出「是哪次提交、为什么、改成了什么」。一条走查里往往叠着**好几层**过期——第一层修完只会露出第二层，别在第一层就报「修好了」（本次四条共 21 层，跑了 11 轮真机）。

**最重要的一条**：腐烂的走查会把**真 bug 一起藏起来**。这四条里，前三条纯属走查过期，第四条剥掉 4 层过期之后露出一个真回归——Agent 落方案后画布上不长分镜表节点（落盘 `project.json` 里 `generationCanvas.nodes` 为空，而 `docs/audit/2026-09-10-shot-table-storyboard-walk.md` 记过它当时是好的）。所以「先假定是走查过期」是**排查顺序**，不是结论：每剥一层都要重新问一次「这层是走查错了还是产品错了」，剥到最后一层仍要问。

**为什么会踩**：`tests/ux/storyboard-*.walk.mjs` 四条不在 `quality-gate.yml` / `desktop-rc.yml` / `REAL_USER_TEST_MANIFEST` 任何一条链里，只靠人手跑；从 2026-09-06 到 09-17 之间分镜面经历了 v6 信息架构（0d5a56d47）、删行展开态（0fc4768fb）、删摘要卡（805096d41）、通知策略改行内（4a5f52130）、两批按钮文案清扫（2b59d13ef / ac2fa59e7）、候选名单收成可用性判据（88a485019）——每一次都合法，每一次都没人跑这四条。到 09-17 发现时它们已经**叠着**过期：

| 走查 | 报错表面 | 叠着的过期层（按修复顺序露出） |
|---|---|---|
| `storyboard-table-exec` | 「暂时无法验证密钥」 | ① 给 `authType:'none'` 家经渲染层存 key（产品**按设计**拒，且可用性早已不看 `hasApiKey`）→ ② 摘要卡「再次编辑」→ ③ 按钮「用新图重跑」→「新图重跑」→ ④ 场组头与「播放本场」撞 strict mode → ⑤ 参考卡区默认收起 + `data-anchor-stat` 只在展开行 → ⑥ 顺播计数混进参考卡行、提示改逐镜 → ⑦ 批量钮不再印计数 → ⑧ 结果即收证据挪到参考卡区 → ⑨ 参考卡悬停浮层被删（组件成了零调用点的死码）→ ⑩ 行操作菜单「删除镜头」→「删除」→ ⑪ 形态契约仍是 v5（v6 只更新了人读的设计合同，没迁机器契约）|
| `storyboard-table-phasec` | 「打开分镜页」不可见 | ① 摘要卡 → ② 上传后 @ 面板不刷新、重开时机竞态 → ③ 文案「此模型」→「该模型」→ ④ 行展开态/台词/转场整段删除，解绑搬进参考槽弹层 |
| `storyboard-strategy-resolve` | 「闸没有给出任何提示」 | ① toast 改行内 `data-storyboard-action-feedback`（闸**在**，钱没漏）→ ② 种的视频模型没映射 = 不可用 = 被替换成别家 |
| `shot-table-storyboard-projection` | 「新建分镜方案」不可见 | ① 改名「新建方案」→ ② 拆分镜不再有计划卡/「确认」，直接经工具落方案 → ③ 落地后面板 surface 切到 storyboard，钉 creation 的定位器假绿 → ④ 工具回执是折叠 `<details>`，看在不在别看可见 |

关键判据：**报错说的是最先撞到的那一层，不是全部**。每修一层要重跑一次；一条走查跑五轮才绿是正常的。

**怎么用**：
- 先复跑基线（`origin/main` 干净 worktree + `pnpm build`）确认 delta=0，再动手。
- 每层过期都去 `git log -S"<旧文案/旧属性>" -- src/` 找到删/改它的提交，把提交号写进走查注释——下次再红时读者能直接判断「又是哪层」。
- 死选择器改完必 `grep -rn` 全仓其它用法（`mantine-Notification-root` 还有 9 处，其中只对 `level:'inline'` 那类失效）。
- 固定等待一律换 `stationTimeout()`；`scripts/station-waits-baseline.json` 里被改动行的指纹用文本级删除，别整文件重写。
- 剥到某一层改不动了，先去**落盘状态**找判据（项目文件 / 目录文件），别只看 DOM：本次就是靠隔离 profile 里的 `project.json` 认定「节点从没被创建」，而不是「创建了没渲染」。
- 走查绿了以后**把它接进一条 CI 链**，否则下一轮改版它照样烂：零额度的三条（exec / phasec / strategy）可进 journeys 维度，真模型那条只能本地跑。
