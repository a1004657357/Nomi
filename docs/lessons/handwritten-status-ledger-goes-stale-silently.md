# 手写的状态账本没有时刻，读的人会把旧快照当现状

> 📎 教训 · 首次记录 2026-09-18 · 状态：现行
> **触发场景**：你正要根据某份「盘点 / 台账 / inventory / 现状清单」下结论，比如「X 还没部署」「Y 还没合」。

**结论**：**手写的状态账本是一张快照，不是一个真相源。** 引用它之前先问「这行是几点写的、我现在能不能现查一遍」；能现查的（部署没部署、合没合、跑没跑）一律现查，账本只用来找线索，不用来下结论。写账本时必须给每条状态标上采集时刻，否则下一个读者看不出它已经过期。

**为什么会踩**：2026-09-17 批次 2 收尾时，主会话按 `release-inventory-20260917.md` 报了「Cloudflare Worker 仍未部署」。那行是 17:40 写的，而 Worker 19:1x 就已经上线（`https://nomi-feedback-intake.2373272608.workers.dev` 在线、仓库两个 secret 都已设、端到端验过 NF-0917-0001）。账本本身没有错——它准确记录了 17:40；错在**它长得像现状，而不像快照**：条目里没有时刻，读的人不会想到要重新核。同一天 `docs/roadmap/TODO.md` 里 T-AG-12 也因此陈旧地写着「待用户部署」。

**怎么用**：
- 账本里每一条状态后面写采集时刻（不是文件头写一个日期就算）；没有时刻的状态行视为不可引用。
- 下「X 还没做」这种否定式结论前，先跑一条能现查的命令（`curl` 端点、`gh pr view`、`git cat-file`），再引用账本作旁证。参见 [下否定式结论前先证明你在哪个 checkout](prove-which-checkout-before-negative-claims.md)。
- 能机器派生的状态（PR 合没合、服务在不在线）就别手写进账本；手写只留给机器答不了的判断。
