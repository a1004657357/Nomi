# 拒绝话术只对人说，不对 Agent 说——它照做不了，只能卡在那儿

> 📎 教训 · 首次记录 2026-09-18 · 状态：现行
> **触发场景**：你要写（或看到）一条工具错误文案，内容形如「请到设置里选择模型」「请先在偏好中配置 X」。

**结论**：**凡是工具返回给 Agent 的错误，必须同时给出 Agent 自己走得通的那条路。** 「请到设置里选模型」是给人的指路——Agent 没有手，点不了设置；它收到这句话只能重试或放弃。正确写法是在同一条错误里补上它能执行的动作，例如「也可以在调用里直接点名模型：`candidate: { providerId, modelId }`，可用值见 `list_models`」。

**为什么会踩**：2026-09-18 全自动档真花钱腿的走查里，`draft_shots` 解不出模型时返回的就是一句纯人类指路。Agent 读到后没有任何可执行的下一步，整条 lane 卡死，表现却像「模型不可用」。根因修掉之后（传输层不再丢 `candidate` 的模型身份），这条话术仍然是错的——**它描述的是人的操作面，而调用方是程序**。这一类在仓里不止一处：任何写着「请到…里…」的工具错误都有同样的毛病。

**怎么用**：
- 写工具错误文案时自检一句：「收到这句话的如果是一段程序，它下一步能做什么？」答不出具体调用 = 重写。
- 人类面与模型面是两个受众：面板上给人看的可以说「去设置里选」，返回给 Agent 的那份必须带参数名与取值来源工具。两份文案不要共用一个字符串。
- 排查「Agent 卡住不动」时，先把它最后收到的那条工具错误原文读出来，判断里面有没有它能执行的动作。
