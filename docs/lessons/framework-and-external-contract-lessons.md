# 接框架与外部契约的几次学费（从 engineering-rules.md 瘦身时搬来）

> 📎 教训 · 首次记录 2026-10-02（事件发生在 2026-08 至 2026-09） · 状态：现行
> **触发场景**：接框架 / SDK、对接外部文件格式或供应商 API、判断「某工具支不支持某能力」、给安全关键依赖设计可选成员。

**结论**：凭记忆判断等于没查；只接了框架最底层、只按自己列的清单核对、只看本机旧版本，都会让「做对的和做错的写在相邻两行」而文档级交付物一个字都拦不住。

- **只接了最底层的 agent loop（2026-09-06，#546）**：pi 已提供会话持久化、有序转录、重试、价格和 `steer()/followUp()`，我们各写了一套且更差（内存会话 + 自研快照替掉落盘与迁移、两处开关关掉 provider 级退避、自己维护 steering Map 拼进下一次 prompt）。治法：四列表 + 参考实现逐层对照 + 逐字段裁决（R5.4）。另见 [reference-implementation-not-dissected-is-not-research](reference-implementation-not-dissected-is-not-research.md)、[doc-level-conformance-misses-field-level-hardcoding](doc-level-conformance-misses-field-level-hardcoding.md)。
- **逐字段硬写（2026-09-07）**：同一天刚交完逐层对照，`laneTools.mts` 仍给所有 lane 工具硬写 `executionMode: 'sequential'`，而上游该字段逐工具可选；相邻一行的 `replay` 已经从 `mutates` 派生。`check:framework-surface` 起因于此，装上当天还抓到别的分支合入造成的三格真漂移。
- **自造了生态已有的格式（2026-09-07）**：技能格式官方只有 `SKILL.md` + frontmatter，我们另起了 `skill.json`，用户的技能包导不进来，文案还在引导用户去造这个文件。同一机制：研究这一步靠人记得，高负载下必漏。
- **拿本机旧版本断言「不支持」（2026-09-01）**：按本机 2026-06 的 CLI build 断言它给不了新模型，被官方文档当场纠正（新版早已支持，且图片必填参数变了）。实查对象是现役文档，不是本机。
- **模型参数数字没一个来自文档（2026-08-12）**：某档案的参考图 / 视频 / 音频上限与默认比例四个数全错，文件头却写着「契约逐项对账自官方文档」。声称对过与真的对过之间没有验证手段，所以出处要落库不落注释。
- **安全关键依赖写成可选成员（2026-09-03）**：`McpTransport` 的确认回调可选，打包态装配点漏传，开发态 43/43 全绿、打包态 15/43；客户端确认面整条不可达数月而单测全绿。登记欠账不阻止下一个人合法地漏传，要把依赖改成必填（R17）。
- **Agent 工具真实模型 0/18（2026-09-06，#547）**：单测喂的是手写合法参数，从来没有真实模型试过填它，所以 Agent / 工具改动要有真实模型的写对率（R13.1）。
