# 省额度：重复的事写脚本，有界的机械活给 Codex，要判断的才用最贵的模型

> 📎 教训 · 首次记录 2026-09-22 · 状态：现行
> **触发场景**：你是编排会话，准备派工；或者发现某个后台工人已经烧了几十万 token；或者同一张统计表 / 同一串状态检查命令你（或工人）已经是第二次现写；或者额度撞了上限（HTTP 429）工人被切断。

**结论**：保质量的前提下，额度花在**判断**上，不花在**重复**上。派工前过三问：

1. **这件事以前做过一模一样的吗？** 做过 → 写成脚本进仓库（或 scratchpad），以后跑脚本，不让模型再现写一遍。
2. **它有界、机械、有判官吗？**（只新增文件或按规则替换；验收是测试或一组已知数字）→ 发 Codex，或用便宜档模型。
3. **这个工人的上下文是不是已经很大、而剩下的活很小？** → 别续跑，起一个新工人给一份紧凑任务书。

只有要判断的活（状态机、花钱路、根因、UI 取舍）才用最贵的模型。

**为什么会踩**：

2026-09-21/22 一晚上，两路 Opus 工人各烧 50–95 万 token，04:3x 同时撞额度上限被切断，两边都停在半截（一边 19 个未提交文件、一边 154 张被误重录的基线）。复盘消耗去向：

- **同一份报表每轮重写**：「工具 × 错误类型 × 次数」三轮真实模型评测，每轮都是工人现写统计，编排会话自己也手写了两遍内联 Python。
- **续跑超大上下文**：工人历史接近一百万 token 后仍用 `SendMessage` 续跑——它每走一步都在为整段历史再付一次费，而剩下的只是五个小尾巴。
- **重复的状态检查**：编排会话每次手敲同一串「三四个 worktree 各停在哪 + 心跳 + main 最新」。
- **档位不分**：截图重拍、基线清理、只读核对这类活也派给了最贵的模型。

**怎么用**：

- **分档**（配合 playbook 的派工分级）：

  | 活的形状 | 给谁 |
  |---|---|
  | 状态机 / 花钱路 / 根因 / UI 取舍 / 新供应链 | 最强模型 |
  | 只读核对、截图重拍、基线清理、按清单改文案 | 便宜档模型 |
  | 有界 + 机械 + 有判官（只新增文件，或按规则批量替换） | Codex |
  | 每次都一样的统计 / 检查 | 脚本，不用模型 |

- **发 Codex 的姿势**（命令行可用即可，应用里的 MCP 连接断了不影响）：

  ```bash
  # 先 30 秒探活
  codex exec --skip-git-repo-check -s read-only "Reply with exactly: CODEX_OK" </dev/null
  # 独立 worktree、关 stdin、脱离会话、日志带 worktree 后缀
  nohup codex exec -s workspace-write -C <独立 worktree 绝对路径> "$(cat brief.md)" \
    </dev/null > <scratchpad>/codex-<任务>-<worktree>.log 2>&1 & disown
  ```

  任务书写死四件：**只新增文件（或列明可改的文件）**；**不 commit / push / checkout**；**不跑 gates、Electron、Playwright、pnpm install**；**必须复现的已知数字**当验收（例：「run1 必须得到 121 次调用、45 次重试，对不上先查自己的解析」）。回来后编排会话核数字、读 diff，自己提交。`</dev/null` 的原因见 [codex-exec-background-needs-stdin-closed](codex-exec-background-needs-stdin-closed.md)；`-s read-only` 连 scratchpad 都写不了，要落文件至少 `workspace-write`。

- **别续跑大上下文**：工人累计 token > 约 50 万且剩余工作小 → 新开一个，任务书里写清盘上现场（分支、HEAD、哪些文件、哪份报告的哪一章）。盘上现场 + 报告就是交接，不需要它「记得」。
- **脚本化的两个现成例子**：`scripts/agent-trajectory-report.mjs`（轨迹 JSONL → 工具×错误表、归一化失败正文 Top-N、多轮并排对照、最长重试链）；编排会话 scratchpad 里的 `lanes.sh`（各 worktree 分支/HEAD/脏文件数 + 心跳尾行 + main 最新 + Codex 日志尾，一条命令看全）。
- **每完成一块立刻 commit + 追加报告 + 写心跳**：额度上限、断网、应用崩溃都会在任意时刻切断工人；没落盘的活 = 白烧的额度。
- **不许省的**：花钱路真机走查、真实模型数字（工具写对率 / 回合成功率）、编排会话亲眼看截图、跨池独立验收、根因分析。省掉这些换来的是「测试全绿但一用就坏」，返工比省下的贵得多。

**出处**：2026-09-22 用户原话「后续可以考虑一下额度的消耗…在保证质量的前提下…有些是不是可以写自动化脚本，有些也可以发给 codex，当然不是所有」；当晚两路工人 429（`You've hit your session limit`）同时被切断的现场；Codex 探活 `CODEX_OK`（codex-cli 0.155.1）；首个按此法外发的任务 = `scripts/agent-trajectory-report.mjs`。
