把对话当界面设计。

Claude Code / Codex 里不渲染图片、不渲染卡片——用户能看见的只有对话本身。所以体验 = 一场好对话：接住时复述确认，该定方向时给方案选，干活时报进展，花钱前请示，交付时给结果和链接。同一份数据两级呈现：终端是文本，桌面客户端（Claude Desktop / claude.ai / Cursor）是真卡片。Nomi 窗口退位为「媒体与控制室」。

核心取舍确认不是越多越好也不是越少越好——按「错向代价 × 确认成本」设五道门（方向 / 剧本分镜 / 预算 / 样片 / 粗剪），其余全部自主跑但留痕可纠；配三档信任档位，用户一句话可调。左卡右上角可切「终端 / 桌面富渲染」看同一幕的两种形态。

五道门：哪里停，哪里不停

判断公式：错向代价（定错后下游要重做多少）× 确认成本（表态要几秒）。比值高才设门；其余自主跑、参数回显留痕、随时可纠。模型不单独设门——它是预算合同里可见可改的一行，不是用户目标（通用第一）。单张图/单段视频的小任务只走预算确认，不套五门。

信任档位（run 级，写进合同可查证）：关键确认（默认，五门全开）／ 只管钱（跳过创意与样片门，留预算 + 不可逆）／ 全程确认（每镜提交前都停）。对话里说「别问了直接出」= 降到只管钱。

为什么不是仪表盘？

2026-08-11 实查（官方文档 + changelog）：Claude Code 终端不渲染工具结果里的图片（只有模型看得见）、不渲染 MCP Apps 卡片（官方宿主名单没有它），工具调用默认折叠成一行。08-10 版 blueprint 的「聊天端媒体卡 + run-card」在主力客户端上等于不存在。反之，上面六幕用到的每个机制——转述（工具结果→模型讲人话）、行内进度（notifications/progress，Claude Code 实时渲染且防超时）、反问弹窗（elicitation，v2.1.76+ 原生表单）、resource_link 深链、系统通知（Nomi 自发）——全部是官方支持且今天就可见的。同一份 run 事件流喂所有端：Desktop / Cursor 用户额外看到已实现的 MCP Apps 状态卡（增强层，不是中心）。Higgsfield 官网演示里的品牌调用卡（logo + 提示词 + 参数 chips）就发生在这一层——它在终端里的等价物，正是各幕的「参数回显」文本行：降级不降义。
