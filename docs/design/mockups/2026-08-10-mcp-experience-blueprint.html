01 / REAL FRICTION

问题不是“少一个进度条”，而是没有统一回执。

现在的 Nomi、MCP 工具结果、任务中心各自只掌握一部分信息。用户一旦离开 Nomi，就不知道任务是在运行、等审批、失败，还是已经断线；也不知道媒体产物到底有没有真正可见。

连接 ≠ 配置存在必须真实启动、握手、验证轻量调用。
运行 ≠ 假百分比没有真实总量时，只报阶段和已用时间。
失败 ≠ 一个错误码必须说明原因、下一步和诊断编号。
02 / ONE RUN HUB

一个事件主干，服务所有客户端。

每次 MCP 调用都生成 invocationId 和 runId。生成服务只向 Run Event Hub 写真实事件，Codex、Claude、Nomi 和系统通知从这里读取同一份状态，并按客户端能力展示图片、视频和确认动作。

INPUTCodex / Claude

发起任务，携带客户端、会话和调用标识。

EXECUTION模型与生成服务

提交、服务处理、下载、校验都发真实阶段事件。

Run Event Hub

任务状态的唯一真相源，持久保存并允许断线恢复。

05 / DELIVERY ORDER

先让它可靠、可见、可确认，再做高级富交互。

Higgsfield 值得借鉴的是“对话是驾驶舱、workspace 是归档与编辑处”，不是照抄某张卡片。Nomi 还需要补上连接修复、媒体回执、原地确认、并发审批和真实恢复能力。

P0先做

可用且看得见

修复真实连接、媒体回执和原地确认，这是发布门槛。

  • 连接诊断与一键修复
  • 统一 runId、来源和下一步动作
  • 图片缩略图、视频首帧与资源链接
