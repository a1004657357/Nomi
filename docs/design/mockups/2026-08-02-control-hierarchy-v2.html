控件分层法 · 四面样张 v2

v1 收得太狠，这版换个顺序做。左/上 = 今天的真实布局；右/下 = v2 提案。
已用真机截图逐项对账（docs/design/mockups/2026-08-02-real-ui/），对账中改掉了三处我原先画错的地方：3D 顶栏任务页签的位置、把「选中假人」和「选中相机」两个不会同屏的右栏画成了同屏、以及漏画的项目库页。

v1 错在哪（已作废）：① 把「常驻 ≤5」当硬指标去凑数，为了达标连中频的也收了（抠图、优化、×N 其实常用）。 ② 更蠢的一条——切图▾ / 变换▾ 本来就是二级菜单、一次点击可达，v1 把它们塞进「编辑▾」变成三级：为了少一个按钮，让用户多点一次。 「≤5」从此只当观察指标，不当门槛。
v2 的顺序：先分组 → 再去重 → 再归位 → 最后才收纳
  1. 分组控件一个不少，只是有了边界和名字。「杂」的主因是没秩序，不是数量。
  2. 去重同功能的多个入口收成一个。减的是真冗余，可达性零损失——下载 5→1、放大预览 4→1、截图语义 3→1。
  3. 归位放错地方的搬回它该在的地方。语言/外观/检查更新本来就该在设置里（设置的「关于」tab 现在还是空的）。
  4. 就近情境控件搬到它作用的那个对象旁边。不是藏，是别让它挤在常驻条里导致布局抖动。
  5. 收纳只有真长尾才进 ▾。全 App 只剩一处：3D 的约 40 个逐骨骼姿势滑杆。

三、剪辑控制条：15 件一个不减，但终于分得出「整片」和「这一段」

现在这条 toolbar 最大的坑不是长——是「画幅」改的是整片、「显示 / 取景缩放」改的是当前这一段，两类混排在同一条里，用户根本不知道自己在改什么。v1 想把它们全收进「画面▾」，那等于把问题藏起来。

分组控件一件没减，只是套进 4 个有名字的组。关键是「这一段 · 镜 3」这组用 accent 底色 + 写出当前片段名——用户一眼知道自己改的是这一段、不是整片；没选中片段时这组自动灰掉（真机上「显示 适应」现在就是灰的，因为它本来就是 per-clip 的，却和整片的「画幅」并排长得一模一样）。
就近时间轴头部那 4 颗选中才冒出来的工具（重生成 / 前移 / 复制 / 后移）搬到片段自己头上。它们现在挤在常驻 pill 里，一选中整条就变长、布局跟着抖——把情境控件塞进常驻条的典型症状。
「文字」留在原位（v1 想撤掉它，错了，加字幕是常用动作）。
真机对账补充：那 5 道分隔线在真机上淡到基本看不见，所以「有分隔」约等于没有——这也是为什么要改成有底色、有名字的分组。
