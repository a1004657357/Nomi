# 生成画布控件辨识与比例连续性优化设计

日期：2026-08-06
状态：交互样张已获用户确认，待书面规格复核后实施

## 1. 目标与真实摩擦

这次不是给画布继续堆功能，而是让已有能力在第一次使用时就能被看懂、选中后不打断操作。

用户连续遇到六类摩擦：

1. 生成数量只显示 `×1`，点击后循环切换，不能明确选择 1、2、3、4，也没有 3。
2. 比例面板里的 `auto` 是英文，且与有轮廓的比例选项共用双行布局后，上方形成空槽。
3. 左侧创建节点栏只有图标，缺少稳定名称；旧界面还把一部分能力藏进省略号，用户必须逐个试。
4. 顶栏有的按钮带名称、有的只有图标；分段圆环不能自然表达“任务”，设置又与浏览器混在同一工具组。
5. 改比例时节点高度变化、底部编辑框冻结，二者之间出现断口；参数浮层或触发器若随几何变化移动，鼠标还要追着控件走。
6. 固定节点宽度再改比例会把 1:1 的大节点压成 21:9 的小条，虽然比例正确，视觉重量却越来越小。

底层判断：比例切换是“换画幅”，不是“缩小内容”；工具栏是高频入口，不应靠记忆图标或展开省略号才能使用。

## 2. 现状证据与根因

### 2.1 现有代码

- `NodeGenerationComposer.tsx` 把生成数量保存为 `1 | 2 | 4`，按钮每次点击按 1 → 2 → 4 循环，结构上无法选择 3。
- `InlineParameterBar.tsx` 的 `ratioShape()` 只识别数值比例；同组存在轮廓后所有选项都进入双行布局，`auto` 因无轮廓显示为空槽。
- `CanvasToolbar.tsx` 当前已经直接声明 8 种 `PRIMARY_NODE_KINDS`，但使用原生 `title`，反馈延迟且视觉不一致。上下文创建菜单 `NodeAddMenu` 另有用途，不属于左侧栏省略号。
- `NomiAppBar.tsx` 把上手、浏览器、设置放在同组；`TaskCenterButton.tsx` 使用无文字的 `IconProgress`；设置同样只有图标。
- `nodeSizing.ts` 以已有宽度为常量，只根据比例推导预览高度，宽比例因此退化成越来越薄的横条。
- `NodeGenerationComposer.tsx` 的 `freezeShift` 在参数面板打开期间冻结编辑框位移；节点尺寸仍变化，于是锚定关系被拆成两套时序，形成断口。

### 2.2 已批准样张结论

最终交互样张验证了三项几何不变量：

- 1:1 约 381 × 381，21:9 约 582 × 249，9:16 约 286 × 508，面积均约 14.5 万，视觉重量近似不变。
- 三次切换中，底部编辑框的 bounding box 完全相同。
- 比例触发器和已打开浮层的 bounding box 完全相同，用户不需要追鼠标。

顶栏采用已确认的 A 方案：任务独立；上手与浏览器为工作辅助；设置与模型接入为配置；“去出片”为唯一主动作。

## 3. 方案取舍

| 方案 | 用户看到什么 | 代价与判断 |
|---|---|---|
| **A. 面积守恒 + 编辑器锚点不变（采用）** | 宽画幅变宽、竖画幅变高，节点仍像同一个对象；编辑框和浮层不跑 | 需要统一节点尺寸与位置更新，但从根因上消除缩小、断口和追控件 |
| B. 固定宽度，只改高度 | 实现最接近现状 | 21:9 被压成小条，正是用户否定的体验 |
| C. 固定外框，仅在内部 letterbox | 节点大小完全不变 | 节点外形不再表达真实画幅，画布扫视时会误判输出比例 |

采用 A。真正的取舍是“实现简单”与“空间连续性”之间的取舍；画布是空间工具，连续性优先。

## 4. 最终交互设计

### 4.1 生成数量：显式选择 1–4

- 把循环按钮 `×1` 替换为紧凑选择器，摘要显示“1 张”“2 张”“3 张”“4 张”。
- 点击后在触发器正上方打开 1、2、3、4 四个等宽选项；选择后只更新数量并关闭，不立即生成。
- 默认 1 张；选择仅保存在当前节点编辑会话，不新增项目持久字段。
- 生成期间禁用选择器，避免一次请求的确认数量与实际调度数量不一致。
- 费用确认、任务创建与 `confirmAndRunNodeVariants` 都使用同一个选中值，3 张与其他数量走同一通用链路。
- 删除旧的点击循环逻辑和 `1 | 2 | 4` 类型，不保留第二套入口。

### 4.2 比例自动项：本地化且不留空槽

- 内部参数值继续使用供应商无关的 `auto`，不改变任何 API 合同。
- 中文界面显示“自动”，英文界面显示“Auto”；摘要同样本地化。
- 自动项上方显示设计系统现有的 Tabler `IconAspectRatio`，形成统一的自适应画幅图形；不再绘制第二套 CSS 图标。
- 自动项与数值比例保持同样的图形—名称两行结构，不再出现空白占位。
- 供应商分段、比例集合和文件格式保持现状，不为某个模型写专用面板。

### 4.3 左侧创建栏：8 个能力直接可见

按当前真实能力直接显示 8 个入口：文本、图像、视频、声音、3D 模型、画板、全景、3D 场景。

- 核心媒体（文本/图像/视频/声音）与空间工具（3D 模型/画板/全景/3D 场景）之间保留一条弱分隔线。
- 左侧栏不显示省略号，也不通过省略号承载创建能力。
- 每个按钮使用现有 Radix `Tooltip`，悬停约 250ms 后在右侧显示“文本节点”等完整名称；键盘聚焦时同样显示。
- 每个按钮提供 `aria-label="添加{名称}"`，tooltip 不是无障碍名称的唯一来源。
- `NodeAddMenu` 继续服务画布右键/空白处创建等上下文入口，不作为左侧栏的平行实现。
- 窄窗口若 8 个按钮超出垂直安全区，工具栏整体允许滚动/自适应间距，不重新引入隐藏省略号。

### 4.4 顶栏：按用户任务分组

正常桌面宽度下所有功能按钮都显示“图标 + 名称”，结构从左到右为：

1. **任务组**：列表/队列语义图标 + “任务” + 待处理数量徽标。
2. **工作辅助组**：“上手 1/4”“浏览器”。
3. **配置组**：“设置”“模型接入”。
4. **主动作组**：“去出片”。

具体约束：

- 任务图标使用 `IconListDetails`，不再使用像进度圆环的 `IconProgress`；它要表达“这里有任务列表”，而不是某一个任务的百分比。
- “任务”入口始终常驻；完全无历史或当前无待处理任务时不显示数字徽标，有任务时显示数量和状态。
- 设置从浏览器所在组移到模型接入旁边，因为二者都是低频配置，浏览器是创作辅助。
- 条件按钮隐藏后不得留下孤立分隔线；分组边界由实际可见子项派生。
- 紧凑宽度下可逐级收起文字，但必须保留一致的 styled tooltip 和 `aria-label`，不能出现一部分有名字、一部分没有名字的混合状态。
- “去出片”继续是顶栏唯一高强调按钮，其他新增文字不提高视觉层级。

### 4.5 改比例：面积近似守恒

设节点切换前用于预览的基准面积为 `A`，目标宽高比为 `r = width / height`：

```text
targetWidth  = sqrt(A * r)
targetHeight = sqrt(A / r)
```

实现约束：

- `A` 从节点当前标准视觉尺寸派生，不硬编码样张的 14.5 万。
- 若目标尺寸超过节点类型或画布允许的最大宽高，按同一比例整体缩放；不得分别裁剪宽高破坏目标比例。
- 若低于最小交互尺寸，同样整体放大到可操作下限。
- `auto` 使用模型档案解析出的默认比例；无法解析时沿用当前稳定默认，不凭供应商名称分支。
- 用户手动缩放过的节点，以其当前视觉面积作为下一次比例切换的基准，避免切比例时突然回到默认大小。

### 4.6 编辑框连接与浮层稳定

比例变化必须在一次状态提交里同时更新节点尺寸和位置，保持与编辑框相连的锚点不动。

编辑框在节点下方时，保持节点**底边中心**不变：

```text
nextX = oldX + (oldWidth - nextWidth) / 2
nextY = oldY + (oldHeight - nextHeight)
```

编辑框因空间不足翻到节点上方时，保持节点**顶边中心**不变：

```text
nextX = oldX + (oldWidth - nextWidth) / 2
nextY = oldY
```

同时满足：

- 编辑框 bounding box 在一次比例面板打开期间保持不变，节点边缘到编辑框的连接间距保持不变。
- 比例触发器保持固定摘要宽度；浮层锚在触发器正上方，打开期间位置不因摘要或节点几何变化而改变。
- 比例选中态可立即变化，浮层不自动关闭，方便连续比较不同画幅。
- 节点尺寸和位置使用同一个 store action/纯函数结果提交，不允许先改尺寸、下一帧再补位置。
- 新锚定算法落地后删除 `freezeShift` 及其只为补偿断口存在的回调链，不保留旧冻结方案。

## 5. 架构与数据流

### 5.1 几何单一入口

在 `nodeSizing.ts`（或同目录的单一纯函数模块）提供通用计算：

```text
resolveAspectPreservingVisualSize(currentSize, targetRatio, bounds)
anchorNodeToComposer(currentRect, nextSize, attachmentSide)
```

数据流：

```text
用户选择比例
→ InlineParameterBar 发出规范化 ratio 值
→ NodeParameterControls 解析目标 ratio 与节点边界
→ 纯函数计算 nextSize + nextPosition
→ generationCanvasStore 单次提交 meta/size/position
→ BaseGenerationNode 与 NodeGenerationComposer 同帧渲染
```

`NodeGenerationComposer` 只把当前连接侧（`top` / `bottom`）告诉参数控制层，不自行修补节点位移。组件不复制几何公式。

### 5.2 控件职责

- `InlineParameterBar`：选项展示、本地化、固定浮层锚点。
- `NodeGenerationComposer`：数量选择与发起生成；不处理比例几何。
- `NodeParameterControls`：把参数变化转成单一的节点更新意图。
- `nodeSizing`：尺寸、边界、锚点的纯计算和不变量。
- `CanvasToolbar`：能力清单与 tooltip，不持有第二份节点类型名称。
- `NomiAppBar` / `TaskCenterButton`：顶栏分组和任务入口语义。

## 6. 国际化、无障碍与视觉约束

- 所有新增可见文字进入 `zh-CN` / `en` i18n：自动、任务、设置、每次生成、1–4 张、8 种节点 tooltip。
- 数量摘要使用插值/复数友好 key，不拼接仅适用于中文的字符串。
- 选择器、比例网格和顶栏按钮支持 Tab 导航、Enter/Space 激活、Escape 关闭、方向键在同组移动（沿用现有 Radix 行为时不重复实现）。
- tooltip、popover 与 badge 全部使用设计 token；不新增 hex 色、任意字号、任意圆角或全局 CSS。
- 光/暗模式必须使用同一 DOM 结构，只有 token 翻转。
- 动画只插值节点几何；遵守 `prefers-reduced-motion`，减少动态时直接完成但仍保持原子锚定。

## 7. 边界与失败处理

- 节点靠近画布边缘时，优先保持编辑框锚点和画幅比例；画布本身可平移，因此不通过缩小节点来“塞回当前视口”。只有节点类型硬边界才触发等比缩放。
- 当前比例已是目标比例时不产生 store 写入，避免历史栈噪音。
- 模型不支持某比例时沿用现有禁用/过滤机制，不显示一个点击后偷偷回退的选项。
- 生成请求进行中，数量选择器禁用但摘要不消失；失败后恢复选择能力。
- 顶栏条件入口为空时由可见子项决定分隔线，不留下空组。
- tooltip portal 不参与画布拖拽命中，悬停名称不得阻挡节点创建按钮。

## 8. 测试与验收

### 8.1 自动化（先红后绿）

1. `nodeSizing`：1:1、21:9、9:16 的输出比例正确，未触边时面积误差在舍入容差内；触边时等比缩放。
2. 锚点：下置编辑框的底边中心、上置编辑框的顶边中心在比例切换前后相等。
3. 原子更新：一次比例选择只产生一次节点几何提交，不经过“尺寸已变、位置未变”的中间态。
4. 数量选择：存在 1、2、3、4；选择 3 后调度恰好 3 个变体；生成中不可改。
5. 自动比例：中文显示“自动”、英文显示“Auto”，图形槽非空，内部提交值仍为 `auto`。
6. 左侧栏：8 个直接按钮均有 tooltip 和 `aria-label`，没有 overflow/ellipsis 创建按钮。
7. 顶栏：任务入口有队列图标、名称与条件徽标；设置与模型接入同组；隐藏条件项后无空分隔线。

### 8.2 真机旅程

1. 打开图像节点比例面板，依次选择 1:1 → 21:9 → 9:16；节点看起来是换画幅而非越切越小。
2. 读取三种状态的 bounding box：视觉面积近似一致；编辑框、比例触发器、已打开浮层的位置完全一致；连接间距无跳变。
3. 把节点移到画布上部触发编辑框翻转，再重复比例切换；顶边连接同样不断开。
4. 数量分别选择 1、2、3、4；确认菜单位置稳定、摘要明确，并用零额度 mock 验证调度数量。
5. 鼠标和键盘依次经过左侧 8 个入口，名称都能出现；无省略号。
6. 在任务有待处理、仅有历史、完全为空三种状态检查顶栏；设置不再与浏览器混组。
7. 分别亲读光/暗、正常/紧凑宽度截图，与获批样张逐项对账。

## 9. 不动项与回滚

- 不改变供应商、模型档案、比例参数值或生成 API。
- 不改变底部编辑框“相对视口保持稳定”的已确认方向，只修复节点与它的空间连接。
- 不新增第二套工具栏、比例面板或节点尺寸系统。
- 不把 8 个左侧入口重新塞进省略号；上下文 `NodeAddMenu` 保持独立用途。
- 不改画布背景、节点内容、主导航步骤或“去出片”的业务行为。
- 实现按可独立回滚的提交组织；回滚代码时对应测试一并回滚，不迁移用户数据。

## 10. 完成定义

只有同时满足以下条件才算完成：

- 本规格的 7 组自动化断言通过。
- 项目七道门禁：filesize、tokens、i18n、lint、typecheck、test、build 全绿。
- Playwright 走完比例、数量、左栏和顶栏真实旅程。
- 人眼读过与获批样张并排的光/暗截图，确认没有缩小感、断口、浮层漂移或无名图标。
- 删除被替代的循环数量逻辑、空自动槽和 `freezeShift` 补偿链，不留下并行实现。
