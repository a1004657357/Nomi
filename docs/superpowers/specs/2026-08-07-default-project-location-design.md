# 新项目默认位置设计规格

日期：2026-08-07
状态：用户已批准（2026-08-07 对话：选择“只影响未来新项目，不迁移旧项目”的推荐方案）

## 目标

让桌面端用户在“设置 → 文件与保存”中选择以后新建 Nomi 项目的默认根目录，解决 Windows 用户无法控制 C 盘占用的问题。

## 用户体验

- 设置项准确命名为“新项目默认位置”，避免暗示会迁移所有 Nomi 数据。
- 路径行始终显示当前生效目录：未自定义时显示系统文档目录下的 `Nomi Projects`，自定义后显示用户选择的目录。
- 用户可执行三个动作：更改目录、在文件管理器中打开、恢复默认。
- 更改目录后，仅之后新建的项目使用新目录；已有项目保持原位并继续从项目注册表打开。
- “生成物自动另存”继续作为独立设置存在，不与项目根目录合并。
- 目录选择取消时不产生修改；目录不可写或不安全时明确返回错误并保留旧设置，不静默回退。

## 架构

### 设置真相源

新增主进程模块 `electron/settings/projectLocationSettings.ts`，把用户选择持久化到固定的 `userData/project-location.json`。该文件不能放进可自定义项目根，否则会形成路径自举问题。

设置结构保持最小：

```ts
type ProjectLocationSettings = {
  projectsRoot: string | null
}
```

读取时对损坏 JSON、非绝对路径和空字符串回退为 `null`；写入使用原子 JSON 写入，避免应用中断留下半截配置。

### 路径解析

`getProjectsRoot()` 保持单一入口，优先级为：

1. `NOMI_PROJECTS_DIR` 环境变量（测试和开发隔离，最高优先级）；
2. 用户设置中的绝对目录；
3. Electron 系统文档目录下的 `Nomi Projects`。

因此所有通过默认创建流程产生的新项目自然使用新根目录，不修改项目注册表或已有项目路径。

### IPC 与渲染层桥

新增独立设置 IPC 注册器，暴露四个异步操作：

- 读取当前目录与是否为自定义目录；
- 选择并保存新的默认目录；
- 恢复系统默认目录；
- 在文件管理器中打开当前目录。

选择目录由主进程使用 Electron 目录选择器完成。保存前验证路径为绝对目录、不是文件、可创建且可写；验证失败时抛出可展示错误。打开目录前确保目录存在。

### 设置界面

复用当前 `SettingsDialog` 的“文件与保存”页和既有 token，不新增顶栏入口或并行设置页。删除“稍后支持”占位标签，将该区改为：

- 标题“新项目默认位置”；
- 当前路径只读行；
- “更改…”主操作；
- “打开文件夹”次操作；
- 自定义状态下出现“恢复默认”；
- 固定说明“仅影响之后新建的项目，已有项目仍保留在原位置”。

操作期间禁用相关按钮；失败时使用现有 toast 展示错误，界面继续显示旧路径。

## 非目标

- 不迁移已有项目或素材。
- 不移动 API 凭证、模型目录、应用配置和下载偏好。
- 不新增 per-project“移动到…”能力。
- 不改变“打开文件夹作为项目”的既有入口。
- 不处理关窗确认或其他旧计划中的独立功能。

## 错误处理

- 设置文件缺失或损坏：使用默认目录，应用正常启动。
- 选择器取消：返回取消状态，设置不变。
- 目录不可写、路径指向文件或创建失败：拒绝保存并返回本地化错误。
- 打开目录失败：保留设置并展示错误，不改变根目录。
- 环境变量存在时：它仍为最高优先级；设置界面显示实际生效路径，但不允许误称用户设置已生效。

## 验收

- 单元测试钉死设置读取/写入/清除、损坏兜底和路径优先级。
- IPC 测试钉死取消不修改、非法目录不修改、有效目录保存和恢复默认。
- 构建后真机走查浅色与暗色设置页。
- 真机选择临时目录后创建新项目，确认项目落在新目录；恢复默认后再次创建，确认回到默认目录；原项目仍能打开。
- 全部项目门禁通过后才能提交并推送。
