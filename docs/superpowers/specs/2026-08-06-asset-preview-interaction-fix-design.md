# 素材库视频封面与预览页素材交互修复设计

日期：2026-08-06
状态：方案 A 已获用户确认，待规格复核后实施

## 1. 真实摩擦与证据

用户在素材库里遇到两个连续摩擦：

1. 视频卡片只显示空白/白条，无法判断是哪段视频。
2. 预览页左侧「素材」里的图片、视频看得到，但单击没有有效结果，拖到时间轴也不被图片轨/视频轨接收。

根因证据：

- `useFilmstrip` 始终用当前打开项目的 ID 抽帧；「全部素材」却包含其他项目的视频。跨项目视频 URL 与当前项目 ID 不匹配，主进程报「源视频不在当前项目素材里」，封面只能退回空占位。
- `AssetLibraryContent` 在预览页仍沿用画布/素材管理语义；卡片单击只改变内部选中态，没有消费动作。
- `TimelineTrack` 只接受素材库的音频拖拽，图片/视频的 `ASSET_LIBRARY_DRAG_MIME` 被忽略。预览页虽然展示三类素材，实际只有音频存在落轨链路。
- 「项目素材」页签的拖拽还会切换成文件夹归类 MIME；在预览页语境中同样无法落轨。

真实布局依据：

- `tests/ux/shots/video-ops/03-after-upload.png`：素材卡片现有尺寸、角标、播放图标和素材库密度。
- `tests/ux/shots/video-ops/06-preview-timeline.png`：预览播放器与图片/视频/音频轨的现有位置。
- `PreviewSourcePanel` 已批准的「镜头」交互：单击追加片尾、拖拽指定落点；本修复让「素材」与它一致，不新增布局或新按钮。

## 2. 方案对比

| 方案 | 用户看到什么 | 代价 |
|---|---|---|
| **A. 语境化主动作（已确认）** | 预览页单击素材直接追加片尾，拖拽到对应轨精确放置；生成页仍拖到画布；视频卡显示真实首帧 | 需要把素材→时间轴从音频专用扩成三类通用链路 |
| B. 单击只放大预览 | 点卡片只看大图/播放，必须拖拽才能入轨 | 仍然让用户学习隐藏拖拽，未解决“点了没效果”的核心摩擦 |
| C. 卡片旁新增「加入时间轴」按钮 | 行为明确，但每张卡多一个按钮 | 面板更挤，增加视觉噪音；同一动作与「镜头」页签不一致 |

采用方案 A。底层逻辑是 effect-first：用户在剪辑页挑素材的目的就是把它放进成片，单击先出结果；需要精排时再拖拽。

## 3. 交互设计

### 3.1 预览页「素材」

| 操作 | 结果 |
|---|---|
| 单击图片 | 追加到图片轨末尾，默认 3 秒 |
| 单击视频 | 探测真实时长后追加到视频轨末尾 |
| 单击音频 | 探测真实时长后追加到音频轨末尾 |
| 拖拽到匹配轨道 | 落到鼠标指向的目标位置；拖拽本身就是精排，不要求额外按键 |
| 拖拽到错误类型轨道 | 不落片，给出已有的人话提示 |
| 键盘 Enter / Space | 与单击同义，追加到对应轨末尾 |

预览语境不承担素材整理：卡片不进入“无后续作用的选中态”，「项目素材」中的卡片也发时间轴素材 MIME，不再发文件夹归类 MIME。素材文件夹仍可用于浏览，但删除/新建文件夹等管理动作保持在生成页素材库完成。

### 3.2 生成页素材库

- 保留现有拖到画布的能力。
- 「项目素材」保留单击选择、批量删除、文件夹归类，双击放大预览。
- 「全部素材」不再产生无后续作用的选中态：单击放大预览，拖拽到画布。
- 不新增按钮、不改变卡片几何、颜色或密度。

### 3.3 视频封面

- 胶片条请求优先使用 `nomi-local://asset/<projectId>/...` URL 自带的所属项目 ID；没有项目型 URL 时才回退当前项目 ID。
- 同一规则位于 `useFilmstrip` 单一入口，自动覆盖素材库瀑布流、素材选择器、预览页镜头封面和时间轴胶片条，避免各处分别猜项目。
- 抽帧失败继续显示诚实占位，不拿其他图片冒充；但不再因跨项目 ID 错配而失败。

## 4. 架构与数据流

### 4.1 素材转时间轴

把现有音频专用链路收敛成一条通用链路：

`AssetRef / AssetLibraryDragPayload`
→ 归一成 `AssetRef`
→ `buildClipFromAssetRef` 生成图片/视频/音频 clip
→ 视频/音频离屏探测真实时长
→ 单击时查对应轨末尾，拖拽时使用鼠标指向的目标落点
→ `addTimelineClipAtFrame`

约束：

- 图片沿用画布节点入轨的 3 秒默认值。
- 视频沿用 5 秒兜底，但真实文件可探测时必须覆盖兜底。
- 音频沿用 10 秒兜底，但真实文件可探测时必须覆盖兜底。
- `sourceNodeId` 继续使用 `asset:<稳定 id>`，不伪造画布节点。
- 删除音频专用的平行实现/命名，所有三类素材共用同一个构建与落轨入口。

### 4.2 素材库使用语境

`AssetLibraryContent` 增加明确的使用语境（画布 / 时间轴），由调用方声明，不根据所在 DOM 猜测：

- 画布语境：拖拽创建画布素材节点；项目页签允许管理选择。
- 时间轴语境：单击追加、拖拽落轨；不启用管理选择。

卡片只接收一个主动作，避免单击、双击相互触发造成重复入轨。

### 4.3 胶片条项目归属

`useFilmstrip` 在排队前计算 `{ videoUrl, projectId, cacheKey }`：

1. URL 能解析出项目 ID → 使用 URL 所属项目。
2. 否则使用显式项目 ID（若调用方提供）。
3. 最后回退当前打开项目。

缓存键继续包含项目 ID 与 URL，跨项目同名文件不会串封面。

## 5. 错误处理

- 无法解析或读取视频：卡片显示现有中性占位，失败状态进入会话缓存，不做无限重试。
- 视频/音频时长探测失败：使用各自默认时长，仍允许入轨。
- 素材 URL 为空或 payload 损坏：拒绝入轨，不创建空 clip。
- 拖到错误轨道：不落片，沿用时间轴现有 warning toast。
- 异步探测期间重复点击：每次用户动作仍是一次明确追加；不引入全局锁或隐藏去重。

## 6. 同类入口检查范围

必须逐项验证：

1. 生成页素材库：全部素材 / 项目素材。
2. 预览页左栏：镜头 / 素材，三类素材的单击与拖拽。
3. 素材选择器与参考图块：视频封面继续走同一 `AssetVideoCover`，点击选择语义不被改写。
4. 时间轴已有 clip：跨项目视频胶片条使用 URL 所属项目，不再白条。
5. 浏览器捕捞素材进入素材库后：仍能预览、拖画布、在预览页入轨。

## 7. 测试与验收

### 自动化（先红后绿）

- 胶片条项目解析：跨项目 `nomi-local` URL 必须选择 URL 内项目，而不是当前项目。
- 素材→clip：图片 3 秒、视频真实时长/5 秒兜底、音频真实时长/10 秒兜底；空 URL/错误类型拒绝。
- 拖拽解析：图片、视频、音频均能归一；轨道类型不匹配被拒绝。
- 追加行为：三类素材找到各自轨道末尾并只追加一次。
- 素材库语境：预览页单击走时间轴主动作，生成页项目素材仍走选择管理。

### 真机旅程

1. 准备两个项目，各放一段画面明显不同的视频；在项目 B 打开「全部素材」，项目 A 的视频也显示正确首帧。
2. 在预览页「素材」中依次单击图片、视频、音频，三条对应轨各新增一个 clip，播放器能看到/听到结果。
3. 把三类素材分别拖到匹配轨，落点反馈与实际位置一致；拖到错误轨不产生 clip。
4. 回生成页：全部素材单击能预览、拖动能建画布节点；项目素材仍可选中并删除/归类。
5. 亲读光/暗模式截图；布局必须与改前相同，只允许视频封面从空占位变成真实画面、点击后时间轴出现结果。

## 8. 不动项与回滚

- 不改素材卡尺寸、网格、筛选器、颜色、播放图标或预览播放器布局。
- 不新增 store，不复制一套“预览专用素材库”。
- 不改项目文件协议和安全边界；只纠正调用方传入的项目归属。
- 不清理用户现有缓存或素材。
- 实现保持单 commit；revert 即恢复旧交互。新增测试随实现一起回滚。
