# 2026-08-06 画布反馈批次根因收口设计

## 背景

用户群在同一条真实创作旅程中反馈七类摩擦：角色图本地上传失效、画布文字在双主题下发虚、连线语义标签不可解释/不可编辑、节点上方 composer 与结果工具条互相遮挡、分组内节点过多时无法拖到远处分组、多张生成结果无法单项管理、个别项目无法创建或打开。

这不是七个互不相干的按钮缺口，而是三条结构链：

1. 画布屏幕空间 UI 没有统一几何与清晰度契约；
2. 生成结果只把“当前主结果”当成素材，历史结果没有完整生命周期；
3. 项目读取失败被压成 `null`，用户只看到“找不到项目”，无法区分缺失、损坏与可恢复备份。

## 已确认事实

- 角色卡上传在 `8a199b85` 已修复：节点外壳只在真实拖动超过阈值后才抢 pointer capture。此次不重写，补最新版回归。
- composer 避让仍查询已不存在的 `.generation-canvas-v2-node__panorama-toolbar`，而共享工具条没有该类名；因此工具条实际高度恒被测成 0。
- `updateEdgeMode`、事件日志与持久化已经存在；缺的是能力约束后的用户入口。
- `GroupItem` 自己持有展开状态，但子节点 `dragstart` 没有通知父组。
- `ImageResultStack` 能切主图，不能删除；`canvasNodeToAssetRef` 只投影 `node.result`，历史结果不进入“项目素材”。
- “全部素材”来自磁盘资产，但当前只预览、不提供删除；直接删文件会留下项目节点中的坏引用。
- 最新 `origin/main` 上项目读写单测 23/23 通过；隔离构建实测“新建空白项目 → 打开工作台”成功、控制台零错误。无法打开不是通用创建链故障，应增强特定记录的诊断与恢复。

## 设计原则

- 不新增第二套画布或素材库；所有入口共用同一份结果与删除语义。
- 关键 UI（composer、工具条、连线标签）使用不透明 token surface 与足够对比度，不在文字承载层使用 backdrop blur。
- 连接标签只展示目标模型能够消费的语义；编辑不会制造静默无效边。
- 删除一张结果只删除该结果，不删除节点；删除最后一张后节点回到待生成状态。
- 磁盘文件移入系统废纸篓；项目记录先去掉引用，文件删除失败只留下可清理孤儿，不制造坏节点。
- 项目恢复必须先保留损坏原件，再从最近一次有效备份恢复。

## 交互规格

### 1. 上传回归

- 短按“上传角色图”必须打开系统文件选择器并把图片写入当前节点。
- 从同一 CTA 长按拖动仍能移动节点，拖动不得误弹文件选择器。

### 2. 清晰度与遮挡

- `FloatingToolbarShell` 暴露稳定的 `data-node-floating-toolbar` 几何契约。
- composer 的视口定位只查询该契约；翻到节点上方时，位置为 `节点上边缘 - 工具条屏幕高度 - 两段间距 - composer 高度`。
- 工具条和提示词优化弹层使用 `bg-nomi-paper`，移除文字承载层的 backdrop blur。
- 优化输入占位文字从 `ink-40` 提升到 `ink-60`。
- 连线标签使用 caption token、至少中等字重与实体描边背景，继续反缩放保持屏幕字号。

### 3. 连线语义编辑

- typed edge 标签变成可点击按钮，内容为“角色 / 风格 / 构图 / 首帧 / 尾帧”。
- 点击后在标签旁打开小菜单；候选模式从完整模式集合中过 `validateReferenceEdge(source, target, mode)`，不支持的模式不出现。
- 选中模式调用现有 `updateEdgeMode`；菜单底部提供“断开连接”。
- `reference` 通用边仍不常驻显示标签，但选中边后可打开同一菜单。
- Esc、点外与选择完成都会关闭菜单；键盘 Enter/Space 可用。

### 4. 分组拖动

- 从组内节点开始拖动时，来源组立即折叠。
- 拖到折叠目标组上停留 450ms 后自动展开；离开或结束拖动取消计时。
- 组本身的拖动排序不触发节点来源折叠逻辑。

### 5. 多结果生命周期

- `result + history` 先按 `id || url` 去重，再全部投影为独立 `AssetRef`。
- 当前主结果保持在首位；每个素材 id 由 `nodeId:resultKey` 组成，`ownerNodeId` 与 `ownerResultId` 可追溯。
- 结果堆栈中每张非主图同时显示“设为主图”和删除按钮。
- 删除非主结果：从 history 移除该项；主结果不变。
- 删除主结果：自动提升剩余结果中最新一项为主结果；若无剩余，清空 `result/history` 并将节点设为 `idle`。
- “项目素材”显示当前画布全部结果，而非每节点仅一张。
- “全部素材”卡片提供独立删除按钮，不改变卡片主点击“预览”的语义。
- 删除跨项目磁盘素材时：若有 `ownerNodeId`，先读取对应项目并移除匹配 URL/路径的结果，再保存记录；随后把文件及 `.meta` 移入废纸篓。

### 6. 项目诊断与恢复

- 主进程新增只读诊断：`ok / missing / corrupt / id_mismatch`，同时报告最近一次备份是否有效。
- 每次成功保存 workspace manifest 前，将旧的有效 manifest 原子写入 `.nomi/project.backup.json`。
- 恢复时先把损坏 manifest 复制为带时间戳的 `.corrupt-*.json`，再用有效备份覆盖并重新读取。
- renderer 在 `hydrateProject` 返回 null 或抛错时调用诊断：
  - 有有效备份：弹确认“从最近备份恢复”；成功后重新 hydrate。
  - 无有效备份：明确说明是记录损坏或目录缺失，并提供打开项目文件夹入口。
- 正常新建/打开流程不增加额外弹窗。

## 不动项

- 不改变生成模型、生成计费、结果产生顺序。
- 不把节点 UI 全部迁到独立 portal，不重写画布坐标系统。
- 不创建新的全局素材数据库；沿用项目 manifest + workspace assets。
- 不改变用户已拍板的比例切换“底边固定、视觉面积保持”行为。

## 验收

- 所有纯逻辑先有失败测试：工具条 clearance、有效边模式、拖动 disclosure、结果提升/删除、素材投影、项目诊断/恢复。
- 角色上传既能点又能拖。
- 浅色/深色各截图：优化弹层与连线标签清楚；composer、工具条、结果卡无相交。
- 生成 3 张图：设主图、删非主、删主、项目素材、全部素材行为一致。
- 构造损坏 manifest + 有效 backup：能恢复；无 backup：明确诊断且不覆盖原件。
- 全门通过后与获批样张逐项对账。
