# 生成画布选择优先手势与操作帮助设计

> ⛔ **「选择优先」这一条已于 2026-08-08 被用户真机推翻**：画布主导作用是看图，平移才是高频动作。
> 现行手势契约见 [docs/plan/2026-08-08-canvas-drag-pan-and-quiet-render.md](../../plan/2026-08-08-canvas-drag-pan-and-quiet-render.md)。
> 本文其余部分（操作帮助面板、平移和弦不打断连线、纯模型仲裁）仍然有效。

日期：2026-08-07  
状态：交互方向与对比样张已获用户确认，待书面规格复核后实施

## 1. 目标与真实摩擦

本设计只处理生成画布的键盘、鼠标和触控板操作，不改变其他页面或其他画布。

当前最直接的摩擦是：用户在空白处按住左键拖动时会平移画布；要框选多个节点，必须额外按住 `Shift`。这让高频批量选择持续支付修饰键成本，而平移已经同时拥有 Space、鼠标中键、鼠标右键和触控板入口。

反馈雷达还揭示了两项同类问题：

1. 鼠标用户明确反感“必须按修饰键才能滚轮缩放”，更偏好滚轮直接缩放。
2. 用户在拖拽连线时希望用右键继续平移画布；当前 `beginPan` 会取消正在进行的连线，导致远距离连接中断。

界面上还有两项辨识问题：

- 画布操作提示长期占据界面，但日常熟练后没有持续行动价值。
- 左下角整理、小地图、连线显示等纯图标按钮缺少统一的悬浮名称，用户必须逐个尝试。

底层判断：把唯一自然的框选入口让给平移，是入口分配错误。平移有多条等价路径，框选没有；帮助信息应随取随用，不应长期占位。

## 2. 实证与现状

### 2.1 用户反馈

- 2026-07-31 微信反馈：要求修饰键才能缩放“很痛苦”，滚轮直接缩放更符合鼠标习惯。
- 2026-07-31 微信反馈：左键拖连线时，希望右键拖动画布继续寻找目标。
- 本轮用户现场反馈：单击后不能直接拖框选、必须加 `Shift`，操作麻烦。

### 2.2 竞品实查

TapNow 当前官方文档明确说明：

- 空白左键拖动开始框选，不移动画布。
- 鼠标可用滚轮滚动画布，也可用中键或右键拖动画布；触控板用双指滑动。
- 鼠标按 `⌘` / `Ctrl` 加滚轮缩放，触控板捏合缩放；`Shift + 单击`追加节点。

官方依据：

- <https://docs.tapnow.ai/zh/docs/canvas/explore-the-canvas>
- <https://docs.tapnow.ai/zh/docs/account/use-shortcuts>

LibTV 的真实项目和当前前端实现共同表明：

- 默认 `V` 选择态下，空白左拖直接框选。
- Space + 左拖、鼠标中键和触控板用于临时平移。
- `H` 可进入抓手模式，左拖改为平移。
- 底部键盘图标打开完整快捷键面板。

Nomi 不照抄两家的全部键位：TapNow 的 `⌘ Space` 容易与 macOS 系统搜索冲突，LibTV 的 V/H 常驻工具模式又引入了额外状态。Nomi 只采纳双方一致且能解决真实摩擦的“选择优先”语义。

### 2.3 当前代码根因

- `useCanvasPointerInteractions.ts` 把空白左拖直接路由到平移，把 `Shift + 左拖`路由到框选。
- `useMarqueeSelection.ts` 以 Shift 为启动前提，并把框选固定为追加选择，缺少“普通框选替换、Shift 框选追加”的标准语义。
- `useCanvasViewportGestures.ts` 的 `beginPan` 在存在 `pendingConnectionSourceId` 时调用 `cancelConnection()`，使连线与平移互斥。
- `CanvasGestureHint.tsx` 长期渲染操作提示；左下角 `CanvasNavigationStack` / `CanvasToolbar` 中的图标按钮没有统一的 styled tooltip。
- `canvasGesturePreference.ts` 已有鼠标“滚轮缩放”和触控板“滚动画布 / 修饰键缩放”两种方案，本设计不再创建第三套偏好。

## 3. 方案取舍

| 方案 | 用户看到什么 | 代价与判断 |
|---|---|---|
| **A. 选择优先，无工具模式（采用）** | 空白左拖直接框选；Space / 中键 / 右键 / 双指平移 | 高频框选零修饰；复用已有平移入口；不新增状态 |
| B. 保留当前平移优先 | 空白左拖平移；Shift + 左拖框选 | 第一次平移直觉，但框选持续付修饰键成本，已有平移入口被重复占用 |
| C. V/H 选择与抓手工具 | 左拖行为由常驻模式决定 | 能力显式，但用户要记当前模式，界面多一组常驻按钮 |

采用 A。真正的取舍不是“框选还是平移”，而是“把零修饰键优先给哪一个动作”。平移已有四条路径，因此零修饰键应给框选。

## 4. 最终交互设计

### 4.1 选择

| 操作 | 结果 |
|---|---|
| 单击节点 | 只选中该节点 |
| `Shift + 单击`节点 | 在当前选择中追加或移除该节点，沿用现有多选语义 |
| 空白左键拖动 | 直接出现框选区域；结束时以框内节点替换当前选择 |
| `Shift + 空白左键拖动` | 在当前选择上追加框内节点，不移除已选节点 |
| 空白单击 | 清空选择，不移动画布 |
| `Escape` | 取消正在进行的框选；没有框选时沿用现有退出 / 取消优先级 |

约束：

- 框选超过统一拖动阈值后才成立，小范围手抖仍按空白单击处理。
- 框选只命中可选择、可见的顶层节点；组内子节点继续遵守现有组选择规则。
- 框选不新增用户设置，不允许同时保留“左拖平移”和“左拖框选”两套可选世界。

### 4.2 平移

| 输入 | 结果 |
|---|---|
| `Space + 左键拖动` | 临时平移画布 |
| 鼠标中键拖动 | 平移画布 |
| 鼠标右键拖动 | 平移画布 |
| 触控板双指滑动 | 在触控板方案中平移画布 |

具体规则：

- 不新增 V/H 工具模式，也不新增常驻抓手按钮。
- Space、中键和右键的平移语义在空白、节点上方和连线过程中保持一致；只有文本输入、节点内部可滚动区域等现有排除区继续优先处理自身输入。
- 右键移动超过拖动阈值后，不再弹出画布右键菜单；右键按下再原位松开仍打开原有菜单。
- `Escape` 是取消连线的显式入口；开始平移本身不得取消连线。

### 4.3 连线中移动画布

连线和平移必须成为可组合动作，而不是互斥状态。

```text
左键从端口拉出连线
→ 保留 pendingConnectionSourceId 与当前指针目标
→ 用户按 Space / 中键 / 右键拖动画布
→ 只更新 viewport，不清空 pending connection
→ 平移结束后继续跟随左键指针
→ 左键在目标端口释放，完成连接
```

实现约束：

- `beginPan` 不再调用 `cancelConnection()`。
- 平移期间连接预览线继续存在，并随 viewport 重新计算；不冻结在旧屏幕坐标。
- 左键连接指针的捕获权不能被右键或中键平移永久抢走。
- 只有用户按 `Escape`、在无效位置结束连接或触发现有显式取消条件时，连接才取消。

### 4.4 缩放

保留现有两种输入偏好，不倒退、不扩散：

- 默认“鼠标方案”：滚轮直接缩放，指针位置为缩放中心。
- “触控板方案”：双指滑动画布，捏合缩放；需要鼠标滚轮缩放时沿用现有修饰键规则。
- 画布设置只保留这一个输入方案切换，不为框选 / 平移新增设置。
- `⌘` / `Ctrl` + `+`、`−`、`0` 等现有键盘缩放若已支持则继续保留；不为了模仿竞品新增系统冲突键位。

### 4.5 操作帮助入口

- 删除画布中长期占位的 `CanvasGestureHint` 展示，不保留并行提示条。
- 在左下角画布导航控件中增加一个键盘图标按钮；图标使用现有设计系统 / Tabler 图标，不绘制自定义 CSS 图标。
- 按钮 tooltip 显示“画布操作”；点击后在按钮上方打开紧凑操作帮助浮层。
- 浮层按“选择 / 移动画布 / 缩放 / 节点操作”分组，只显示当前真实支持的操作；Mac / Windows 键位由平台派生。
- 当前输入方案不同，只切换缩放 / 双指相关文案，不复制两份完整面板。
- 浮层支持点击外部和 `Escape` 关闭，不抢占画布快捷键，不进入项目持久状态。

### 4.6 左下角图标名称

- 整理画布、小地图、连线显示 / 隐藏、缩放、画布操作等纯图标按钮统一使用项目现有 Radix `Tooltip`。
- 悬停约 250ms 后显示“名称 + 快捷键（若存在）”；键盘聚焦时同样显示。
- 每个按钮必须有独立 `aria-label`，tooltip 不是唯一无障碍名称。
- tooltip portal 不参与画布拖拽命中，不应让指针经过时误触平移、框选或滚轮缩放。

## 5. 手势仲裁与组件边界

### 5.1 单一仲裁顺序

所有指针入口遵守同一优先级，避免每个 hook 各自猜测：

```text
文本输入 / 节点内部控件 / resize handle
→ Space / 中键 / 右键显式平移（允许与 pending connection 并存）
→ 节点端口连线与连接指针更新
→ 节点拖动
→ 空白左键框选
→ 空白单击清空选择
```

关键不变量：

- “平移是否被请求”由按键 / 鼠标按钮决定，不再由“是不是空白左拖”决定。
- 没有显式平移输入时，端口左键先启动 / 更新连接；连接已经开始后，Space、中键或右键只临时接管 viewport 移动，松开后继续更新同一条连接。
- 连接状态可以与平移状态并存；节点拖动、resize 等仍保持互斥。
- 任一操作结束或窗口失焦后，pointer capture、临时按键态、上下文菜单抑制态都必须清理。

### 5.2 模块职责

- `useCanvasPointerInteractions`：只做事件分类与优先级仲裁，不计算 viewport 或框选几何。
- `useCanvasViewportGestures`：处理 Space / 中键 / 右键 / 双指平移与缩放；不得拥有“取消连接”的副作用。
- `useMarqueeSelection`：处理框选阈值、矩形、命中和替换 / 追加模式；不再要求 Shift 才能启动。
- `useDragToConnect`：拥有连接开始、完成和显式取消；暴露与 viewport 变化兼容的连接状态。
- `CanvasControlsHelpPopover`（新）：只展示从真实键位配置派生的帮助内容。
- `CanvasNavigationStack` / `CanvasToolbar`：承载键盘图标与统一 tooltip，不复制手势业务逻辑。

不新建全局 store。框选 / 平移过程态继续留在对应 hook；只有现有项目需要持久化的 viewport 和已存在的输入方案偏好进入 store / local storage。

## 6. 与既有规格的边界

本规格与 `2026-08-06-canvas-control-clarity-design.md` 互补，不互相替代：

- 既有规格继续负责生成数量、比例连续性、左侧 8 个创建入口和应用顶栏分组。
- 本规格只负责生成画布的选择、平移、缩放、连线中移动、操作帮助和左下角 tooltip。
- 两份规格共享同一 Radix Tooltip 和 i18n 纪律，但不得各自实现一套 tooltip 封装。
- 若实现时间重叠，先提取 / 复用现有 styled tooltip 组件，再分别落到左侧创建栏和左下角导航，不复制样式。

## 7. 国际化、无障碍与视觉约束

- 所有新增可见文字进入 `zh-CN` / `en`：画布操作、选择、移动画布、缩放、整理画布、小地图、显示 / 隐藏连线及各条说明。
- 键位标签由平台派生：Mac 显示 `⌘` / `⌥`，Windows 显示 `Ctrl` / `Alt`；业务逻辑使用统一动作标识，不把展示字符串当快捷键判断。
- 键盘按钮与帮助浮层支持 Tab、Enter / Space、Escape 和焦点返回。
- tooltip、popover、边框、阴影、字号、圆角只使用设计 token 和现有组件，不新增全局 CSS。
- 光 / 暗模式使用同一 DOM 结构；只由 token 翻转。
- 框选矩形沿用现有选中强调色，不新增第二种选择视觉语言。

## 8. 边界与失败处理

- 指针在输入框、textarea、contenteditable、下拉菜单、节点内部滚动区时，画布快捷键不得抢输入。
- Space 按下时若焦点在文本输入区，插入空格；只有画布拥有交互焦点时才进入临时平移。
- 右键拖动中途离开窗口或窗口失焦，必须结束平移并清理右键菜单抑制态；不得让后续右键永远失效。
- 框选从右下向左上等任意方向都要正确；缩放不为 100% 时命中以 flow 坐标计算。
- 框选矩形覆盖组时沿用当前组选中边界，不递归选中不可见子节点。
- 连线中平移失败或 pointer capture 丢失时，连接保持到现有超时 / 显式取消条件；不因一次 viewport 事件立即销毁。
- 触控板捏合和双指滚动继续由现有输入方案仲裁，不能同时触发缩放与平移。

## 9. 测试与验收

### 9.1 自动化（先红后绿）

1. 空白左拖超过阈值后启动框选，无需 Shift；viewport 不变化。
2. 普通框选替换旧选择；`Shift + 框选`追加旧选择；空白单击清空选择。
3. Space + 左拖、中键拖、右键拖都会平移；都不会生成框选矩形。
4. 右键原位点击打开上下文菜单；右键拖动超过阈值后不打开菜单。
5. 连接进行时以 Space、中键或右键平移，`pendingConnectionSourceId` 保持，连接预览仍存在；到达目标后能完成连接。
6. `Escape` 显式取消连接；开始平移不调用 `cancelConnection()`。
7. 鼠标方案滚轮直接缩放；触控板方案双指平移、捏合缩放；两种方案没有第三份分支。
8. 删除常驻 gesture hint；键盘图标能打开 / 关闭帮助浮层，Mac / Windows 文案正确。
9. 左下角所有纯图标按钮均有 Radix tooltip 和 `aria-label`，tooltip 不阻挡画布事件。
10. 窗口失焦 / pointer cancel 后，marquee、pan、Space 和右键菜单抑制状态全部清零。

### 9.2 真机旅程

1. 在有多个节点的生成画布上直接空白左拖，框选两个节点；不按 Shift 也成功，画布位置不动。
2. 先选一个节点，再普通框选另一组，确认旧选择被替换；按 Shift 重做，确认变为追加。
3. 分别使用 Space + 左拖、中键、右键、触控板双指平移；操作结束后点击 / 框选立即恢复正常。
4. 从节点端口拉出连线，保持左键的同时右键平移到远处节点并完成连接；连接不闪断、不取消。
5. 在鼠标与触控板方案间切换，验证滚轮 / 双指 / 捏合行为与帮助浮层文案一致。
6. 悬停和键盘聚焦左下角每个图标，名称与快捷键都出现；点击键盘图标打开总表。
7. 亲读光 / 暗模式、Mac / Windows 分支截图，与获批样张逐项对账。

## 10. 不动项与回滚

- 不改生成节点业务、节点类型、模型参数、项目数据格式或导出流程。
- 不改其他画布或时间线的手势。
- 不新增 V/H 工具模式、抓手常驻按钮或新的左拖语义设置。
- 不删除现有鼠标 / 触控板输入方案，只修正帮助文案和手势冲突。
- 不把操作帮助塞进设置页；它仍在画布现场可达。
- 新实现落地时同 commit 删除被替代的 Shift-only 框选入口、常驻 `CanvasGestureHint` 和 `beginPan` 中取消连接的旧副作用，不保留 fallback。
- 实现按手势核心与帮助 UI 可独立回滚的提交组织；回滚代码时对应测试一起回滚，不迁移用户数据。

## 11. 完成定义

只有同时满足以下条件才算完成：

- 10 组自动化断言通过，且现有画布测试无回归。
- 项目七道门禁：filesize、tokens、i18n、lint、typecheck、test、build 全绿。
- Playwright 走完框选、四种平移、两种选择合并模式、两种输入方案和连线中平移旅程。
- 人眼读过同构建、同入口的光 / 暗截图，确认框选不平移、连线不闪断、帮助不常驻、图标都有名字。
- 与获批对比样张逐项一致，不引入 V/H 模式或第三套手势偏好。
- 被替代实现已经删除，没有并行版、fallback 或遗留 TODO。
