# 结构评审：`electron/video` 这一层（2026-09-17 复查）

> **为什么写这份**：#802 列车收尾把 #782 的主体（付费出口一律带 `grantId`）并回集成分支，
> `check:symptom-cluster` 随之数出 `electron/video` 在 09-10 → 09-15 的 7 天里有三份根因合同：
> `2026-09-10-shot-table-async-write-ownership`、`2026-09-12-run-task-grant-class`、
> `2026-09-15-shot-seconds-precision`。R21 的判据是：第三份合同是「这一层的结构不对」最便宜的
> 证据，不是再修一次的理由。这份是 [`2026-09-12-electron-video-structural-review.md`](2026-09-12-electron-video-structural-review.md)
> 的复查——那份看的是 09-07/09-10/09-12 三份，这次窗口换成 09-10/09-12/09-15，新进来的是精度那份。

## 新进来的那一份是不是同一个形状

| 日期 | 合同 | 这一层的什么性质让它发生 |
|---|---|---|
| 09-10 | shot-table-async-write-ownership | 编排函数**自己决定写回哪里**，写回的世代/归属不在参数里 |
| 09-12 | run-task-grant-class | 编排函数**自己决定发什么请求**，花钱授权不在参数里 |
| 09-15 | shot-seconds-precision | 「镜头时间精确到几位」这份领域约束**没有 owner**，每个读者各自现发明一套 |

前两份是 09-12 那份评审已经判过的「横切关切体内自取」。09-15 这份**不是**同一个面：
它缺的不是「参数没传」，而是**这份数据的领域约束根本没有归属层**——`buildShotBoundaries`
产出镜头区间，却没有任何一层被指定为「时间精度的 owner」，于是丢贴边切点用 `0.01`、
时长显示用 `toFixed(2)`、提示词用 `toFixed(1)`，三处互不相等且都不是真正显示给用户的那处。

所以这一层现在暴露的是**两条**性质，不是一条：

1. **横切关切在体内自取**（09-10 / 09-12）——已由「必填参数 + 硬零门岗」收口，防线见 09-12 那份的三条。
2. **数据的领域约束没有归属层**（09-15）——09-15 的修法已经立了唯一真相源 `electron/video/shotTime.ts`
   （0.1s 格子），并在**产出边界**（`buildShotBoundaries`）与**落库读入口**
   （`shotTableFactRowSchema.transform()`）两道边界收口，显示层另加响的检测器禁止再写 `toFixed`。

## 判断：仍然不重构这一层，但把第二条性质写成规矩

理由与 09-12 一致：行数不是根因，把长编排函数拆成六个短函数，横切关切照样能在任一体内自取、
领域约束照样能没有 owner。真正管用的是**让缺失当场变红**：

- 横切关切 → 必填参数（编译器）+ `check:run-task-grant` / `check:outbound-policy`（硬零门岗）。
- 领域约束（精度、单位、坐标系这一类）→ **产出边界归一 + 读入口归一 + 显示层检测器**，
  三点齐了，新读者漏一次会被检测器当场抓住，而不是等用户看见 `0.0333333s`。

**本轮收尾正是按这条规矩做的减法**：#782 曾经带了第二套精度判据（「最短镜头长度按源片 fps 派生」
的 `minShotSeconds`），它和已合入 main 的 #795「量化到 0.1s 格子」解决的是同一个症状
（碎镜 / 贴边切点）。两条判据同时在树上就是并行版（P1），而且二者的边界还不重合——
09-17 按用户拍板删掉 fps 那一半，精度这件事在 `electron/video` 里只剩 `shotTime.ts` 一个 owner。

## 这一层现在该守的四条（在 09-12 三条之上加第 4 条）

1. 横切关切一律参数化、且必填（花钱授权 / 写回世代 / 出站目的地）。
2. 新付费出口过 `check:run-task-grant`；新出站路过 `check:outbound-policy`；新 IPC 面 `assertTrustedSender`。
3. `catch` 不许吞到只剩一个空值——失败带着原话上抛或落进 `failureReason`。
4. **数字有单位和精度就必须有 owner**：精度只许在 `shotTime.ts` 这类真相源里定义，
   在产出边界与读入口各归一一次；任何新的 `toFixed` / 魔法阈值都按已有检测器当场拦。
   判一条「要不要再发明一个常数」的最短问法：**这条约束属于哪一层？那一层有没有测试？**

## 复查点

下次 `electron/video` 再进第三份合同时，先回来看第 2 与第 4 条的门岗有没有被绕过或被加了基线。
若四条都守着而事故仍复发，那时「拆这一层」才有据可依。
