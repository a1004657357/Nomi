# Nomi v0.20.0 pre-release audit

Date: 2026-08-16 to 2026-08-17
Range: `v0.19.0..1d3b98e23962c33da9556ba76d8d362fc091299a`, plus release-branch hardening
Scope: 185 merged commits, including PRs #84, #87, #88, #89, and #90.

## Verdict

The merged product changes and release hardening have no unresolved P0 finding in local review. Stable promotion remains blocked until the release commit passes repository/PR gates, the release-critical journeys, packaged-media audits, packaged MCP smokes, the v0.19.0 upgrade check, and the immutable RC workflow.

## Audit dimensions

### Product and frontend

- Reviewed the clip editing actions, drag/trim behavior, visible-media scheduling, settings update UI, and direct-download site contract.
- PR #87's clip journey performs real local FFmpeg exports; it is now a mandatory RC journey.
- PR #88's visible-media behavior is covered by unit tests and a focused S-scale Electron performance journey in RC.
- Batch agent node creation now requests a single canvas fit, and the floating composer pans by the minimum amount needed to keep its controls and the bottom dock visible.
- J1 and J2 passed against the real configured assistant model with milestone screenshots reviewed for node framing, composer controls, references, generation parameters, and the batch action.

### Backend, persistence, and migration

- The catalog schema advances from version 8 to 9. Legacy custom-call named configuration moves from plaintext vendor metadata into the existing safeStorage-backed credential record; migration defers without rewriting when safeStorage is unavailable.
- Renderer-facing custom configuration exposes only `{name, hasValue}`. OpenAI-compatible calls omit `Authorization` entirely when no key is configured.
- Existing project hydration still covers media URL/category migrations, v5.1-to-v6.0 migration, asset-kind normalization, and shot-index backfill.
- Production-run persistence, recovery, cancellation, gate decisions, and MCP projections are exercised by the production MCP journey, including a valid final MP4.
- A final v0.19.0 user-data upgrade check remains part of RC artifact acceptance because source-level migration tests cannot prove installer behavior.

### Desktop and platform packaging

- macOS arm64/x64 DMG and ZIP plus Windows x64 NSIS targets are present in the release configuration.
- These are the only supported release targets. macOS artifacts are unsigned and unnotarized; Windows artifacts do not carry an Authenticode signature.
- The packaged-media audit previously rejected foreign packages but did not prove the required executable or its target architecture. The release branch now requires exact FFmpeg/FFprobe paths, Mach-O/PE headers, matching arm64/x64 machine types, and executable bits on macOS.
- The RC workflow now runs the packaged media audit on all three targets and launches the packaged MCP journey on macOS arm64 and Windows x64.
- Stable promotion requires the fixed RC workflow path/ID, `workflow_dispatch` event, repository, run attempt, and head SHA. A final manifest binds every packaged artifact size and SHA-256 after both platform jobs complete.

### Updater and public download

- Versioned assets and stable aliases agree with the website download contract: Apple Silicon DMG, Intel DMG, and Windows setup EXE.
- macOS unsigned builds intentionally open the architecture-specific website download route rather than attempting in-app replacement.
- Stable promotion requires all five valid gzip blockmaps, validates updater metadata, uploads to a draft Release, verifies the remote asset set/size/digest, and only then publishes it.

### Test architecture

- The default CI journeys cover first success and edit/export UI mounting, but not the highest-risk changes in this release.
- RC validation now additionally runs clip editing/export, production MCP/recovery, and visible-media scheduling scenarios.
- Packaged MCP startup is checked from an isolated working directory so repository files cannot mask missing package assets.

## Resolved findings

1. **P0: release version mismatch.** `package.json` is updated from `0.19.0` to `0.20.0`, with changelog and release notes.
2. **P1: packaged media audit accepted an empty target set.** The audit now requires one non-empty target package for both FFmpeg and FFprobe, with regression tests.
3. **P1: Windows package paths were built but not exercised.** Windows RC now audits media binaries and runs the packaged MCP smoke.
4. **P1: merged feature journeys were absent from RC.** Clip, production MCP, and focused canvas media scenarios are now release gates.
5. **P1: `main` Quality Gate failed after PR #84.** The guarded `AboutSection.tsx` hash is updated to the independently verified post-merge source hash.
6. **P0: custom-call named values crossed the renderer/persistence boundary in plaintext.** Schema v9 stores them in the encrypted credential record and returns presence-only metadata to the renderer.
7. **P1: keyless OpenAI-compatible calls sent an empty bearer header.** Authorization is now conditional on a non-empty configured key.
8. **P1: batch-created nodes and the composer could land outside the visible canvas.** The shared tool executor now fits batch results and composer placement is viewport constrained.
9. **P0: RC provenance trusted a mutable workflow name and self-asserted commit only.** Promotion now verifies the fixed workflow path/ID, dispatch event, repository, run attempt, API-reported head SHA, and final artifact digests.
10. **P1: public release creation could leave partial assets.** Stable promotion now uploads into a reusable draft, checks the exact remote asset set, size, and SHA-256 digest, then publishes atomically.
11. **P1: macOS x64 media packages were absent after a host-only install.** The macOS RC job installs all optional architectures with `pnpm install --force`, then audits both packaged targets.
12. **P1: custom configuration could still cross the renderer in an export.** Renderer-facing exports no longer include custom secret values, and deferred safeStorage migration retries in the same session.
13. **P2: updater blockmaps and curated release notes were optional.** All five blockmaps are required and validated, and the stable Release body now comes from `docs/release-notes/v0.20.0.md`.
