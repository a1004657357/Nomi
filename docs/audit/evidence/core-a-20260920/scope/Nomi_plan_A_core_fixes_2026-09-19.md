### 1.5 开工与证据纪律

先读当前 `AGENTS.md` 及其指向的架构、工程／根因／设计规则；生成文件不手改。以下只读命令在确认的仓库内执行，不替代保护 dirty 树的程序：

```bash
git status --short
git branch --show-current
git rev-parse HEAD
git rev-parse 'HEAD^{tree}'
git worktree list --porcelain
git diff --name-status
git diff --cached --name-status
git ls-files --others --exclude-standard
```

远端刷新、干净集成分支和 worktree 建立使用仓库实际的 `delivery:preflight` 及现行流程；不在脏树上盲目 rebase。每项 delta 记录来源树、base、staged/unstaged/untracked、patch/content hash、文件、任务归属、依赖、验证、目标提交。共享 reducer、repository、类型、消息契约、生成适配器由一位集成负责人维护。

文件路径是调查入口；实施前核实当前符号与真实 `file:line`。计划中描述的语义字段不等于现成 API，不允许凭任务书虚构调用方或 i18n key。新类型必须在共享契约内定义并贯穿生产调用、IPC/MCP 投影及测试。

每项循环为：定位共享根因及门表 → 写能在旧实现上失败的用例 → 实际运行并记录目标失败 → 最小完整实现 → 重跑与邻接回归 → 独立提交。不能让“依赖未装／接口不存在”的红灯冒充目标缺陷红测。

只对实际需要的命令加一层锁；先查当前聚合脚本是否内置锁，不嵌套申请非重入锁，不杀其他树的测试。最终 scoped 提交之后让 `review:branch` 审到完整提交差异；修复 findings 后更新提交、验证和收据，确认 tree 一致才推送。Ponytail 不替代付款、迁移和取消正确性审查。

证据至少含：任务／用例 ID、执行入口、平台、commit/tree、dirty 状态及差异摘要、锁文件 hash、包 hash、夹具匿名版本、真实／模拟模式、命令、退出码、日志和未验证范围。仅 HEAD 不能标识不同 dirty 构建。原始日志／profile本地保留；PR 只放脱敏索引、相对路径和 hash。来源里的 `/tmp` 或聊天临时目录不得成为唯一证据。

**核心修复 PR 可交付：** K0–K7 的代码和依赖已明确，相关 C 用例有真实结果，未完成资源项显式列出，最终树已按仓库要求验证与评审，可以推送任务分支开 scoped PR。不以开 PR 宣称全部软件已解决。

**候选包可建议进入发布审批：** 上述代码已进入指定候选树并打包；本次启用范围内数据安全、付款安全、身份/隐私和保存重开无阻断；适用目标平台真实安装包及核心旅途通过；残余未验证能力没有被无根据宣传。若任何启用路径仍可能误删、误取消、未授权提交或破坏旧数据，结论为不放行。实际 merge/发布仍需用户另行授权。

不能因为完整版还有14条旅程未全验就机械否决一个范围明确的小修复PR；也不能因为核心PR通过就把完整版剩余缺陷宣布解决。
