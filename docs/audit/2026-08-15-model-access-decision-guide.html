01 / Verdict

一句话结论

归档不是“最新完整修复版”。它有值得移植的 ComfyUI 能力，但模型接入和设置页面部分会回退当前 main 已经完成的修复。

不要整包合入

会带回旧问题

归档仍强制 Key、抓不到文档就失败、只保留验证通过 mapping，并保留独立浮卡入口。

可以移植但要重做

ComfyUI 专用能力

H3、Qwen、空 loader 清理和参数持久化思路正确，但固定节点编号和公共 transformer 绕行需要加固。

当前 main 仍要补

无 Key 正式运行

UI 可以保存免鉴权端点，但文本运行时仍要求非空 apiKey，验证和 Agent 调用会在最后一步失败。

先讲清楚：什么叫“必须修”，什么叫“取舍”

不可破坏的底线

结果只有对或错

页面说“保存成功”，正式调用就必须真的能用；密钥不能出现在普通文件和日志里；验证任务必须结束；轮询频率必须有上限。这些都能写成自动测试，不依赖个人审美。

判断方法：只要能构造一个正常用户输入，让系统稳定地失败、泄密、永远不结束或无限请求，它就是确定的缺陷。
需要权衡的工程选择

两条路都可能正确

例如按节点类型查找更耐工作流变化，固定节点编号却更容易兼容旧模板；保留贡献者的领域逻辑能省时间，直接覆盖当前 main 又会带回旧问题。

判断方法：先守住“能用、安全、可结束”三条底线，再比较兼容性、维护成本、实现速度和未来扩展。

最重要的区别：“必须修”说的是结果不能错；“取舍”说的是达到正确结果可以走不同路线。具体修法可以讨论，但正确性、安全性和任务终态不能拿来交换。

02 / The system

“接入模型”到底经过什么

把 Nomi 想成一个翻译和调度系统：用户说“我要用这个模型”，程序要把它翻译成正确的网址、认证方式、请求格式和可执行能力。

用户填 Base URL、Key、模型名。
也可能是局域网 HTTP、没有 Key。
→
设置 / 向导收集输入，拉取模型列表，展示验证进度。
这里决定“能不能继续操作”。
→
Provider Adapter把一家供应商翻译成 Nomi 能理解的统一模型、能力和调用方式。
→
真实请求验证或正式生成。
最终必须发到正确的 /models、/chat/completions、/prompt 等路径。
任何一环失败都要可解释、可取消文档是帮助，不应是准入门槛验证失败也要保留用户控制权

把 Provider Adapter 拆开看：它不是模型，而是“兼容翻译层”

输入：用户和供应商给了什么
  • 基础地址、是否需要密码、额外请求头
  • 供应商返回的模型名单与模型类型
  • 可选的接口文档；没有文档也必须继续
→
Adapter：Nomi 在中间翻译什么
  • 判断这家接口使用哪一种请求规则
  • 把“聊天、图片、视频”翻成真实调用路径
  • 生成可执行 mapping，并逐项真实验证
  • 把成功、失败、未验证原因写回模型目录
→
输出：运行时以后拿什么工作
  • 一条明确的供应商与模型身份
  • 每种能力对应的真实请求路线
  • 可以展示和恢复的验证状态

它的边界：设置页面只负责收集和展示，Adapter 负责翻译，运行时负责真正发请求。三层必须共享同一套地址、认证和模型身份，否则就会出现“页面保存成功，正式聊天失败”。

03 / Non-negotiable

肯定要修的事

这里的判断标准是：不修就会让用户无法完成基本任务、造成数据/凭据风险，或者再次出现“永远转圈”。

P0 / 正式功能错误

无 Key 不能只修 UI

“免鉴权”表示服务根本不需要密码，例如局域网网关或 LM Studio。现在 UI 能保存 authType:none，但文本模型构造仍检查 apiKey 非空。

为什么是必须修：用户会看到模型已经保存，却在验证或聊天时失败。这是“保存成功、使用失败”的断裂。
无 Key 设置→不发空 Bearer→验证→正式 Agent
P0 / 凭据安全

第二密钥不能放普通配置

额外 Header、SecretKey、AK/SK 都属于凭据。当前实现把它们放在供应商 metadata 里，脚本试跑的 transcript 也可能记录它们。

为什么是必须修：这不是“以后优化一下 UI”，而是明文凭据会被日志、备份或错误报告带走。
安全存储→运行时临时注入→统一脱敏
P1 / 可靠性

验证必须有终点

网络请求、AI 编译、媒体轮询任何一步都可能不返回。必须有批次截止时间、单步超时、取消按钮和明确的 failed / timed_out / cancelled 状态。

为什么是必须修：“一直验证中”不是文案问题，而是任务生命周期没有终态。
P1 / 可用性

修正前端轮询节奏

轮询 Effect 依赖整个 adapterRun。每次收到新快照都会重建定时器并立即再请求，实际变成“响应多快就请求多快”。

为什么是必须修：它会放大 IPC 和磁盘读写，网络慢时还可能产生重叠请求；稳定的 900ms 应该由稳定的计时器控制。
这些判断在最新 main 里的代码证据
无 Key 正式调用：electron/ai/buildAiSdkModel.ts:99 仍在 Key 为空时直接抛错；设置页允许免鉴权并不能绕过这里。
额外密钥存储：electron/providerAdapter/service.ts:121 把额外 Header 写入供应商 metadata；主 Key 有安全存储，额外秘密却没有同等级保护。
验证生命周期：src/ui/onboarding/OnboardingWizard.tsx:242 的 main 版本没有把 cancelled 和 timed_out 当作完整终态；当前未提交工作区已经补了后台截止时间和取消链路，但尚未进入 main。
轮询节奏：同一 Effect 的依赖包含整个 adapterRun，而每次轮询都会替换它，因此计时器会不断销毁并立即重建。
04 / Trade-offs

值得做，但要有边界

“取舍”不是不要做，而是先承认它的收益和风险，选择不会破坏当前 main 的移植方式。

建议移植

H3 Director 专用适配器

它负责把“比例、时长、首尾帧、参考视频”翻译成 H3 的时间线和节点输入。收益是重新构建后能力仍在源码里。

取舍理由：领域逻辑很值钱，但不能只依赖固定节点编号；应先按节点类型和连接关系查找，旧编号只做兼容。
建议移植

Qwen 0–3 图模式

它防止作者示例图混进用户请求，并保证第 1、2、3 张图片进入不同的 ComfyUI 输入槽。

取舍理由：行为正确、测试充分；但固定节点 ID 像写死门牌号，工作流重新导出后可能失效。
建议移植

默认生成模型设置

用户可以分别为文生图、图片编辑、文生视频、图生视频指定默认模型，并精确保存供应商和模型的组合。

取舍理由：数据模型可靠；页面要接入当前唯一设置入口，不能把旧浮卡一起带回来。
建议移植后加固

空媒体 loader 清理

没有尾帧时删除空 loader 和下游连线，避免 ComfyUI 把空值当成 input 目录。

取舍理由：根因判断正确，但要补音频、数字节点 ID，并让公共清理先于所有专用 transformer 执行。
暂不采纳整套代码

归档里的 Provider Adapter、旧设置浮卡、构建产物

归档的接入代码比当前 main 旧：没有文档就失败、只给验证通过的媒体 mapping、仍保留双入口。`dist-electron` 是构建结果，不是长期源码。

为什么取舍：直接覆盖会把已经解决的问题重新引入。只提取可验证的领域逻辑，重新接到当前 main 的生命周期和设置页面。
05 / Plain-language dictionary

技术名词翻译

下面每个词都回答三个问题：它是什么、它在 Nomi 里做什么、为什么会影响用户。

先读：模型接入的核心结构

Provider

供应商，也就是提供模型接口的一方，可以是 DeepSeek、一个公网中转站、局域网网关或本机服务。

像“快递公司”：不同公司地址、单号格式、取件规则不同。

Provider Adapter

供应商适配器。它把不同供应商的地址、认证、模型能力和请求格式翻译成 Nomi 的统一格式。

像“转换插头”：墙上插座各不相同，设备仍想用同一种插头。

Base URL

接口的基础地址，例如 http://192.168.x.x:8078/v1。后面的 /models、/chat/completions 会从它拼出来。

像商场地址，具体店铺是后面的路径。

authType:none

明确告诉程序“这家服务不需要 Key”。正确实现必须连空的 Authorization: Bearer 也不发送。

像小区门口没有门禁，不应该伪造一张空门卡。

Protocol / 协议

请求和响应的约定，例如 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。

像不同国家的语言和表格格式，地址对了，语言说错也无法办理业务。

Mapping

模型能力到真实 HTTP 调用的路线。例如“这个模型的文生图要 POST 到哪里、结果在哪个字段”。

像导航路线；模型名字存在，不代表已经有可走的路线。

Verification / 验证

Nomi 用一次真实请求检查地址、认证、模型和能力是否真的可用。

像试拨电话，不是只检查通讯录里有没有这个号码。

Document Discovery

尝试读取供应商的 API 文档，让系统知道图片、视频等非标准能力的调用方式。

像先看说明书；没有说明书不等于机器一定坏。

Transformer

请求变换器。发送前把 Nomi 的统一参数改写成某个工作流实际需要的节点输入。

像机场转运行李标签，把同一件行李贴成下一段航班认识的格式。

ComfyUI Workflow

由节点组成的生成流程。节点可能负责加载图片、采样、编码和保存文件。

像流水线，每个节点是一台机器，连线是传送带。

Loader

ComfyUI 中负责读取图片、视频、音频或模型文件的节点。空 loader 可能把目录误当文件。

像文件柜抽屉；抽屉没有文件时，不能把整间档案室当成一张照片。

Vendor + Model Identity

模型的精确身份由供应商和模型名一起组成，而不是只看模型名。

“同名的人”要用公司 + 姓名区分，不能只看姓名。

Timeout / Cancel

Timeout 是系统等太久后自动结束；Cancel 是用户主动停止。两者都必须产生明确终态。

计时器和刹车，不是把页面关掉就算任务结束。

Unverified

用户选择了模型，但 Nomi 这次探测没有成功。它不等于模型不存在，也不等于已经验证通过。

像“地址已登记，但还没打通电话”，应该允许用户继续配置并看见风险。

Safe Storage

操作系统提供的安全凭据存储。普通 catalog 只保存引用或状态，不保存可直接使用的密钥。

把钥匙放保险柜，系统只拿临时钥匙开门。

地址、接口和认证

API / 接口

两个程序按固定规则交换数据的入口。Nomi 不需要打开供应商网页，而是通过接口把文字、图片和参数发过去，再接回结果。

像餐厅后厨的点单窗口：顾客不进厨房，只按菜单格式下单。

HTTP 与 HTTPS

两者都是网络传输方式。HTTPS 会加密传输，HTTP 不加密。局域网 HTTP 可以正常接入；真正需要判断的是地址是否可达、接口规则和认证是否匹配。

都是送信，HTTPS 像上锁的信箱。不上锁不等于地址不存在。

局域网网关 / 公网中转

局域网网关只在家里或公司网络内可访问；公网中转可以从互联网访问，并把请求转给真正的模型服务。两者都可能兼容 OpenAI 接口，也都可能没有公开文档。

前者像公司内线，后者像外部总机。

URL、Path、Endpoint

URL 是完整网络地址；Path 是地址后面的具体路径；Endpoint 是真正处理某类请求的接口终点。例如基础地址加 /models 得到模型列表终点。

URL 是完整收件地址，Path 是楼层房间，Endpoint 是实际办事窗口。

Model / 模型与能力

模型是执行生成任务的程序。能力是它能做的事情，例如聊天、文生图、图生视频。同一个模型名存在，不代表 Nomi 已经知道每一种能力该怎么调用。

员工在名单里，不等于已经知道他的岗位和工作流程。

API Key / apiKey

供应商发给用户的一段访问凭据，用来证明“这次请求是谁发的”。有些公网服务必须提供，有些本机或局域网服务明确不需要。

像门禁卡；没有门禁的小区不应该强迫每个人填卡号。

Header、Authorization、Bearer

Header 是随请求附带的小字段；Authorization 是常见的认证字段名；Bearer 表示“后面这段 Key 就是持有人凭据”。三者不是同一个东西，而是容器、字段名和认证格式的关系。

Header 是信封备注区，Authorization 是“身份证明”一栏，Bearer 是这一栏的填写格式。

Extra Header、SecretKey、AK/SK

有些供应商不只要一个 Key，还要求额外请求头或一对 Access Key / Secret Key。它们仍然是密码，不能因为放在“额外配置”里就按普通文字保存。

主门钥匙和保险箱钥匙都属于钥匙，不能把第二把贴在门外。

GET、POST 与 JSON

GET 通常用来读取数据，POST 通常用来提交任务。JSON 是请求和结果常用的结构化文本格式。路径正确但方法或字段格式错误，请求仍会失败。

到了正确窗口，还要分清“查询表”和“申请表”。

兼容契约与兜底

兼容契约是一套已知的通用调用规则，例如 OpenAI 风格的模型列表和聊天接口。兜底表示找不到供应商文档时，先按这套常见规则真实试用，而不是立刻拒绝整个接入。

没有专用说明书时先用行业通用插头试接，但仍要检查是否真的通电。

三种常见文本协议

OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 是三套不同的文字模型请求格式。它们都能聊天，但路径、字段和返回形状不同，不能只改供应商名字。

都是寄包裹，不同快递公司的面单格式不同。

模型列表 / /models

供应商返回的可用模型名称清单。拉到名单只能证明地址和这一步认证大致可用，不能证明聊天、图片或视频生成已经能执行。

看到菜单不等于后厨已经能做出每一道菜。

Nomi 内部、验证和安全

UI、前端、设置向导

UI 是用户看到并点击的页面；前端是负责这些页面的代码；设置向导是分步骤收集地址、认证和模型的界面。它们负责交互，不负责替代真实调用。

像银行柜台：柜台收材料和展示结果，真正记账在后台完成。

Runtime / 运行时

用户真正聊天或生成图片时执行请求的后台代码。接入验证通过而运行时失败，说明“试车路线”和“正式路线”没有使用同一套规则。

验车场能开不够，上路时也必须使用同一套发动机和油路。

Agent / 智能助手

Nomi 中会调用文字模型来理解任务、规划步骤或回答用户的助手。它最终仍要通过运行时访问已配置的模型，并不是一个绕过认证的独立模型。

像项目经理，会组织工作，但打电话仍需要能用的通信线路。

AI SDK

一套现成的程序库，把多家文字模型包装成较统一的调用方式。Nomi 的文本验证和正式 Agent 会经过它；如果这里强制 Key，前面的免鉴权设置就会失效。

像统一电话机；电话线接好了，电话机仍可能因为错误规则拒绝拨号。

Catalog / 模型目录

Nomi 保存供应商、模型、能力路线和启用状态的结构化清单。它回答“有什么模型、属于谁、能做什么”，不应该直接保存额外明文密码。

像员工花名册，应该记录岗位，不应该把银行卡密码写进去。

Metadata / 附加信息

挂在供应商或模型旁边的补充字段，用来记录状态、标签等非核心信息。普通 metadata 往往会进入文件、备份或调试输出，所以不适合放密钥。

像档案袋外面的备注贴，适合写分类，不适合写保险箱密码。

Log、Transcript、Redaction

Log 是程序运行记录；Transcript 是一次脚本或验证过程的详细记录；Redaction 是在写记录前把密钥替换成不可用占位符。仅在页面上隐藏密钥远远不够。

监控录像要留，但密码键盘区域必须打码。

Task、Lifecycle、Terminal State

Task 是后台执行的一项工作；Lifecycle 是它从排队、运行到结束的全过程；Terminal State 是不会再继续变化的最终状态，例如成功、失败、超时或已取消。

快递必须最终变成已签收、退回或丢失处理，不能永久显示运输中。

verified / failed / partial

verified 表示真实试用通过；failed 表示失败并有原因；partial 表示同一批里有成功也有失败。这些标签必须反映证据，不能为了让按钮变绿而伪装。

体检是“通过、未通过、部分项目待复查”，不能把未检查写成通过。

Polling / 轮询

页面每隔一段时间向后台询问“任务进度到哪了”。轮询本身正常，但间隔必须稳定，请求未完成时不应再叠加同类请求。

每隔一分钟问一次可以；对方每回答一个字就再打一次电话会堵塞线路。

Effect / 页面副作用

页面框架在某些数据变化后自动执行的一段逻辑，例如启动轮询。若它依赖整个进度对象，每次进度更新都会重启计时器，轮询就可能失去原本的 900 毫秒节奏。

时钟每走一格就被重新上弦，反而无法按正常周期报时。

IPC

桌面应用页面与后台主进程之间的消息通道。页面通过它启动验证、读取进度和取消任务。高频重复轮询会让这个通道和后台读写承受无意义负担。

像前台和仓库之间的对讲机，持续抢话会让真正指令进不来。

P0 / P1

问题优先级。P0 通常表示核心功能完全不可用或有严重安全风险；P1 表示重要流程明显不可靠或用户很容易卡住。它不是“修复质量等级”。

P0 像刹车失灵，P1 像车门经常打不开，都应修，但紧急程度不同。

AI 编译 / Repair

系统根据接口文档生成调用草稿，验证失败后再尝试修正草稿。它适合处理非标准图片和视频接口，但不应该成为已有通用规则的文本模型的必经门槛。

特殊机器需要看图纸定制转接件；标准插座不必每次重新设计。

唯一入口 / 浮卡

唯一入口表示不同按钮最终都打开同一份模型设置页面；浮卡是叠在页面上的独立小面板。两套入口并存会产生两份状态、两套保存逻辑和位置错乱。

同一账户有两个互不通账的柜台，用户无法知道哪边才是真记录。

ComfyUI 与贡献者改动

H3 Director

一类视频工作流的专用调度逻辑，把画面比例、时长、首尾帧和参考视频放到正确节点。值得保留的是这些业务规则，不是旧版接入页面。

像熟悉某条生产线的工艺师，他的工艺知识有价值，但不能把旧厂房一起搬回来。

Qwen 0–3 图模式

让同一工作流能接收零到三张用户图片，并把每张图片送到正确输入槽。还要删除模板自带的示例图，避免把作者素材混进用户任务。

有几个包裹就开几个真实货位，空货位不能塞着演示样品。

Node、Connection、Input

Node 是工作流中的处理步骤；Connection 是节点间的数据连线；Input 是节点接收的参数或文件。删除空节点时也要删除相关连线，否则流程仍可能引用不存在的数据。

机器、传送带和进料口必须一起调整。

Node ID / 节点编号

每个节点在工作流文件中的编号。直接写死编号实现很快，但工作流重新导出后编号可能变化；按节点类型和连线关系查找更稳，旧编号可保留作兼容。

找人用“质检员岗位”比只记“17 号座位”更可靠。

Parameter Persistence / 参数持久化

用户调整比例、步数或强度后，保存并再次打开项目仍能恢复这些值。测试必须覆盖保存、重开和最终请求，不能只看输入框当时显示。

调好的座椅位置熄火后仍应记住，而不是下次全部归零。

Source 与 dist-electron

Source 是开发者维护的原始代码；dist-electron 是工具根据源码生成的可运行文件。构建产物可以用于试跑，但不应覆盖源码或作为长期合并依据。

源码像菜谱，构建产物像做好的菜；不能靠拆菜恢复可靠菜谱。

Git、分支和交付状态

main 与 origin/main

main 是电脑上的主分支；origin/main 是远端仓库主分支的本地记录。同步后两者应指向同一个提交。本次都已到 452df94d。

一个是本地账本，一个是远端总账的最新副本。

Branch / 分支

从某个提交分出去的一条独立开发线。分支里修好了不等于产品已经修好；只有经过测试并合入 main，后续版本才会自然包含它。

支路上修好了一段路，不代表主干道已经铺好。

Worktree / 工作区

当前电脑上实际打开的代码和未提交修改。它可以比 main 新，也可能混有尚未验证的半成品，所以报告必须把“main 已有”和“工作区正在改”分开写。

账本里的正式记录和桌面上还没入账的票据不是一回事。

Commit / 提交与哈希

提交是一份有说明、可追踪的代码快照；哈希是它的唯一编号，例如 452df94d。只有压缩包而没有 Git 历史，就无法证明某个提交编号真的对应包内全部文件。

像带编号和日期的存档页，散装复印件不能证明来自哪一页。

Archive 与 SHA-256

Archive 是压缩包；SHA-256 是根据文件内容算出的长指纹。指纹能证明“现在看的仍是同一个压缩包”，但不能证明里面的代码已经合入 main。

封条编号能证明箱子没换，不能证明箱内货物已上架。

Test / 测试与验收

自动测试检查可重复的代码规则；人工验收检查真实用户流程。两者都通过才有较强证据：测试绿不代表页面好用，页面能点也不代表密码安全或后台会结束。

零件检测和整车路试缺一不可。

PR、Merge、已合入

PR 是请求把一个分支的改动审查后加入主分支；Merge 是实际合并动作；“已合入”表示 main 已经包含这些提交。只创建分支、写完代码或通过测试，都不能称为已合入。

申请入库、执行入库、货物已在正式货架上是三个阶段。

07 / Acceptance

怎么证明真的修好

每一项都要从用户输入一路验证到真实请求，不只看页面上的绿色标签。

免鉴权 HTTP 网关

填 http://局域网地址，Key 留空；检查模型列表、验证、文本 Agent 三处都没有 Authorization 头。

没有公开文档的公网中转

让文档探测返回空；验证仍进入通用 OpenAI 兼容契约，模型不会从列表消失。

故意制造挂起

让上游请求不返回；到达截止时间后必须显示 timed_out，取消后必须显示 cancelled，不能继续转圈。

故意让一个模式失败

文本通过、图片失败时，文本仍可用；图片显示未验证和修复入口，不能被误标为 verified。

凭据泄漏测试

在额外 Header 和第二密钥中放测试字符串，检查 catalog、日志、transcript、错误弹窗都没有明文。

ComfyUI 0–3 图

分别测试 0、1、2、3 张图，以及缺少可选尾帧/音频；检查最终 /prompt 中节点和连线真实正确。

设置入口

从顶部、模型卡、画布错误提示进入，最终都落到同一个设置模型页；页面下方不出现第二个浮卡。

默认模型

设置供应商 A 的默认模型，再新增图片和视频卡；禁用 A 后必须回退到健康模型，不能串到同名供应商 B。
