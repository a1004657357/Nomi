## Findings

### P2 — LOD thumbnail overwrites original image dimensions (confirmed; local correction provided)

`LightweightGenerationNode.tsx` attaches `mediaMeasurement.onImageLoad` to `preview.src`. `resolveLightweightNodePreview` chooses `thumbnailUrl || url`, but `computeNodeMediaMeasurementPatch` checked only captured result id/url and media kind, never which image actually decoded. Result: a 4001×3001 original became 1024×768 after lightweight loading. This is not a hypothetical malformed input: `electron/assets/assetPreview.ts` intentionally scales thumbnail long edge to 1024 with short side rounded by the `-2` filter. The intrinsic metadata loses both original resolution and exact aspect. Full/LOD switches can rewrite the values repeatedly.

Reproduction: `/tmp/nomi-media-audit-repro.mjs`, `/tmp/nomi-media-audit-repro.log`, exit 1. Before meta 4001×3001; after meta 1024×768; 600px-wide displayed height changes 450.03749 -> 450.0. The small visual drift does not make loss of original dimension facts acceptable. Base and all three dedicated cards currently render result.url directly; they do not reproduce the thumbnail case, but share the unsafe boundary.

Correction in image-aspect worktree: the image measurement union requires `sourceUrl`; the hook obtains the actual DOM `getAttribute('src')`, and shared compute rejects sources other than current result.url. This preserves relative URLs (unlike comparing browser-absolute `.src` to raw relative persisted URLs), also rejects stale DOM source events, and preserves original-source measurements. NomiImage currently assigns its resolved src unchanged, and these callers do not use srcSet. Video handling is deliberately unchanged because NodeVideoPlaybackGuard can legitimately heal/rewrite playback URLs; video posters were already rejected by the kind check. No hidden Image, decoder, network probe, or thumbnail regeneration was added.

Red: focused new cases produced 3 failed / 17 passed before implementation (`/tmp/nomi-thumbnail-red.log`). Green: 4 related suites / 42 tests (`/tmp/nomi-thumbnail-green.log`). A browser fixture using the production hook with an in-memory store and real DOM image decode confirms thumbnail writes=0 and original writes=1, dimensions 4001×3001, options persist/emit/history all false (`/tmp/nomi-thumbnail-browser.mjs`, `.log`). This is an isolated browser test, not a real Electron project walkthrough. If original dimensions are absent and LOD has only a thumbnail, geometry remains unmeasured until original decode; no rounded thumbnail ratio is invented as original geometry.

### P2 — capture-phase Escape steals an input's owned cancel action (confirmed; handed to Escape owner)

`AnchoredPopover.tsx:125-151` moves document keydown from bubble to capture and unconditionally prevents/default-stops Escape once upper portal checks pass. It now acts before a focused child's React onKeyDown. An input marked `data-nomi-escape-owner="true"` cannot consume Escape to cancel its own edit. Browser reproduction with the real popover yields `popoverOpen=0`, `inputHandled=false` instead of staying open and calling the child handler. Existing `overlayLayers.ts` has the owning-target selector used elsewhere, but the new popover path does not consult it.

The capture change has a valid purpose: ordinary Escape in a portal reached the owning React Flow node before document bubble and unselected the node. That fixes the reported composer-disappearance bug. The missing inner owner arbitration is a separate regression, not an argument to blindly revert the capture fix. Nested inline listboxes are another risk because hasOpenPopupAbove excludes descendants; I did not separately reproduce that variant. Parent/other agent owns the correction; this auditor made no Escape production edit.

## Test changes and baseline scrutiny

- `computeMediaMetaPatch.test.ts`: drops currentSize because the pure boundary no longer owns size. The old explicit acknowledged-generation-footprint assertion is replaced by exact metadata-only output. This is a real contract replacement, not equivalent coverage. It is justified by the approved intrinsic-aspect behavior; retaining the old freeze assertion would test the behavior the user wanted removed. Video-duration assertions remain. New legacy-metadata case verifies portrait ratio overrides stale height.
- `nodeSizing.visualSize.test.ts`: existing cases retained; new landscape/portrait/extreme, stale param/previewHeight, asset split, video, footer and invalid dimensions check the changed contract. No weakened expected values found.
- `useNodeMediaMeasurement.test.ts`: new file checks result identity, poster type, footer merge and extremes/special-node exclusions. Frozen head missed actual decoded-source identity. Local added tests fail red for both measured and unmeasured thumbnail cases and stale DOM sources, then pass after shared fix. These exercise the shared write boundary rather than asserting implementation strings.
- `_composerFixedFooter.mjs`: three additional Escape checks enforce hidden preset/menu, retained node selection and visible composer. Existing assertions are not deleted.
- `_feel.browser.mjs`: new fixture uses real AnchoredPopover and React Flow; natural/trigger/menu/input Escape, portal listbox/dialog, IME, pre-prevented event and outside click are valuable. However the prevented-event test calls preventDefault before dispatch, so it never proved a nested onKeyDown could claim the key. The input test had no owned cancel handler. That gap hid the confirmed regression.
