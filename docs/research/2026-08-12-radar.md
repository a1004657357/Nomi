## 🟢 可落地

### GroundShot：training-free model-agnostic 实体内存 + 生成顺序调度

- **链接 / 日期**：[arXiv 2606.20799](https://arxiv.org/abs/2606.20799)，v1 **2026-06-18**，最新版 2026-07-20；作者来自浙江大学等。暂无公开代码仓，但方法完整描述在论文中，核心契约可直接移植。
- **一句话洞察**：训练无关、模型无关的 agent 框架——在线维护实体级视觉内存（entity-level visual memory），按"这一镜作为后续参考的期望价值"调度生成顺序，生成后用检测/分割验证实体可靠性才允许写入内存，检索时按实体相关性（非时序近邻）排序。
- **落到哪个模块**：`src/workbench/generationCanvas/runner/generationReferenceResolver.ts`（引用决策） + `src/workbench/generationCanvas/runner/referenceAncestors.ts`（锚点写入契约）。具体：① 引用候选筛选前先过验收门（身份/构图通过才允许成为后续镜头的参考），② 检索时按与当前镜头实体的语义相关性排序，而非直接取时序最近帧。
- **诚实边界**：论文无公开代码，"实体核实"部分依赖检测/分割工具（GroundingDINO、SAM 级别），Nomi 当前用 VLM 裁判替代是可行的最小接法；生成顺序调度需要 canvas 引擎支持非线性排队（待核实 `dependencyWaves.ts` 是否已支持部分拓扑排序）。

### 3R：training-free RAG-based T2V Prompt 优化框架

- **链接 / 日期**：[arXiv 2603.01509](https://arxiv.org/abs/2603.01509)，**2026-03-02**（ICLR 2026 TTU Workshop）；作者 Zillur Rahman、Alex Sheng、Cristian Meo；暂无公开代码仓。
- **一句话洞察**：纯 prompt 层（无需微调任何生成模型）的三步管线：① 从历史视频-文本语料检索高相关修饰词（RAG 增强）；② 用指令微调的 LLM 把增强后的 prompt 改写成与生成模型训练集分布一致的格式；③ 加时序帧插值增强动态一致性。任意 T2V 模型均可直接用。
- **落到哪个模块**：`src/workbench/generationCanvas/agent/storyboardPlan.ts` 的镜头 prompt 改写节点，或独立的"AI 优化 prompt"节点。具体：引入 RAG 修饰词召回（从 Nomi 已有生成成功案例的 prompt 作为语料库）+ 格式对齐改写，替代现有纯 LLM 润色。不依赖训练，符合 P4 解耦原则（可接任意 T2V 后端）。
- **诚实边界**：ICLR Workshop 论文，尚无同行评审；论文中 RAG 语料库来自外部大规模 video-text 数据集，Nomi 替换为自有生成历史时效果有衰减，需离线实验验证增益。

## 🟡 架构教训

### ShotStream：双缓存分离 intra/inter 一致性，级联误差通过蒸馏封顶

- **链接 / 日期**：[arXiv 2603.25746](https://arxiv.org/abs/2603.25746)，v1 **2026-03-31**；KlingAI Research / 浙江大学；[GitHub 代码已开源](https://github.com/KlingAIResearch/ShotStream)，含训练与推理脚本及 HuggingFace checkpoint。
- **一句话洞察**：把多镜生成的缓存拆成两层——**global context cache**（存条件帧，负责跨镜一致性）+ **local context cache**（存当前镜内生成帧，负责镜内连贯性），用 RoPE 不连续指示符显式区分，避免两类一致性需求在注意力层相互干扰；训练时先用双向教师模型，再蒸馏成因果架构，把级联误差压在蒸馏层而非让它随镜数累积。
- **影响 Nomi 哪个决策**：Nomi 在 `generationReferenceResolver.ts` / `referenceAncestors.ts` 向后续镜头传递参考时，当前用统一的引用槽；ShotStream 的教训是"跨镜参考（角色/场景锚点）"和"镜内历史（当前镜已生成的前几帧）"必须分槽管理，混在一起会让注意力在跨镜身份和镜内连贯之间打架。这是 Nomi 现有 `referenceSlots.ts` 值得梳理的架构点。
- **诚实边界**：ShotStream 的核心收益来自联合训练蒸馏（基于 Wan 2.1-T2V-1.3B），API 边界外无法照搬；Nomi 只采用"双缓存分槽"的接口契约——不混用跨镜锚点和镜内历史两类上下文。

## 🔵 对标基准

### KathaTrace / KathaBench-25K：量化"视觉看着连贯但语义其实已断"的镜间叙事瘫痪

- **链接 / 日期**：[arXiv 2607.01312](https://arxiv.org/abs/2607.01312)，v1 **2026-07-01**；数据集 [HuggingFace iamjamuna/KathaBench-25K](https://huggingface.co/datasets/iamjamuna/KathaBench-25K)，CC BY 4.0，已公开可下载。5,000 叙事 / 20,000 个镜间转场 / 28,712 条可恢复性问题对，人工验证 Fleiss' kappa = 0.845。
- **一句话洞察**：核心指标 **Semantic Trajectory Gap（STG）** = 仅凭文字描述能猜出下一幕的概率 − 仅凭生成画面能猜出下一幕的概率；差值越大说明视觉化过程丢失了越多叙事线索。当前 SOTA 生成器 STG 均值 23.5 ± 1.3，即有大量"画面看上去合理但叙事逻辑已断"的转场。
- **怎么接进 Nomi eval**：从 KathaBench-25K 的 transition 子集抽 transition-type 多样的 50 条，把它们转成 Nomi 的多镜剧本 fixture（镜头 A 描述 → 镜头 B 描述 → 生成 B → VLM 问"看到 B 的画面，能推断出从 A 到 B 发生了什么吗"），记 image-only recoverability 分，接入 `evals/lib/vbenchRubric.mjs` 作为新维度 `narrativeCoherence`。与 VideoArgus 的 rubric 框架（08-09 雷达）互补：VideoArgus 评单帧/单镜质量，KathaTrace 评跨镜叙事连贯。
- **诚实边界**：KathaBench-25K 的叙事来自古典故事集（伊索、五卷书），风格偏寓言；Nomi 用户的剧本多为现代商业/营销场景，STG 数字不可直接对比，仅作趋势参考。
