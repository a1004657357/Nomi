## 一句话总结

本轮 **🟢 2 / 🟡 1 / 🔵 1**。最大的一件事：上一轮推荐的 3R prompt 优化方案（无公开代码、需自建 RAG 图谱）**本轮被 SCMAPR 直接取代**——同样 training-free + model-agnostic，但**代码已开源（Apache-2.0，纯 LLM API 调用、零训练依赖）**，且带了 3R 没有的「原子级语义校验 + 条件回改」闭环，正好补上 Nomi prompt 优化节点当前「改完不校验、模型漏掉的要素没人发现」的缺口。

**本轮最该动的两件事：**

1. **用 SCMAPR 的「原子化校验 + 条件回改」替换 `NodePromptOptimizer.tsx` 当前的一次性润色**：现在 Nomi 的优化节点是「LLM 润色一遍就返回」，模型漏写主体/动作/光线没有任何检测。SCMAPR 的做法是把改写后的 prompt 拆成原子语义单元，逐条比对原始输入有没有丢，丢了才触发回改——这是纯 prompt 层逻辑，Apache-2.0 代码可直接参照，不改任何生成后端（符合 P4 解耦）。
2. **按 EM-Vid 的「实体索引记忆」重审 `referenceSlots.ts` 的槽语义**：EM-Vid 的核心论断是「存整帧 = 存了一堆无关信息，反而稀释身份」，应改存**按实体索引的 patch**。Nomi 的槽已经是有序 + 按 archetype 声明的（`numbered` 角色图对应 character1..N），架构方向是对的；缺的是「同一角色跨镜时选哪张历史帧」的实体相关性排序——这条与 08-12 的 GroundShot 落地项合并做，别开两个工。

## 🟢 可落地

### SCMAPR：六 agent 五阶段的 training-free prompt 精炼，代码已开源

- **链接 / 日期**：[arXiv 2604.05489](https://arxiv.org/abs/2604.05489)，v1 **2026-04-20**（当前 v4）；HiThink Research + 华东师范大学 + 广州大学 + 清华大学。**代码公开**：[github.com/HiThink-Research/SCMAPR](https://github.com/HiThink-Research/SCMAPR)，Apache-2.0（数据 CC BY-NC 4.0），11 star。
- **一句话洞察**：把 prompt 优化拆成**改写组**（Scenario Router 打场景标签 → Policy Generator 生成该场景专属改写策略 → Prompt Refiner 执行）+ **校验组**（Semantic Atomizer 把改写结果拆成原子语义单元 → Entailment Validator 逐个原子做蕴含检查 → Content Reviser 只在校验失败时条件回改，且回改时原子约束锁定不动）。关键是**改写和校验分离**——不让同一个模型既当运动员又当裁判。
- **落到哪个模块**：`src/workbench/generationCanvas/nodes/NodePromptOptimizer.tsx`（196 行，当前是一次性润色）+ `src/workbench/generationCanvas/agent/canvasPromptContext.ts`。具体改法：① 在优化节点返回前插一道 Atomizer/Validator——把用户原始输入拆成「主体 / 动作 / 场景 / 光线 / 镜头语言」原子，逐条检查改写后的 prompt 有没有丢；② 只有校验不过才触发一次回改（预算 1 次，防死循环，参照 `storyboardLoopBudget` 的封顶习惯）；③ Scenario Router 可复用 Nomi 已有的 `creationAiModes.ts` 模式标签，不必另建分类器。
- **为什么这次值得动（vs 上轮的 3R）**：3R 需要自建 RAG 关系图谱 + 无代码，落地阻力大；SCMAPR 零检索依赖、纯 LLM API 调用（`pip install -r requirements.txt` + 填 API key 即跑），且校验闭环正是 Nomi 现在完全没有的部分。
- **诚实边界**：论文报告的增益不大（VBench 平均 +0.78%~+2.67%，Wan 上更小）——这不是画质飞跃，是**减少「用户写了但生成时丢了」的低级失误**，价值在稳定性不在上限。多一轮 LLM 调用会增加优化节点延迟，需在节点上做可关开关。

### EM-Vid：实体索引的 latent patch 记忆，稀疏 token 条件化

- **链接 / 日期**：[arXiv 2605.23610](https://arxiv.org/abs/2605.23610)，v1 **2026-05-22**；作者 Jente Vandersanden、Matheus Gadelha（Adobe Research 背景）、Chun-Hao P. Huang、Hyeonho Jeong、Yulia Gryaditskaya。**暂无公开代码仓**（本轮实查未找到）。
- **一句话洞察**：不存整帧，存**按实体（角色/物体）索引的 latent patch bank**——论断是「整帧参考里绝大部分像素与身份无关，反而稀释了注意力」；配套三件事：稀疏 token 条件化（自注意力只看实体相关信息）、有预算的记忆更新（bank 保持紧凑、随镜演化）、噪声注入（控制外观但不泄漏原帧构图）。声明 training-free、兼容预训练模型。
- **落到哪个模块**：`src/workbench/generationCanvas/runner/referenceSlots.ts`（槽解析唯一真相源）+ `generationReferenceResolver.ts`。**Nomi 已经站对了一半**——槽是有序的、`numbered` 角色图按位对应 prompt 的 character1..N，这已经是「按实体索引」而不是「一坨参考图」。缺的是：同一角色在第 5 镜时该拿第 1 镜还是第 4 镜的帧当参考，当前没有实体相关性排序，是靠边的连法定的。改法：在 `generationReferenceResolver.ts` 里给同实体的多个候选帧加一层排序（按该帧中该角色的可见度/清晰度打分），与 08-12 的 GroundShot 落地项**合并成同一次改动**。
- **诚实边界**：EM-Vid 的 latent patch 操作在**扩散模型内部**（要能碰 latent 和自注意力），Nomi 走供应商 API，这部分照搬不了。可采纳的只是**「实体索引 + 有预算的记忆」这个数据结构契约**，落在参考选取层，不是生成层。无公开代码，实现细节需自行推导。

## 🟡 架构教训

### MuSS + ACP-Var：多镜生成的隐藏失败模式是「复制粘贴」，不是「不一致」

- **链接 / 日期**：[arXiv 2604.23789](https://arxiv.org/abs/2604.23789)，v1 **2026-04-26**，**v3 2026-08-11（本轮窗口内刚更新）**；数据来自 3,000+ 部电影。公开状态：论文页未见数据集/代码链接，**待核实**。
- **一句话洞察**：提出 **Anti-Copy-Paste Variance（ACP-Var）** 指标，点破一个反直觉的失败模式——当你为了跨镜一致性猛塞参考图时，模型会走捷径**把参考帧的主体近乎原样贴过来**：身份指标满分，但人物姿态、朝向、光线在所有镜头里纹丝不动，看着像 PPT 不像电影。另配「渐进式字幕管线」处理跨镜描述的上下文冲突。
- **影响 Nomi 哪个决策**：这直接影响 `shotVerify.ts` 的验收判据。Nomi 当前的镜头验收偏向「像不像同一个人」，**没有反向门**——如果生成结果和参考图过于相似（姿态/构图几乎复制），当前会被判为「一致性很好」通过，实际上是坏结果。教训：验收应是**双向区间**，太不像要打回，太像也要打回。同理，`referenceSlots.ts` 里首帧/尾帧的强约束在连续镜头上会放大这个问题。
- **诚实边界**：ACP-Var 的具体计算依赖其 3D 结构一致性模块，Nomi 用 VLM 裁判只能做定性判断（「这两镜的人物姿态是否几乎相同」），不是原指标。数据集公开状态未核实，本轮只取教训不接 eval。

## 🔵 对标基准

### V2V-Bench：11 维分解式 video-to-video 评测，ρ=0.905

- **链接 / 日期**：[arXiv 2606.05665](https://arxiv.org/abs/2606.05665)，v1 **2026-06-04**；Centific Global Solutions Inc.（Tao Liu 等）。**未见公开代码/数据集链接**，待核实。
- **一句话洞察**：把 V2V 质量拆成 5 类 11 维——时序对齐（帧对应 / 时序一致）、结构保真（结构保留 / 布局遵循）、变换质量（编辑忠实度 / 风格迁移质量）、视频质量（运动平滑 / 美学 / 成像 / 时序闪烁）、语义对齐（内容保留）。V2V 专项维度上与人类判断 Spearman ρ=0.905；**但全 11 维平均只有 0.688**——这个落差本身是有用信息：通用画质维度的 VLM 打分远不如专项维度可靠。
- **怎么接进 Nomi eval**：对口 `evals/journeys/j5-edit-export.mjs`（编辑/导出旅程）——Nomi 的时间轴编辑、抽帧接力本质就是 V2V。把「结构保留 + 布局遵循 + 内容保留」三维映射进 `evals/lib/vbenchRubric.mjs`，专门用来判「编辑之后，不该变的地方有没有被改坏」。**注意只接专项维度**（ρ=0.905 那批），通用画质维度（美学/成像）按论文自己的数据就不可靠，别接。
- **诚实边界**：无公开代码/数据集，只能照 rubric 定义自建题目；且 V2V-Bench 针对完整视频到视频的变换，Nomi 的抽帧接力是「取尾帧 → 再 t2v」，属于部分重叠而非完全对口。与 08-11 的 WorldJen（通用 16 维）、FilmBench（电影多镜）分工：V2V-Bench 只补编辑旅程这一块。
