# Nomi 论文雷达：2026-08-24

一句话：本轮真正的新料是**镜间转场从「prompt 描述」升级成「模型可控信号」**（ShotPlan，代码+76★）和**把「agent 自己评自己、自己进化技能」做成可跑框架**（VideoWeaver，代码+自带 bench）——两者都直接打在 Nomi 的 decompose-stitch 命门上，且都有开源代码可立刻上手。

本轮最该动的两件事：

1. **拉 ShotPlan（Wan 底座、Apache-2.0、76★）跑一遍**，把「硬切/软转场/镜内运镜」当成可控 token 而不是塞进 prompt 的形容词——这是 Nomi 时间轴 shot→shot 链目前最缺的一环（DirectorBench 早就指认「镜间转场」是全行业中心瓶颈）。
2. **借 VideoWeaver 的「agent-as-judge 看执行轨迹 + 技能进化」范式**，把 Nomi 的质量门从「生成后打个分」改成「看整条节点执行轨迹、发现问题回改 prompt/参数、把有效改法沉淀成可复用技能」——和 Nomi 节点执行模型天然同构，且它自带 285 case bench 可直接接 eval。

> 说明：本轮 arxiv **2608（8 月）窗口仍然很薄**——8 月才过三周，视频生成方向「带代码」的新论文尚未冒头（各 daily crawler 里 2608 前缀几乎全是无代码 poster）。按铁律只吃近 6 月（≥2602 在窗口内），本轮收的是 **2604–2607 里此前几期雷达漏掉、且经二次核验有代码/传播信号**的几篇。昨天（08-23）已报的 EntityBench / DirectorBench / MotionCtrl / Wan / VBench 一律不重复。

## 🟢 可落地

### ShotPlan：把「镜间转场」从 prompt 形容词变成可控 token，代码 + 76★

- **链接 / 日期**：[arXiv 2607.17675](https://arxiv.org/abs/2607.17675)，v1 **2026-07-20**；[项目页](https://pensioner-11.github.io/ShotPlan/)、**代码公开** [github.com/Pensioner-11/ShotPlan](https://github.com/Pensioner-11/ShotPlan)，**76 star / Apache-2.0 / 仍在更新**（pushed 2026-07-21），**Wan 视频扩散底座**。
- **洞察**：引入「可学习的 planning token」捕捉镜级转场线索，配 Fractional Temporal RoPE（FRoPE）把转场**建到帧级**——单条文本 + 逐镜 caption 就能产出「在指定时间戳硬切 / 交叉淡入软转场 / 镜内定域运镜」。评测集专盯跨镜角色一致（60）、场景一致（30）、长镜无转场（10）。
- **落到 Nomi**：这正对 Nomi 时间轴的 **shot→shot 链**（方向 4，DirectorBench 认定的中心瓶颈）。目前 Nomi 的转场只能靠 prompt 里写「切到…」，模型接不接得住全凭运气；ShotPlan 给的是**显式转场信号**。**建议先做一次对照实验**：拿 Nomi 现有逐镜 caption 喂 ShotPlan，看「硬切/软转场/镜内推拉」的可控度是否显著优于纯 prompt——若成立，`ShotIntent` 里的 `cameraIntent`/转场类型就有了一个能落地的原生控制目标（Wan 系供应商可原生、其它标 translated，符合 P4 解耦 + 08-23 雷达 MotionCtrl 的教训）。落点待核实：时间轴 shot 链模块 / 生成参数适配层（需 grep 现有 `ShotIntent` 定义确认字段）。

### VideoWeaver：agent 看自己的执行轨迹 + 进化技能，代码 + 285-case bench

- **链接 / 日期**：[arXiv 2606.08091](https://arxiv.org/abs/2606.08091)，v1 **2026-06-06**；**代码公开** [github.com/JianhuiWei7/VideoWeaver](https://github.com/JianhuiWei7/VideoWeaver)，**31 star**（未声明 license，接入前需确认）。
- **洞察**：核心是 **skill evolution 而非固定 pipeline**——agent 用「agent-as-judge」检查**执行轨迹 + 最终输出**给反馈，再用技能进化算法**精炼/合并自己的技能**；论证「显式的 composition skill 比只用基础技能更好」。全程 training-free。自带 benchmark：16 类任务 / 285 case / 带多模态参考。
- **落到 Nomi**：Nomi 就是节点执行图，和「agent 组合基础技能」天然同构。**两个可立即动的点**：① 把质量门（对标 08-23 雷达 DirectorBench 的「按瓶颈诊断」）从「生成后打总分」升级成「读整条节点执行轨迹 → 定位是拆镜/首帧/t2v 哪一步坏 → 回改对应节点」；② 把「哪种 prompt 改法/参数组合真的救回了这类镜头」沉淀成**可复用技能**，下次同类镜头自动调用——这比每次从零 prompt 强。它那 285-case bench 可直接接进 Nomi 的 eval 体系跑基线（⚠️ license 未声明，商用/分发前先核实）。

## 🟡 架构教训

### GroundShot：training-free + model-agnostic 的「实体记忆 + 镜序调度」，但代码没放

- **链接 / 日期**：[arXiv 2606.20799](https://arxiv.org/abs/2606.20799)，v1 **2026-06-18** / v3 **2026-07-20**；**本轮实查未找到公开代码仓**（只有 arxiv + 论文内 GroundBench）。机构未在页面披露。
- **洞察**：不训练、不改模型，纯 agentic——**在线**从「已接受的镜头」里建实体级视觉记忆，按「这个镜头将来当参考有多有用」**调度生成顺序**，对生成视频里的实体做 grounding + 可靠性校验后才入库，每镜生成前检索合适实体参考。附 GroundBench 诊断基准（隔离受控挑战维度量实体级一致性）。
- **影响 Nomi 哪个决策**：这是对 Nomi「参考图=实体记忆」路线（08-23 雷达 EntityBench 已立的方向）的**架构级补强**——它多给了一条 Nomi 现在没有的洞见：**镜头的生成顺序不该等于剧本顺序，而应按「谁能当好后续参考」排**（先生成能立住主角/场景的镜头，再生成依赖它们的镜头）。这可以变成拆镜头规划师 / `arrange_storyboard` 的一条排序策略。代码没放，**当设计教训用，别等它跑**。

### CANVAS：连续性要「显式规划」，不能指望模型自发保持

- **链接 / 日期**：[arXiv 2604.13452](https://arxiv.org/abs/2604.13452)，v1 **2026-04-15**；页面未见公开代码/机构。
- **洞察**：多 agent **显式规划**多镜连续性，三条腿——角色连续 / 持久背景锚点 / 位置感知的场景规划。相对 baseline：背景连续 **+21.6%**、角色一致 **+9.6%**、道具一致 **+7.6%**（在 ST-BENCH / ViStoryBench / 自建 HardContinuityBench 上）。
- **影响 Nomi 哪个决策**：论据支撑「Nomi 该在 storyboard 层显式维护**背景/位置锚点**，而不只锁角色身份」——当前 Nomi 的一致性心智几乎全压在 character_ref 上，背景/道具/地点复现是盲区。这也和 08-23 雷达 EntityBench「实体 = 角色 + 道具 + 场景」的结论互相印证：**该把"地点/道具"也当一等实体存进记忆**，落到设定卡 / storyboard 数据结构。代码未放，取思路。

## 🔵 对标基准

### CineDance / CineBench：多镜「画面+声音一起出」的 6 维人对齐评测

- **链接 / 日期**：[arXiv 2606.09639](https://arxiv.org/abs/2606.09639)，v1 **2026-06-08** / v2 06-11；[项目页](https://aliothchen.github.io/projects/CineDance/)、**代码仓已建** [github.com/AliothChen/CineDance](https://github.com/AliothChen/CineDance)，**数据集第一季度已于 2026-07-22 放出**（gated access；推理码/权重/训练码/全量数据陆续放）。
- **怎么接进 eval 体系**：这是目前少见的**多镜 + 长片 + 音画联合**评测（CineDance-1M 平均 92.8s / 24.2 连续镜头；CineBench 六维人对齐指标）。Nomi 的 pipeline 末端正是「先出画、再合 BGM/配音」，**音画对齐**一直是没量化过的盲区。**接法**：把 CineBench 的六维当 Nomi「导出前整片体检」的一层维度，尤其**音画对齐 + 多镜时序连贯**两项——补上 08-23 雷达 VBench（单镜画质）和 DirectorBench（分维诊断）都没覆盖的音画一致 lane。注意数据集 gated，先用它的**指标定义**，数据申请到再跑全量。
