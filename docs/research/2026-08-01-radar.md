## 一句话总结

本轮 **🟢 4 / 🟡 8 / 🔵 4**，筛掉 61 篇噪音。行业信号明显收敛成两个共识：**① 跨镜一致性的解法正在从「多挂参考图」走向「显式实体级记忆 + 按相关性检索」**（GroundShot / EntityBench / CausalCine 三家独立收敛，EntityBench 给出效应量 d≈2.3）；**② 唇形同步第一次出现「代码+权重+ComfyUI 插件」三全的可跑候选**——Nomi 标了很久的 lipsync 缺口，现在有零自研试跑路径了。

**本轮最该动的 1-2 件事：**

1. **零成本试跑 SoulX-FlashHead，验「口播镜头」能不能成为新镜型。** Nomi 已有本地 ComfyUI 通道（`electron/comfyuiProbe.ts` + `comfyuiLocal*.integration.test.ts` 一族），装社区插件 `ComfyUI_RH_FlashHead` 即可用「每镜首帧图 + 豆包 TTS 音轨 → 说话镜头」真跑验质量，零自研先看效果再决定是否做成一等镜型；V2V 后处理形态的备选 Lip Forcing 权重也已放 HF。
2. **跨镜身份的下一步 = 实体注册表。** Nomi 已有定妆图、参考槽解析（`src/workbench/generationCanvas/agent/referenceEdgeCapability.ts` 一族）和 shotVerify（`src/workbench/generationCanvas/agent/gatherShotVerifyInputs.ts`），缺的正是三篇论文共同指认的那一环：**验证通过的成片实体登记入册，后续镜按内容相关性（同角色/同场景）检索复用为参考，而不是默认只接力上一镜**。EntityBench 有码有数据，可先当尺子量出 Nomi 基线再动手。

## 🟢 可落地

### 1. SoulX-FlashHead — 参考图+音频→实时口播视频，ComfyUI 插件现成
- [arXiv 2602.07449](https://arxiv.org/abs/2602.07449)（2026-02）· Soul AI Lab · [官方仓](https://github.com/Soul-AILab/SoulX-FlashHead)已放推理码+1.3B 权重（HF Space demo），社区已有 [ComfyUI_RH_FlashHead](https://github.com/HM-RunningHub/ComfyUI_RH_FlashHead) 插件；Lite 档单张 4090 96FPS。
- **洞察**：无限长流式 talking head，蒸馏抗身份漂移——补 lipsync 缺口的「新镜型」路线（不改已有视频，直接生成说话镜头）。
- **落地**：本地 ComfyUI 通道装插件即真跑，零自研验质量；成了再考虑做成一等镜型入画布。

### 2. Lip Forcing — 已有成片 + 音频 → 改嘴型（V2V 后处理）
- [arXiv 2606.11180](https://arxiv.org/abs/2606.11180)（2026-06）· KAIST AI（Seungryong Kim 组）· [项目页](https://cvlab-kaist.github.io/LipForcing/)标 Code Released + HF checkpoints；1.3B 学生 2 步去噪 31FPS。
- **洞察**：首个自回归扩散 V2V 唇形同步，形态与 Nomi 缺口精确同构：镜头成片 + TTS 音轨进、配好嘴的片段出，不动 decompose-stitch 链路。
- **落地**：候选「唇形同步」后处理节点；先离线跑通权重再评估是否包进本地 provider。与上一条二选一或互补（新镜型 vs 后处理）。

### 3. GroundShot — 实体级视觉记忆 + 镜头排程（training-free、model-agnostic）
- [arXiv 2606.20799](https://arxiv.org/abs/2606.20799)(2026-06，v3 已迭代到 07)· 无代码仓，但机制是 agentic 编排层的，可在 Nomi 产线原生实现。
- **洞察**：从已生成镜头建「实体级视觉记忆」→ 排程 → 生成后 grounding 验证 → 按镜检索实体参考，与 Nomi 架构同构；自带 GroundBench。
- **落地**：拆镜头→首帧链路加「实体注册表 + 验证通过才复用为参考」，挂在 shotVerify 与参考槽解析层之间（文件见顶部第 2 件事）。**诚实边界**：无码，照抄机制不是照抄代码。

### 4. StreamEdit — training-free 局部改一镜，不整镜重掷
- [arXiv 2605.21466](https://arxiv.org/abs/2605.21466)（2026-05）· ECCV 2026 · UBC（Renjie Liao 组）· 项目页称代码已放。
- **洞察**：少步流式模型上 prompt 驱动编辑已有视频（attention 桥接源视频），对应时间轴「这一镜只想改一处却要整镜重新花额度」的真实摩擦。
- **落地**：本地编辑车道候选（ComfyUI 流式底座）。**接前按 R5 抓其代码实测底座模型要求，勿凭本条落地**。

## 🟡 架构教训

1. **Co-Director**（[2604.24842](https://arxiv.org/abs/2604.24842)，2026-04，工业团队+GenAD-Bench，无码）：点名 agentic 产线「逐镜独立写提示→语义漂移+级联失败」；解法=全局候选方向评分/回退 + 局部多模态自纠环。**影响**：Nomi 的 shotVerify 是「局部环」，缺「全局层」——整片层面的方向评分与回退，可作 evals/loop 状态机的上一层设计参考。
2. **ShotStream**（[2603.25746](https://arxiv.org/abs/2603.25746)，2026-03，可灵团队，[码+权重全放](https://github.com/KlingAIResearch/ShotStream) 174★，ECCV 2026）：因果「下一镜」生成 + 双缓存记忆。**教训**：接力别只带上一镜尾帧，要带一份跨镜「全局条件帧」集合；也可当本地可跑对标。
3. **CausalCine**（[2605.12496](https://arxiv.org/abs/2605.12496)，2026-05，强阵容，无码需训练）：按注意力相关性（非时间邻近）检索历史镜上下文。**教训**：组第 N 镜参考时按内容相关性选历史镜的帧，Nomi 参考解析层可直接吃这条。
4. **FreeStory**（[2606.25079](https://arxiv.org/abs/2606.25079)，2026-06，项目页有）：代词/间接指称是身份断链的隐性杀手。**教训**：LLM 写每镜提示时把「他/她」强制解析为角色规范描述并挂定妆参考——提示词层今天就能抄；注意力注入部分托管 API 走不通。
5. **ActCam**（[2605.06667](https://arxiv.org/abs/2605.06667)，2026-05，Kinetix+MBZUAI+Oxford，[项目页](https://elkhomar.github.io/actcam/)demo 丰富，码标 soon）：零训练把 depth+pose 渲染成条件喂 i2v，两阶段调度（早期定结构、后期撤条件提细节）。**教训**：导演台离屏渲染本就能出 depth/pose 图，等码放出即升🟢接本地 WAN 车道。
6. **TriMotion**（[2606.20774](https://arxiv.org/abs/2606.20774)，2026-06，ECCV 2026，无码需训练）：参考视频/位姿轨迹/文本三种运镜输入同空间等价。**教训**：不接；佐证 Nomi「3D 轨迹→参考视频 + customMove 文本」双入口路线成立。
7. **Goodbye Drift**（[2605.20476](https://arxiv.org/abs/2605.20476)，2026-05，training-free，Wan2.1+VACE 上验证，无码）：顺序尾帧续生的漂移必然复利；树状「先稀疏锚帧、锚间填充」把漂移变有界。**教训**：长镜头别叠多段尾帧接力，改「先出多张锚帧图（首帧机制现成）再逐段生成」。
8. **3R**（[2603.01509](https://arxiv.org/abs/2603.01509)，2026-03，ICLR workshop，无码弱信号）：检索式扩写糙 prompt + 多抽一 VLM 排序。**教训**：配方可抄进 `NodePromptOptimizer.tsx`（Nomi 已有 LLM+VLM 通道，不需要其代码）；勿当 SOTA 引用。

## 🔵 对标基准

1. **EntityBench**（[2605.15199](https://arxiv.org/abs/2605.15199)，2026-05，[码+数据](https://github.com/Catherine-R-He/EntityBench)，Rice）：140 集/2491 镜跨镜实体一致性考卷，三支柱评测+保真门；其基线 EntityMem（每实体持久记忆）角色保真 d≈+2.33，为定妆图路线背书。**接法**：Nomi 全链跑 easy/medium 档，量化跨镜身份相对 20 家模型的位置。
2. **MSAVBench**（[2605.20183](https://arxiv.org/abs/2605.20183)，2026-05，ali-vilab，[码已放](https://github.com/ali-vilab/MSAVBench)）：VLM judge 用「逐实例 rubric + 工具化取证 + 自纠」而非裸打分，Spearman 91.5% 且换 judge 底座结论稳。**接法**：judge 设计搬进 evals lane——现有 VLM judge 加 rubric 化与抽帧取证两步，无需换模型。
3. **MSVBench**（[2602.23969](https://arxiv.org/abs/2602.23969)，2026-02，未见公开码）：20 家模型实测「视觉插值器不是世界模型」；评测轨迹蒸馏进 Qwen3-VL-4B 即达人对齐 judge。**接法**：暂不能跑分；「小 VLM 蒸馏本地 judge」配方记入 eval 长期路线（本地优先=零 API 费 judge）。
4. **SkyReels-V4**（[2602.21818](https://arxiv.org/abs/2602.21818)，2026-02，昆仑万维，权重 limited preview 但 V1-V3 全有开源前科）：生成/续镜/编辑/inpaint 统一成同一报文的不同掩码。**接法**：盯权重/API 放出；开放即是接力续镜候选供应商，接入按 R5 逐项对账。
