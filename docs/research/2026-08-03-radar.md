## 一句话总结

本轮 **🟢 1 / 🟡 2 / 🔵 1**——增量小但不是零。唯一 🟢 落在 prompt 方向：**结构化语言（语义+几何标注）而非更长的散文才是文本条件的有效成分**，这条第一次有了 scaling-law 级证据，而 Nomi 优化器节点的指令恰好还是「补充光线、构图、风格、画质等要点」这种散文式；另外三篇合成一条主线：**VLM 单趟打分正在被系统性证伪**（多人接触镜头上 checklist 饱和 >0.95 而几何尺只有 0.65），评审要拆成「提假设→按视觉证据裁决」两段。

**本轮最该动的两件事：**

1. **把优化器节点的改写指令从「散文式加细节」换成「结构化语义/几何标注」，先过 evals A/B 门再转正。** [Scaling Properties](https://arxiv.org/abs/2607.29679)（07-31）量出：converged loss 随 prompt 里**结构化信息量**线性/幂律下降，与 token 数无关——即「写更多」无效、「写结构」有效。Nomi 落点：`src/i18n/locales/generationCommon.ts` 的 `optimizer.imageDetails/videoDetails`（中英两处）现在只说「补充光线、构图、风格、画质等要点」，改成引导「主体—属性—空间关系—镜头几何」的结构化标注式改写；**但证据出自他们自训模型，黑盒供应商是否同样受益要先用 `evals/lib/vbenchRubric.mjs` 的 alignment 维度对真实供应商跑一轮新旧指令 A/B，赢了才当默认**。改动本身一小时级，A/B 用现成 eval 基建。
2. **给 VLM 判官补「验证段」，并加多人接触难例——三篇同指一个洞。** [MPIE-Bench](https://arxiv.org/abs/2607.27616) 实测：拥抱/搀扶/扭打类多人编辑图，VLM checklist 打 >0.95，而网格重建的解剖/接触尺只有 0.65/0.72 且更贴人类判断——**Nomi `vbenchRubric.mjs` 的 imaging 维（「无肢体崩坏」锚点）在多人接触镜头上大概率也在虚高**；[EVR](https://arxiv.org/abs/2607.29025) 给出可抄的模式：按维度让 Evaluator 提多个假设、Verifier 逐条对视觉证据裁决，替代单趟长推理（易幻觉）或单趟短判（推不动）。落点：`vbenchRubric.mjs` / `src/workbench/generationCanvas/agent/shotVerifyJudge.ts` 的判官提示词加第二段「逐维列证据再裁决」，并往 eval 样例集加 3-5 个双人接触镜头难例人工抽查对齐。与昨天 MEDit-Bench「LLM 裁判位置偏差」是同一条主线，可合并成一项 eval 加固交付。

## 🟢 可落地（这周/这月能直接进 Nomi）

### 1. Scaling Properties of Text Conditioning：文本条件的有效成分是「结构化语言」不是长度——优化器指令该照此重写

- **链接 / 日期**：[arXiv 2607.29679](https://arxiv.org/abs/2607.29679)，v1 **2026-07-31**；[代码](https://github.com/heheyas/context-scaling)（实测 56 stars、08-03 仍在推更）+ HF 模型集 + 在线 demo + 项目页，HF daily 23 赞。作者含 Haoqi Fan 等，CC BY 4.0。
- **一句话洞察**：diffusion loss 不随 prompt token 数 scale，但随 prompt 里**结构化语言量**（白盒 GPG 似然度量近线性、黑盒属性度量 ED 幂律）稳定下降；用图像的语义+几何标注构造结构化 prompt 能直接提升可扩散性。他们另外训了一个 prompter（SFT+冷启+verifier 门蒸馏）在组合/推理/世界知识 benchmark 上超全部开源模型。
- **怎么落**：训 prompter 那半 Nomi 用不上（黑盒供应商边界）；能落的是**改写指令的方向**——`generationCommon.ts` optimizer 块的 image/video details 提示从「补充光线、构图、风格、画质等要点」改成结构化标注引导（主体及属性 / 空间关系 / 镜头几何 / 光线材质），`NodePromptOptimizer.tsx` 零改动。**转正前置门**：用 `evals/lib/vbenchRubric.mjs` alignment + imaging 两维对 2-3 家真实供应商各跑 10 条新旧指令对比，赢了才替换默认。
- **诚实边界**：scaling 结论量在他们自训 DiT 族上；黑盒供应商内部还有各自的 prompt 改写层，迁移收益必须 A/B 实证，不能拿论文分数直接宣称 Nomi 出图会变好。

## 🟡 架构教训（影响设计决策，非即插即用）

### 1. EVR：奖励/评审别让 MLLM 一趟打完——按维度「提假设 + 视觉证据裁决」两段走

- **链接 / 日期**：[arXiv 2607.29025](https://arxiv.org/abs/2607.29025)，v1 **2026-07-31**，HF daily 11 赞；未见官方代码，成熟度即到 🟡 为止。
- **一句话洞察**：多参考图编辑的 RL 奖励一直缺「多图关系约束」的可靠信号，根因是 MLLM 评审的两难——长推理易幻觉、短判断推不动。EVR 把评审拆成独立视觉维度，每维 Evaluator 提出多个假设、Verifier 逐条按具体视觉证据接受/驳回，得到细粒度可靠奖励；拿它微调 Qwen-Image-Edit 后一致性/和谐度对齐 NanoBanana。
- **影响 Nomi 哪个决策**：RL 微调那半在供应商边界外；**评审分解模式直接适用于 Nomi 全部 VLM 判官**——`evals/lib/vbenchRubric.mjs`（五维单趟 1-5 分）、`shotVerifyJudge.ts`（逐镜单趟判）、`evals/loop/semiObjective.mjs`（独立批评 agent）。改法是判官提示词加「先逐维列出可核对的视觉证据、再裁决」的第二段，不新增基建。与 08-02 MEDit-Bench 的「LLM 裁判位置偏差」、本轮 MPIE-Bench 的「checklist 饱和」共同构成「单趟 VLM 总分不可当真相源」的三连证据。
- **诚实边界**：论文场景是训练奖励不是离线 eval，两段式会加约一倍判官调用成本；Nomi 该在难例（多参考/多人）上先用，不必全量铺。

### 2. PhiZero：160 赞的世界模型也走「先推演过程、再渲染外观」——灰模先行的押注被基座层再度印证

- **链接 / 日期**：[arXiv 2607.28624](https://arxiv.org/abs/2607.28624)，v1 **2026-07-30**（昨天窗内、热度周末才起，本轮补报）；HF daily **160 赞**，为本窗最热；项目页 phi-zero.github.io，代码/权重未确认放出。Zhaoxiang Zhang / Tieniu Tan 团队（中科院自动化所系）。
- **一句话洞察**：不在像素空间隐式硬猜动态，而是自监督学出「physical language」（世界状态转移的紧凑离散表示），**先把未来推演成符号序列、再渲染成视频**（reason-then-render），声称支持动作条件模拟与 zero-shot 运动迁移。
- **影响 Nomi 哪个决策**：不改变任何行动（训练级、边界外），但它与 08-02 的 VideoCoCo（可执行灰模过程 → 生成重绘）在完全不同的技术栈上收敛到同一结论：**过程要先被显式表示、可检验，再交给渲染**。Nomi「3D 灰模 take → `referenceVideoUrls` → 生成」这条链的优先级判断得到基座层旁证——继续按 08-02 拍的两件事推进即可，不用为它新开活。
- **诚实边界**：abstract 级证据；代码未放、能力边界未独立核验，别引它宣称任何具体指标。

## 🔵 对标基准（接进 eval 体系自评 Nomi）

### MPIE-Bench：多人接触编辑上，VLM checklist 打 >0.95 而几何尺只有 0.65——「肢体崩坏」维正在虚高

- **链接 / 日期**：[arXiv 2607.27616](https://arxiv.org/abs/2607.27616)，v1 **2026-07-30**（昨窗漏报，HF daily 37 赞补捞）；数据/代码未确认放出。
- **一句话洞察**：把多个指定人物编辑进「拥抱/背抱/扭打」等接触动作时，融肢/多手/穿模是主流失败，但 VLM checklist 在 Interaction 维上饱和（>0.95）看不见这些错；他们用冻结的公开多人体网格重建导出两把新尺——Anatomy（重建人体能否解释全部人体质量）与 Interaction（穿透/表面距离是否符合指令的接触），十个编辑器上分别峰值仅 0.65 / 0.72，五人评审确认两尺比 zero-shot VLM 判官更贴人类。
- **怎么接进 Nomi eval**：① 直接可做的是**难例注入**——Nomi 多角色互动镜头（双人拥抱、递物、搀扶）正是用户高频翻车点，往 eval 样例集加 3-5 个 C2/C3 级接触案例，对这类案例的 `vbenchRubric.mjs` imaging 分强制人工抽查对齐，验证「饱和」是否在 Nomi 判官上复现；② 网格重建尺（SMPL 系）是重资产，数据/代码又未放，**不建议现在集成**，记为后续可选。主教训与 EVR 合并：多人接触镜头进「判官不可信名单」，直到判官加固过验证。
- **诚实边界**：论文对象是图像编辑不是视频生成；Nomi 的对应场景是多参考图出多人镜头，任务相近但不等价，饱和结论要在自家判官上复现后才能引用。
