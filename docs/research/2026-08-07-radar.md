## 一句话总结

本轮 **🟢 0 / 🟡 1 / 🔵 2**。没有足够成熟的新能力值得马上塞进产品；最有价值的是补齐两张“考卷”：**EntityBench 把跨镜一致性从“看起来像”拆成角色、物件、地点与重现间隔，MSAVBench 则把视频、音频、镜头、参考图分开评分**。这比再加一层泛化 VLM 总分更适合 Nomi。

**本轮最该动的两件事：**

1. 在现有逐镜验收旁增加一个最小“跨镜实体记忆”eval fixture：同一角色隔 1 / 5 / 10 镜重现，分别记录身份、服装、道具、场景是否保持。落点先放在 `src/workbench/generationCanvas/agent/shotVerifyJudge.ts` 与现有 eval harness，不改产品 UI。
2. 音频生成链进入实用阶段后，评测必须把画面、音频、镜头边界、参考遵循拆开，不能合成一个总分；先把 MSAVBench rubric 映射记入 eval 设计，不急着引入整套依赖。

## 🟡 架构教训

### ShotStream：长叙事的一致性记忆要区分“全局实体”与“当前镜头局部状态”

- **链接 / 日期**：[arXiv 2603.25746](https://arxiv.org/abs/2603.25746)，v1 **2026-03-26**；论文声明训练、推理代码与模型可用，成熟度高于仅有概念稿。
- **一句话洞察**：它用 global context cache 保留跨镜条件帧，用 local context cache 保留当前镜头帧，并显式标记两类上下文边界；同时用自生成历史训练来减轻逐镜误差累积。
- **影响 Nomi 哪个决策**：Nomi 的分镜 anchors 与单镜 prompt 不应混成一段不断膨胀的文本。长期角色/地点/道具进入跨镜锚点，当前动作/运镜留在单镜；生成后只把通过验收的实体状态回写长期记忆。对应现有 `StoryboardPlanEditor` / `storyboardPlan` 的 anchors 与 shots 分层，方向正确，无需引入模型内部 cache。
- **诚实边界**：核心收益来自模型训练与蒸馏，Nomi 无法照搬 16 FPS 或一致性指标；这里只采用“全局/局部记忆分层”的架构教训。

## 🔵 对标基准

### EntityBench：跨镜一致性必须按实体、重现距离和“先忠实再一致”来测

- **链接 / 日期**：[arXiv 2605.15199](https://arxiv.org/abs/2605.15199)，v1 **2026-05-14**；[官方代码与数据](https://github.com/Catherine-R-He/EntityBench)。140 个 episode、2,491 镜，最长 50 镜，覆盖角色、物件、地点与最长 48 镜的重现间隔。
- **一句话洞察**：现有系统的跨镜一致性会随实体重现间隔快速下降；论文先用 fidelity gate 判断实体有没有按要求出现，再计算跨镜一致性，避免“始终生成错但很一致”拿高分。显式 per-entity memory 是其基线中最有效的做法。
- **怎么接进 Nomi eval**：从官方数据抽 6-10 个短 episode，映射到 Nomi 的角色/道具/场景 anchors；在 `shotVerifyJudge.ts` 外增加 episode 级汇总，先判每镜忠实度，再按实体与间隔统计一致性。优先做 1 / 5 / 10 镜重现，不需要一次吞下 50 镜全量 benchmark。
- **诚实边界**：EntityMem 是生成系统基线，不适合直接塞进 Nomi；可复用的是数据组织、fidelity gate 与跨镜统计方式。

### MSAVBench：多镜音视频不能用一个总分遮住导演控制和同步失败

- **链接 / 日期**：[arXiv 2605.20183](https://arxiv.org/abs/2605.20183)，v1 **2026-05-19**、v4 **2026-06-24**；[官方代码](https://github.com/ali-vilab/MSAVBench)。覆盖最多 15 镜，按视频、音频、镜头、参考四组指标评估，并报告与人类判断 91.5% 的 Spearman 相关。
- **一句话洞察**：当前系统最弱的仍是导演级控制与细粒度音画同步；模块化/agentic 流程并不天然更差，但需要按证据拆维度评估，而不是让一个 VLM 直接报总分。
- **怎么接进 Nomi eval**：把现有画面验收保留为 video/reference 两组；音频节点成熟后另加 speech/music/effect 与同步；镜头切分用工具证据而非只问 VLM。落点从 `evals/` 的 rubric 与 `shotVerifyJudge.ts` 开始，先做 schema 映射，不引入整套模型依赖。
- **诚实边界**：全套评测较重且部分指标依赖外部模型；短期只吸收分组 rubric 和失败样例，不把论文分数包装成 Nomi 指标。
