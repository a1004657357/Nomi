## 一句话总结

本轮 **🟢 2 / 🟡 3 / 🔵 3**。出现了两件可立刻动手的事：GroundShot 的 training-free 实体调度思路可直接固化进 `referenceAncestors.ts` 的接口契约；WorldJen+FilmBench 让 Nomi 的 eval 体系终于有了对电影级多镜叙事评分的外部考卷。

**本轮最该动的两件事：**

1. **把 GroundShot 的"质量感知调度 + 实体记忆验收门"写成 `referenceAncestors.ts` 的不变量**：先生成参考价值最高的镜头，只有通过验收（`shotVerify.ts`）的帧才写入实体记忆，下游镜头按实体匹配度检索，而非按叙事顺序平铺。这是 training-free 的，不改底层模型，可在现有 canvas agent 架构上直接实施。
2. **用 WorldJen 的 16 维 Likert 评审 + FilmBench 的多镜叙事维度给 `evals/lib/judge.mjs` 补一层电影级 rubric**：WorldJen 代码和数据集已公开，FilmBench 也已公开；把两者覆盖"动态美感 + 多镜连贯"的维度映射进 Nomi 逐镜验收的 analytic rubric，可量化当前生成离专业标准还差多少。

## 🟢 可落地

### GroundShot：training-free 实体级视觉记忆 + 质量感知调度

- **链接 / 日期**：[arXiv 2606.20799](https://arxiv.org/abs/2606.20799)，v1 **2026-06-18**；浙江大学、复旦大学、百度。目前未找到独立 GitHub 仓，但论文 HTML 版详述算法可直接参照实现。
- **一句话洞察**：它把多镜生成的制作顺序从叙事顺序中解耦——先生成"参考价值最高"的镜头（主体清晰、遮挡少），通过 grounding+验证后写入实体记忆，后续镜头按实体匹配度检索参考，从而让一致性上限不被最弱那帧拖垮。
- **落地点**：`src/workbench/generationCanvas/runner/referenceAncestors.ts` + `src/workbench/generationCanvas/agent/shotVerify.ts`。具体改法：在 `referenceAncestors.ts` 加"只有通过 `shotVerify` 的帧才能成为后续镜头的实体参考"的守门条件；在 canvas agent 排队逻辑中增加"优先生成参考质量评分高的镜头"的调度钩子，不需要改底层 T2V 接口。
- **诚实边界**：论文的实体 grounding 依赖检测模型（SAM/DINO 类）；Nomi 当前阶段可先用 VLM 描述替代，而不上重型检测链；算法框架 training-free，供应商 API 边界内可行。

### 3R：RAG-based T2V Prompt 三段式优化，任意 T2V 无需训练

- **链接 / 日期**：[arXiv 2603.01509](https://arxiv.org/abs/2603.01509)，v1 **2026-03-02**；Algoverse AI。未找到公开 GitHub，但方法三段流程在论文中已明确描述，可参照实现。
- **一句话洞察**：Retrieval（从关系图检索语义相关修饰词）→ Refinement（闭环多信号反馈迭代优化 prompt）→ Ranking（排序多个候选提示），全程不改 T2V 模型权重，适配任意供应商 API，直接解决"用户输入糙→生成差"的摩擦。
- **落地点**：`src/workbench/api/promptLibraryApi.ts` + `src/workbench/promptLibrary/usePromptLibrary.ts`。具体改法：在 AI 优化节点里增加"检索 Nomi prompt 库中高质量历史 prompt 的修饰词片段 → 在提交生成前自动扩写 → 多候选排序"的三阶管道；Retrieval 步骤可直接复用已有 prompt 库作为知识库，Ranking 可用 `evals/lib/judge.mjs` 打分。
- **诚实边界**：论文无公开代码；Retrieval 阶段的关系图需要 Nomi 自建或用 embedding 近邻代替；闭环 Refinement 会增加每次生成前的 API 调用次数，需在 prompt 库入口做 budget 控制。

## 🟡 架构教训

### AniME：导演 agent + 专业子 agent + MCP 的全工作流编排教训

- **链接 / 日期**：[arXiv 2508.18781](https://arxiv.org/abs/2508.18781)，v1 **2025-08-26**；已收录 SIGGRAPH Asia 2025。未找到公开代码仓。
- **一句话洞察**：全局导演 agent 持有整段动画的记忆和进度，专业子 agent（分镜、角色设计、动画、音频）各自通过 MCP 调取控制条件——这和 Nomi 的 canvas multi-agent 架构高度同构；关键教训是"每个子 agent 只暴露自己的控制接口，导演 agent 不直接调底层模型"，职责边界越清晰，级联错误越少。
- **影响 Nomi 哪个决策**：`storyboardLauncher.ts` 与各子 agent 之间的接口设计——当前要防止 storyboard agent 直接操作生成参数（这是 Animator 子 agent 的职责）；导演层只应发出"这个镜头需要角色 A 在左侧、光源从右"等语义指令，而非直接拼 prompt 字符串。
- **诚实边界**：AniME 针对动漫制作，唇形同步依赖其内部音频模型；Nomi 只采用"职责边界 + 导演层只发语义指令"的架构教训。

### CoTriSyGen：闭环视觉-文本-记忆三方协同防止跨镜漂移

- **链接 / 日期**：[arXiv 2606.16184](https://arxiv.org/abs/2606.16184)，v1 **2026-06-15**；微软亚研院 + 中科大。未找到公开代码。
- **一句话洞察**：在每个镜头生成后，由 Analyzer 对照记忆评估候选关键帧是否与计划意图一致，不一致则触发局部重生成，而不是让错误继续传递给下一个镜头——这是"镜级验收 + 本地修正"的闭环。
- **影响 Nomi 哪个决策**：`shotVerify.ts` 的验收动作应能触发"对当前镜头重生成一次"而非直接标失败、让用户手动干预；闭环重试预算需在 `storyboardLoopBudget.ts` 里有上限，防止死循环。
- **诚实边界**：CoTriSyGen 的 Analyzer 利用其内部模型进行帧级语义匹配；Nomi 可用 VLM prompt 替代，精度会低，但逻辑框架可用。

### Camera Artist：递归分镜叙事 + 电影语言注入，镜间连续性强于扁平 prompt 列表

- **链接 / 日期**：[arXiv 2604.09195](https://arxiv.org/abs/2604.09195)，v1 **2026-04-10**；Haobo Hu 等。未找到公开代码。
- **一句话洞察**：不是给每个镜头单独写 prompt，而是递归生成分镜（当前镜头的 prompt 包含对上一镜头结尾状态的显式引用），叙事连续性来自 prompt 结构而非模型记忆。
- **影响 Nomi 哪个决策**：`storyboardPlan.ts` 生成每个镜头描述时，应显式携带"前一镜头结尾的主体位置/状态/光线"字段，而非每镜独立描述——这一结构改动低成本，对镜间叙事连贯有直接帮助。
- **诚实边界**：Camera Artist 的电影语言注入依赖其专用的 Cinematography Shot Agent 分类器；Nomi 只采用"镜头 prompt 显式携带前镜状态"的结构习惯。

## 🔵 对标基准

### WorldJen：16 维 Likert+VLM 评审，公开代码，ρ=1.000 人类对齐

- **链接 / 日期**：[arXiv 2605.03475](https://arxiv.org/abs/2605.03475)，v1 **2026-05-06**；moonmath.ai。**评估代码和 prompt 数据集已公开**（论文声明 released to support reproducible benchmarking）。
- **一句话洞察**：用"每个 prompt 专属、每个维度专属"的 Likert 问卷（10 题/维）让 VLM 打分，最终 Bradley-Terry 排名与人类判断 Spearman ρ=1.000——说明精心设计的 prompt-specific rubric 可完全替代人工打分，且可复现。
- **怎么接进 Nomi eval**：把 WorldJen 的 16 维（涵盖时序对齐、结构保真、语义一致等）映射到 `evals/lib/judge.mjs` 的 analytic rubric；用 WorldJen 的评估代码作为 Nomi 离线回归测试的评分引擎，先从 J3（首次生成成功）和 J4（参考图生成）各抽 2 个 fixture 跑通。
- **诚实边界**：WorldJen 的 47,160 次打分依赖强 VLM（Claude/GPT-4o 级），eval 运行成本会上升；先做最小可行接法（抽样 fixture），不全量跑。

### FilmBench：电影学院共研，T2V+R2V，公开数据集+代码，覆盖多镜连贯

- **链接 / 日期**：[arXiv 2607.24241](https://arxiv.org/abs/2607.24241)，v1 **2026-07-27**；北京电影学院 + 弧境数字共研。**数据集公开**（HuggingFace: skylenage/FilmBench）；**代码公开**（GitHub: Neo-yk/FilmOps）。
- **一句话洞察**：3 L1 轴 × 12 L2 组件 × 35+3 L3 子指标，同时评测 T2V 和 R2V（参考图到视频）；现有顶级模型在"动态美感 + 多镜连贯"两个维度上无一饱和——这正是 Nomi 最需要打的仗。
- **怎么接进 Nomi eval**：直接下载 FilmBench 数据集，把"多镜连贯"和"参考图一致性"子集接进 `evals/journeys/j4-reference.mjs`；R2V 评测维度可直接映射到 Nomi 首帧参考图→续帧的验收指标；代码已公开，落地阻力低。
- **诚实边界**：FilmBench 评分依赖其 FilmOps 评估工具链，需要先跑通 HuggingFace 数据集读取；R2V 子集对 Nomi 最直接，T2V 子集可延后。

### KathaTrace：叙事可视化语义轨迹崩塌诊断工具 + KathaBench-25K

- **链接 / 日期**：[arXiv 2607.01312](https://arxiv.org/abs/2607.01312)，v1 **2026-07-01**；Jamuna S. Murthy 等（机构小组），未找到公开代码仓。KathaBench-25K 数据集（5,000 故事 × 20,000 转场 × 28,712 问题）在论文中描述，公开状态待核实。
- **一句话洞察**：「语义轨迹差距（STG）= 纯文本可恢复性 − 纯图像可恢复性」——量化了"把剧本画成分镜图后，转场语义丢了多少"；现有生成器平均 STG=23.5，意味着有接近 1/4 的转场语义在可视化时消失了。
- **怎么接进 Nomi eval**：在 Nomi 的拆镜头规划师生成分镜描述之后，用 KathaTrace 的三态评测（文本/图像/图文）测一轮"用户提供剧本→Nomi 生成分镜→STG 多少"，直接量化 Nomi 拆镜头的叙事保真度；待核实代码/数据集公开后接入 `evals/lib/grading.mjs`。
- **诚实边界**：论文无公开代码链接，数据集公开状态待确认；先收作为方法参照，等仓库公开后再接。

|---|---|
| 跨镜角色身份一致 | GroundShot（🟢）提供 training-free 实体调度框架，可直接固化进 `referenceAncestors.ts` 接口契约。 |
| Agent 拆镜/导演编排 | AniME（🟡）提供"导演只发语义指令、子 agent 各守接口"的职责分离教训；Camera Artist（🟡）提示 prompt 结构应携带前镜状态。 |
| 运镜/机位/相机轨迹 | 2026 新稿（ActCam/Track2View）均依赖 3D 模型训练或供应商边界外的控制接口，本轮筛掉。 |

| 生成质量评测 | WorldJen（🔵）和 FilmBench（🔵）分别提供 16 维通用评测和电影级多镜专项考卷，均公开代码/数据集。 |
