# Nomi 论文雷达 · 2026-07-31

> **检索窗与方法**：按固定 8 个方向检索 2026 年近 6 个月 arXiv；在 WebSearch 之外复查 arXiv `cs.CV` 07-28～07-31 的提交列表，回论文页、项目页和官方仓核对日期、代码/数据、机构与可复现边界，并与 07-30 雷达去重。今天的新增主要是 07-29～07-30 提交、但昨日检索时尚未稳定进入索引的论文。

## 一句话总结

本轮 **🟢 1 / 🟡 2 / 🔵 1**。真正值得 Nomi 动的不是接一个新视频模型，而是补齐现有「3D 导演台 → 运镜参考视频 → 黑盒 provider」链路的两道结构保证：**送去花额度前，先确定性检查轨迹会不会穿模、遮住主体、丢失目标；送到生成模型时，让参考视频只负责“发生什么/怎么动”，提示词只负责“长什么样”**。CinemaTraj 和 VideoCoCo 分别给了这两道保证的直接证据；CineWeaver 再次证明跨镜一致性的根不在堆更多参考图，而在**按镜头精确路由参考 + 持久全局锚**。

**本轮最该动的两件事：**

1. **给 J6 运镜链补「零额度轨迹预检」，失败就别送去生成。** 在 `src/workbench/generationCanvas/nodes/scene3d/` 新建纯逻辑的 trajectory-quality helper（别继续塞进巨壳），复用 `scene3dMath.ts` / `scene3dPlayback.ts` 的真实回放位姿，对轨迹均匀采样并输出：越界/穿模率、主体遮挡率、主体入画覆盖率；把门接到 `evals/journeys/j6-camera-move.mjs`，再由 `create_camera_move` 出片前消费。现状已有安全画幅和 framing 回归，但没有布景碰撞/遮挡门；因此会把“几何上坏掉的运镜小片”照样喂给付费 provider。
2. **把「运动」和「外观」的提示职责彻底拆开。** Nomi 已有 `Scene3DTrajectoryCapture → cameraMoveVideo → referenceVideoUrls`，本质上已经是 VideoCoCo 的双引擎雏形。下一步不是再造 Blender，而是让 reference video 成为“动作/因果/机位的唯一真相”，生成提示词只补人物材质、灯光、风格，明确禁止重写运动；出片前用现有 VLM lane 校验“参考动作是否被保留”。这会直接减少当前同一句 prompt 同时描述外观与运镜、两种条件互相打架的失败。

## 🟢 可落地（这周/这月能直接进 Nomi）

### 1. CinemaTraj：原子运镜 + 碰撞/遮挡优化，把「能动」升级成「能安全地动」

- **链接 / 日期**：[arXiv 2607.26910](https://arxiv.org/abs/2607.26910)，2026-07-29；[项目页](https://cinematraj.github.io/)。ACM Multimedia 2026，TUM + Huawei Dresden Research Center。
- **火度 / 成熟度**：有完整项目页、方法/指标/消融和 ACM MM 录用信息；**代码仍是 coming soon**，所以不能照仓接入。但 Nomi 所需的不是它的 RGB-D 重建，而是可在现有显式 3D 状态上直接复现的轨迹质量门。
- **一句话洞察**：LLM 先把人话拆成 orbit / dolly / crane / pan / tilt / zoom / arc 等原子运镜，再只优化不破坏镜头语义的自由参数；轨迹质量不能只看“像不像运镜”，还要同时看 **Collision Rate、Occlusion Rate、Object Coverage**。其消融中，拿 3DGS 密度当实体几何会把碰撞率推到 0.557，而显式 SDF 路径是 0.056；说明“看着有场景”不等于“拥有可碰撞的几何”。
- **落到 Nomi 哪里 / 怎么改**：
  - `cameraMoveBuilder.ts` 已有 13 招语义运镜、`scene3dTypes.ts` 已有对象/相机/轨迹显式状态，原子词表这半边已经具备，不应另起一套。
  - 在 scene3d 子系统新增纯函数 quality helper：沿真实 spline/绑定采样相机位姿；先用对象的显式 geometry/prop bounds 做 AABB/包围体碰撞与相机→主体 ray 遮挡；投影主体包围体算入画覆盖。无需先上论文的 RGB-D/SDF 重建。
  - 把结果接到 `evals/journeys/j6-camera-move.mjs`：免费层必须先过 collision / occlusion / coverage，再进入现有「渲 MP4 → 真生成 → VLM」额度门。用户体验是坏轨迹在本地立刻被拦住并给出“哪里穿了/谁被挡了”，而不是花完额度才看见废片。
- **诚实边界**：CinemaTraj 只验证静态 3D 场景和单条连续轨迹；它明确未解决移动演员、180° 规则、正反打与视线连续。Nomi 第一版只应做**静态布景 + 当前主体位置**的确定性预检，不要把它包装成完整电影语法。

## 🟡 架构教训（影响设计决策，非即插即用）

### 1. VideoCoCo：可执行灰模草稿先锁过程，生成模型只负责变漂亮

- **链接 / 日期**：[arXiv 2607.27380](https://arxiv.org/abs/2607.27380)，2026-07-29；[官方仓](https://github.com/micky-li-hd/VideoCoCo)。
- **火度 / 成熟度**：CUHK / USTC / SCUT / HKU / NTU / PKU / SJTU / CMU / THU 等联合工作；论文发布两天时官方仓约 **4 stars / 2 forks**，已放 5 个 agent skills、8 个手检样例、推理 patch，模型权重仍在上传。代码和格式可读，但完整 3K 数据与训练栈不是 Nomi 可直接吞的产品依赖。
- **一句话洞察**：文本把完整时空过程压成一句话，生成模型既要猜“发生什么”又要猜“长什么样”，论文称之为 **Causal Opacity**。VideoCoCo 让 code agent 先产可执行 Blender 程序，渲一条每帧都确定的白模视频，再让视频编辑模型只做外观实现；PhyGenBench 0.475→0.558、VBench-2.0 52.18→77.88。关键不是 Blender，而是**过程与外观分责**。
- **影响 Nomi 哪个决策**：
  - Nomi 当前 `Scene3DTrajectoryCapture → cameraMoveVideo → referenceVideoUrls` 已经是同构的本地草稿引擎；不要推倒重做，也不要引入第二套 Blender 产品路径（P1）。
  - `create_camera_move` / 下游生成提示应形成单一契约：参考视频定义动作、时序、机位；文本只定义人物、材质、灯光、风格，并明确“不得重写参考运动”。这正好落在当前运镜参考注入与 prompt 组装的交界处。
  - 论文也给出反证：通用现成 editor 会忽略白模动作或与之冲突，作者必须用 3K triplets 适配 OmniWeaving。因此 Nomi 不能仅凭“provider 支持 video_ref”就宣称保真，必须保留现有真生成 + VLM 运动核验，并按模型档案实测哪些 provider 真能守住参考运动。

### 2. CineWeaver：跨镜一致性要「按镜头路由参考」，全局风格只走小型锚记忆

- **链接 / 日期**：[arXiv 2607.26529](https://arxiv.org/abs/2607.26529)，2026-07-29；[项目页](https://cineweaver.github.io/)；IJCV 2026，上海交大 + 中国电信 TeleAI。
- **火度 / 成熟度**：有 39～90 秒多镜 demo 和完整方法页，**代码仍是 code soon**。方法不训练新权重，但要改 Wan2.1 / Phantom 的 positional encoding、attention mask 与 VAE decode，Nomi 的黑盒 provider 拿不到这些内部，因此不能误写成即插能力。
- **一句话洞察**：它把三件事拆开：gap frame / masked attention 负责制造真实切镜；**shot-wise reference routing** 让人物/场景参考只进入指定镜头，避免串镜；小型 **anchor memory** 只传播全局灯光、调色、风格。长片稳定不是“所有参考喂给所有镜头”，而是**局部身份绑定 + 全局少量共享**。
- **影响 Nomi 哪个决策**：
  - Nomi 外部编排层虽不能改 attention，但可以做同构约束：每条 reference edge 必须带实体/镜头角色，生成每镜时只收本镜需要的角色/场景参考；不要把整项目参考图池无差别塞给 provider。
  - 全局共享只保留一个项目级 style anchor / canonical entity anchor；与 07-30 GroundShot 的“最好的一次出现做 canonical”合并成同一个项目记忆，不另起并行版。
  - verify 时增加“参考是否串镜”的负向检查：本镜不该出现的角色/场景也要判错。RefCaptioner 同日提出的 reference selection / phrase binding / distractor rejection 进一步说明，**拒绝错误参考**与“选对参考”同等重要，但其代码/模型目前仍是 coming soon，先不进主清单。

## 🔵 对标基准（接进 eval 体系自评 Nomi）

### 1. MEDit-Bench：评「用户想表达什么」，不是只评剪得像不像摘要

- **链接 / 日期**：[arXiv 2607.25300](https://arxiv.org/abs/2607.25300)，2026-07-28；[项目页与数据](https://ogatakatsuya.github.io/medit-bench/)。大阪大学 + CyberAgent。
- **火度 / 成熟度**：60 条 7–18 分钟长视频、180 个编辑意图、540 条专业剪辑，Hugging Face 数据已开放；训练/评测代码要等录用后发布。数据和指标现在可用，代码成熟度未过线。
- **一句话洞察**：同一素材换一个“我要传达的意思”，专业剪辑选的镜头会大幅变化（跨 message F1 仅 0.15）；所以编辑不是挑“最精彩片段”，而是围绕意图组织上下文。它还发现视频 LLM judge 有严重位置偏差：交换 A/B 顺序可造成 **35.4 个百分点**摆动，与人类偏好一致性只有 Cohen’s κ=0.18。
- **怎么接进 Nomi eval**：
  - 等 Nomi 的时间轴 agent 真正开始做“从已有素材自动组片”时，在 `evals/loop/` 建 editing lane，先抽 MEDit-Bench 的 Blender Studio 可复现子集，输入“素材 + 用户想表达的 message”，输出 cut timestamps。
  - 指标用 union coverage（mIoU）+ one-to-one cut F1 两条，不能只看覆盖率；论文消融显示只看 coverage 会塌成约 1.8 个“粗长段”，而人类平均 11.5 cuts。
  - 任何 A/B VLM 评审必须双顺序运行并单列人评校准，不能把单次 judge 偏好当真相。这个教训也应回灌 Nomi 现有视觉 eval，而不只用于未来编辑器。
- **诚实边界**：它只评已有长素材的 cut-only 重组，不评 Nomi 当前的逐镜生成、转场特效或音频编排；所以是未来 timeline lane 的外部考卷，不是今天的产品功能。

| 方向 | 2026-07-31 增量结论 |
|---|---|
| 1. 跨镜角色身份一致 | CineWeaver（🟡）给出「按镜头路由参考 + 全局 anchor memory」；RefCaptioner / MRVBench 进一步覆盖多参考绑定与 distractor rejection，但官方仓只有 coming soon、1 star，先观察。 |
| 2. Agent 拆镜头/导演编排 | VideoCoCo（🟡）用可执行时空草稿消除“文本计划不可执行/只给稀疏关键帧”的因果黑箱；其 agent skills 可读，但第二引擎依赖专门适配模型。 |
| 3. 运镜/机位/相机轨迹 | CinemaTraj（🟢）可直接迁移 collision / occlusion / coverage 本地预检；TARS（2607.28261，07-30）展示文本控制景别、视角、第一/第三人称重拍，但仓库目前只有 README、需自训练，未过主清单成熟度线。 |
| 4. 多镜叙事连贯 / 转场 | CineWeaver 证明切镜与连续运动在模型内部是相反约束，要显式断开 continuity；黑盒 Nomi 侧的可迁移部分是镜级独立生成、参考精确路由与 canonical anchor。 |
| 5. 生成质量评测 / benchmark | CinemaTraj 提供运镜几何三指标；MEDit-Bench（🔵）提供 message-conditioned cut coverage + cut F1，并给出 LLM judge 位置偏差的强反例。 |
| 6. Prompt 优化 / 结构化改写 | VideoCoCo 明确“参考视频管运动、文本管外观”的 prompt 职责分离；VIPE（2607.25537）针对的是视频模型**理解/推理**前的视觉改写，不是生成 prompt，筛掉。 |
| 7. 音频 / 唇形同步 / TTS | Ripple（2607.26818）是流式音视频生成模型内部架构，无黑盒 provider / 本地编排可落点；本轮无过线新增。 |
| 8. 视频编辑 / 抽帧接力 / inpaint | MEDit-Bench（🔵）补 message-driven 剪辑考卷；TARS 是重拍模型而非编辑编排能力，暂不接。 |

## 上轮 vs 本轮 diff

- **新增（07-30 雷达未收，本轮进正文）**：CinemaTraj（🟢）、VideoCoCo（🟡）、CineWeaver（🟡）、MEDit-Bench（🔵）。
- **过期方向：无。** 07-30 的 GroundShot「canonical 首现」与本轮 CineWeaver「shot routing + anchor memory」互相加强，应合并为一个项目级 reference memory，而不是两个功能。
- **判断变化**：昨天结论是“先建最优身份锚、评中间产物”；今天把下一层补齐——**中间产物必须是可执行且可预检的时空草稿，进入生成模型前要把参考职责严格路由**。这让 Nomi 现有 3D 导演台从“参考素材生成器”升级为真正的过程控制层。
- **本轮筛除约 15 篇噪音**：包括只改模型内部 attention/频谱、无黑盒接入面的 FreqForcing / TPD / CineWeaver 全量实现；只有 README 或 coming soon 的 TARS / RefCaptioner（保留方向注记）；偏视频理解而非生成的 VIPE / ObjectStream / VisualRouter；以及需训练新 backbone、与 Nomi solo/provider 边界不符的 PhiZero / Chimera / Ripple 等。
