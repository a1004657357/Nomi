## 一句话总结

本轮 **🟢 0 / 🟡 2 / 🔵 2**。没有「本周能直接接进 provider 编排层」的黑盒即插能力（跨镜身份的新方案仍集中在 training-free 但需操作模型内部 latent / attention，落不到 Nomi 的黑盒 provider）。但捞到 **4 条真正新增、对 Nomi 架构与 eval 直接有价值**的工作：GroundShot 把「先锚定最好的那次首现、按参考价值调度生成顺序」讲成方法论，正是 Nomi `gatherShotVerifyInputs` 现在**没做**的那一半；VERTIGO 用「渲染预览 → VLM 按提示词打分 → 把「角色出画率」从 38% 压到近 0」验证了 Nomi 站位观察器该显式查构图/出画；VideoWeaver（**有代码**）用 agent-as-judge 评「执行轨迹 + 中间产物」，恰好对得上 Nomi decompose-stitch 产出的 script/storyboard/keyframe 中间件；KathaTrace（07-01，最新）给了「转场语义是否可从图/文恢复」的可迁移度量。

**本轮最该动的两件事：**

1. **给 Nomi 的镜级 verify / 身份锚补上「首现质量门 + 按参考价值调度」（借 GroundShot 思路）。** 现状 `gatherShotVerifyInputs.ts` 用 `shotIndex-1` 当连贯对照、按**编号顺序**逐镜校验；GroundShot 指出**观众拿每次再现去比「第一次清晰出现」，那次的画质就是整段一致性的天花板**。落法：身份锚不应恒取「上一镜」，而应取「该实体质量最高、已验收通过的那次出现」作为 canonical 参考并在设定卡里保护它；批量生成时把「最可能当好参考」的镜头优先生成。这是把已存在的 verify 骨架从「顺序比对」升级成「锚定最优首现」，纯编排层改动，不碰 provider。

2. **给站位/eval lane 补一个「构图 / 角色出画」客观信号（借 VERTIGO）。** `evals/loop/poseLane.mjs` 现在免费层只查「落地 + 结构断言」，形状对不对留给 VLM。VERTIGO 的核心可迁移点：**渲染 2D 预览 → 用 VLM 按提示词打分，专门盯「角色是否出画 / 构图是否达意」**，并实测把出画率 38%→~0%。Nomi 已有 3D 站位离屏预览 + VLM gated 打分基建，只需在 `poseLane` / 站位观察器加一条「主体是否在画内、构图是否符合镜头意图」的判据，不需要它的 DPO 训练。

## 🟡 架构教训（影响设计决策，非即插即用）

### 1. GroundShot：训练无关、模型无关的实体接地多镜生成 —— 「首现即天花板」

- **链接 / 日期**：[arXiv 2606.20799](https://arxiv.org/abs/2606.20799)，v1 2026-06-18，**v3 2026-07-20**（本轮新增，07-29 雷达未收）。作者 Yixuan Lai / Tianjia Shao / Jingdong Wang 等，cs.CV。
- **火度**：**无官方代码仓 / 项目页**（仅 arXiv PDF/HTML + 第三方发现工具入口）。很新、方法自洽，但成熟度以「有 repo」衡量尚未过线 → 定 🟡 而非 🟢。
- **一句话洞察**：观众判一致性是拿每次再现去比**第一次清晰出现**，那次的画质就是整段一致性天花板；于是它 online 从已验收镜头建**实体级视觉记忆**，按「当参考的价值」调度生成顺序、grounding + 校验后才入库、给 canonical 参考加保护、每镜生成前检索最合适参考。附带 GroundBench 诊断基准。
- **影响 Nomi 哪个决策**：Nomi 的镜级 verify 骨架（`src/workbench/generationCanvas/agent/gatherShotVerifyInputs.ts`）现在把「身份锚 = 入参考边的源锚节点」「连贯对照 = `shotIndex-1` 那一镜」，即**按编号顺序**逐镜比对。GroundShot 指出三处该改：① 身份锚不应恒是「上一镜」，而是「该实体质量最高、已通过的那次出现」（canonical）；② 那次 canonical 参考应在设定卡 / `CharacterCardNode` 层被**保护**、后续默认复用；③ 批量生成顺序可**解耦叙事顺序与生产顺序**，先出最可能当好参考的镜头。全是 Nomi 已有 verify + 设定卡 + 批量编排（`shotVerifyRunner.ts` / 批量计划）之上的编排层增强，不碰 provider。**待核实**：GroundShot 无代码，具体调度打分公式需看 PDF 细化，落地前先在 `docs/plan` 记结构。

### 2. VERTIGO：相机轨迹的视觉偏好优化 —— 「渲染预览 → VLM 按提示词打分」

- **链接 / 日期**：[arXiv 2604.02467](https://arxiv.org/abs/2604.02467)，v1 2026-04-02，v3 2026-04-27。作者上海大学 / 上海电影学院 + École Polytechnique；**有项目页 vertigo.magic-lab.tech**（未见公开代码仓）。
- **火度**：有项目页 + 被 RL-for-video-generation 综述收录（base = Qwen2.5-VL，策略 DPO，benchmark LenScript）→ 传播度中上，比 GroundShot 热。
- **一句话洞察**：生成式相机缺「导演在环」的监督，导致轨迹在分布内但**构图差、角色出画、观感糟**；VERTIGO 用 Unity 渲 2D 预览 → 一个电影化微调的 VLM 按「cyclic semantic similarity」对齐预览与文本提示词打分 → 拿分做 DPO 后训练。实测**角色出画率 38%→~0%**，用户在构图/一致/贴合/美感上更偏好它。
- **影响 Nomi 哪个决策**：方法整体要 DPO 训练（Nomi 不做），但**可迁移的是评分回路而非训练**——Nomi 已有 3D 站位离屏预览 + `evals/loop/poseLane.mjs` 的 VLM gated 打分。当前 poseLane 免费层只查「落地 + 结构」，形状留 VLM 但**没专门盯构图 / 出画**。VERTIGO 证明「主体是否在画内、构图是否达镜头意图」是高杠杆的客观信号（一条判据把出画率打到近 0）。落法：在 `poseLane` / 站位观察器（`Scene3DEditor.tsx` 离屏渲染那条链）加「主体在画内 + 构图符合镜头意图」判据，喂进 semiObjective 层，零额外训练。

## 🔵 对标基准（接进 eval 体系自评 Nomi）

### 1. VideoWeaver：评测并进化 agentic 长视频生成的「技能」 —— 有代码，评执行轨迹+中间件

- **链接 / 日期**：[arXiv 2606.08091](https://arxiv.org/abs/2606.08091)，2026-06-06。**官方代码 github.com/JianhuiWei7/VideoWeaver**（本轮唯一有 repo 的新增）。
- **一句话洞察**：agent 把一句指令拆成自组合的工作流（composition skill），**agent-as-judge 检查「执行轨迹 + 最终视频」并把分数锚在证据（metadata + 中间产物）上，把过程指标与最终产物质量分开**；配技能进化算法。16 类任务 / 285 例，跨文/图/音/视参考。
- **怎么接进 eval 体系**：Nomi 就是 decompose-stitch，天然产出 script → storyboard → 逐镜首帧 → 逐镜 t2v 这串**中间件**，正是 VideoWeaver「不只评最终视频、评每一阶段」要的输入。接法：把 VideoWeaver 的「过程指标 vs 最终质量分离」思路接到 `evals/loop/`（`metrics.ts` + `driver.ts` 那条 lane），用它 285 例中与 Nomi 场景重合的子集做外部对标；「agent-as-judge 读中间产物」可复用 Nomi 现成的 `shotVerifyJudge.ts` 多模态判断链路，把评分对象从「单镜首帧」扩到「整条执行轨迹」。有 repo → 优先动。

### 2. KathaTrace：诊断视觉叙事的「语义轨迹坍缩」 —— 07 月最新，转场可恢复度

- **链接 / 日期**：[arXiv 2607.01312](https://arxiv.org/abs/2607.01312)，**2026-07-01**（本轮最新一条）。作者 Jamuna S. Murthy / Rajiv Ramnath（OSU 系）；无公开代码仓（PDF/HTML + 第三方入口）。
- **一句话洞察**：定义**「语义轨迹坍缩」= 一个场景如何接续上一个场景所需的转场含义丢失**（storyboard 看着连贯、但场景间的意义链断了）；提出 KathaBench-25K + generator-agnostic 诊断协议 + 度量 **Semantic Trajectory Gap（STG）= 纯文本可恢复度 − 纯图像可恢复度**，并给 Semantic Compass 做生成后修复探针。
- **怎么接进 eval 体系**：**范围是静态图叙事（storyboard/漫画/previz），不是视频**，直接接需适配。但它正中 DirectorBench 反复指认的中心瓶颈——**镜间转场**。可迁移点：Nomi 的 shot→shot 链（时间轴 / `reconcile.ts` 排序）可借 STG 思路评「相邻两镜的转场含义，能否只凭首帧图 / 只凭镜头文案恢复」，作为「转场是否达意」的诊断轴，补进 verify 的连贯对照维度。**待核实**：STG 未在视频上验证，迁移前需在 Nomi 场景小样试算。
