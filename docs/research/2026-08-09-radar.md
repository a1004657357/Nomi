# Nomi 论文雷达 · 2026-08-09（8 月新稿补收）

> **检索窗与方法**：按固定 8 方向查询近 6 个月 arXiv，并重点复核 08-07 雷达后索引稳定收录的 2608 新稿；项目页、代码状态与数据集均回到一手来源核验。只保留能影响 Nomi 行动、架构决策或 eval 的条目。

## 一句话总结

本轮 **🟢 0 / 🟡 2 / 🔵 1**。没有成熟到值得直接接入产品的新能力；最该吸收的是 **VideoArgus 的“输出盲 rubric + 逐项证据 + 硬条件封顶”**，它能把 Nomi 现有逐镜验收从一个总判断推进到可诊断、可回归的判分链。

**本轮最该动的两件事：**

1. 在 `evals/lib/judge.mjs` 与 `src/workbench/generationCanvas/agent/shotVerify.ts` 的下一轮 eval 迭代中，先冻结只依赖 prompt / 参考资产的 rubric，再看候选视频；硬要求失败时限制总分，避免“画质不错”掩盖身份或动作错误。
2. 跨镜记忆只允许通过验收的结果进入长期锚点，并继续区分参考、历史、源素材与当前目标的角色；先把它作为 `canvasPromptContext.ts` / `referenceAncestors.ts` 的契约，不引入论文内部模型或训练依赖。

## 🟡 架构教训

### ContextMaster：历史可以持续增长，但每次生成读取的上下文预算必须固定

- **链接 / 日期**：[arXiv 2608.04956](https://arxiv.org/abs/2608.04956)，v1 **2026-08-05**；[项目页](https://guoxu1233.github.io/ContextMaster/)。来自清华、南京大学、快手 Kling 团队等；项目页已公开方法与样例，本轮未找到公开实现，成熟度不足以直接接入。
- **一句话洞察**：它把 reference、history、source、target 标成不同角色，用 ConstraintSink 保住本次强约束，再在固定读取预算内稀疏检索历史，避免镜头越多上下文成本越失控。
- **影响 Nomi 哪个决策**：Nomi 不应把整段画布历史平铺进 prompt；当前镜头的上游参考、用户显式约束和已验收历史要保留角色边界，并在 `canvasPromptContext.ts` / `referenceAncestors.ts` 形成有上限、可解释的选择规则。
- **诚实边界**：论文收益依赖内部模型训练、蒸馏与稀疏路由，供应商 API 边界外无法照搬；Nomi 只采用“角色分离 + 固定预算 + 强约束常驻”的接口教训。

### Vorch-Director：自回归接力的根因是“训练看干净历史，推理看带错历史”

- **链接 / 日期**：[arXiv 2608.05776](https://arxiv.org/abs/2608.05776)，v1 **2026-08-06**；[项目页](https://vorch-project.github.io/Vorch-Director-project/)。Vorch Team / 浙江大学；项目页明确标注 **Code coming soon**，当前不具备可复现代码。
- **一句话洞察**：逐段续写会把身份漂移、模糊和音画不同步累积到历史中；其训练方案用噪声级匹配的残差纠错，同时始终保留一个不被污染的 1 秒 clean sink 与主体参考。
- **影响 Nomi 哪个决策**：生成结果不能仅因“完成”就成为后续镜头的可信历史；只有通过镜级验收的画面才可进入长期锚点，原始角色/场景参考必须保持为独立的干净来源，不能被最新输出覆盖。
- **诚实边界**：噪声感知纠错属于 LTX-2 模型训练，不是 Nomi 可执行的 API 级能力；这里采用的是“干净锚点不可变 + 失败结果不写入长期记忆”的流程不变量。

## 🔵 对标基准

### VideoArgus：先写判卷标准、再看视频，且每个分数都要能回到证据

- **链接 / 日期**：[arXiv 2608.05485](https://arxiv.org/abs/2608.05485)，v1 **2026-08-06**；[官方代码](https://github.com/zzzmyyzeng/VideoArgus)与 [VideoArgusBench](https://huggingface.co/datasets/zengziyun/VideoArgusBench) 已公开。仓库在 **2026-08-09** 为新项目早期状态（3 stars），但 1,026 个输入、5 类条件任务与可浏览 rubric 已足够做最小接法验证。
- **一句话洞察**：它在看任何候选输出前，按输入生成样本专属的加权 rubric；再用分割、检测、深度、OCR、闪烁探针等工具为每条标准收证据，最后由 VLM 判分，硬要求失败可封顶总分。
- **怎么接进 Nomi eval**：从 T2V、首帧 I2V、主体参考三类各抽 2 个 fixture，映射到 `evals/lib/judge.mjs` 的 analytic rubric 与 `shotVerify.ts` 的 identity / composition / coherence 维度；记录 rubric 版本、工具证据和硬条件封顶，先跑离线回归，不把整套 SAM / DINO 依赖塞进产品。
- **诚实边界**：项目很新、社区信号还弱，全量工具链较重；近期只复用公开 rubric 数据结构和少量 case，不能把论文的人类相关性数字直接当作 Nomi 自身准确率。

## 8 个固定方向覆盖

| 方向 | 2026-08-09 结论 |
|---|---|
| 跨镜角色身份一致 | ContextMaster / Vorch-Director（🟡）都指向“干净主体锚点 + 有界历史”，暂无可直接接 API 的新实现。 |
| Agent 拆镜/导演编排 | 未发现比现有闭环规划与镜级验收更成熟的新 agent 方案。 |
| 运镜/机位/相机轨迹 | UniWorld-View 等新稿依赖 3D 引导与模型训练，和当前供应商边界不匹配，筛掉。 |
| 多镜叙事/转场 | ContextMaster / Vorch-Director（🟡）补强上下文角色与失败历史隔离的架构依据。 |
| 生成质量评测 | VideoArgus（🔵）提供输出盲、证据化、硬条件封顶的可复用考卷。 |
| Prompt 优化 | 未发现兼具近期、公开代码与 Nomi 可落地性的新增条目。 |
| 音频/唇形/TTS | Vorch-Director 把音画漂移纳入长程评测，但能力依赖联合音视频模型训练，暂不接入。 |
| 视频编辑/inpaint/接力 | VideoArgus 覆盖带源视频和主体参考的编辑评测；生成侧没有满足成熟度门槛的新能力。 |

## 上轮 vs 本轮 diff

- **新增到雷达**：ContextMaster（🟡）、Vorch-Director（🟡）、VideoArgus（🔵）；都是 08-05 至 08-06 首发、在上一轮检索时尚未稳定收录的新稿。
- **主线变化**：08-07 的“实体级长期记忆 + 分组 rubric”不变；本轮进一步明确历史必须有固定读取预算、失败输出不得污染干净锚点，rubric 必须在看候选结果前冻结。
- **过期方向：无。** 新稿没有推翻 EntityBench / MSAVBench 的 episode 级与音视频分组评测方向。
- **筛掉的噪音**：机器人 world model、垂直领域视频、需重训的相机/人体控制、没有公开实现且只提升单项画质的工作，以及与上轮行动重复的 prompt 优化稿。
