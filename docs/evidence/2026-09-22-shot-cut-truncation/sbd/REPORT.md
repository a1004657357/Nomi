## 0. 结论先行（六条）

1. **TransNetV2 在两条真素材上都赢 ffmpeg，而且赢在精确率不是召回率。**
   F1（AI 短片，Nomi 生产默认阈值 0.1）：ffmpeg F1 **0.682** → TransNetV2 **0.875**。
   F2（肖申克，同上）：ffmpeg **0.938** → TransNetV2 **0.989**。
   ffmpeg 在 F1 上报了 **33 个假阳性**；我逐个抽帧看过 8 个，**8 个全是运镜/手持造成的同镜头内误切**，TransNetV2 在这些位置 p≈0.00。

2. **「ffmpeg 系统性偏早」不成立——在硬切上它的偏差是 0 帧。**
   实测有符号偏差中位数：ffmpeg **+0.000 帧**（F1）/ **+0.012 帧**（F2）。
   我另用像素 MAE 独立验过两个切点，ffmpeg 报的 `pts_time` 就是**新镜第一帧**，不早不晚。
   真正带偏移的是 **TransNetV2**：它的转场中点恒比真值**早 1 帧**（F1 39/42、F2 44/44 全落在 −1），这是「转场帧算旧镜最后一帧」的约定差，**+1 帧即可对齐**，不是精度问题。
   Nomi 那条 0.1s 量化（`shotTime.ts`）实测是 **±1.0～1.2 帧的对称误差、均值 −0.03 帧**，它解释不了「偏早」。

3. **速度是这次最硬的坏消息。** 在产品真正要跑的 `onnxruntime-web` + wasm 上，
   **单线程 71.7 秒 / 每分钟视频**，**默认（4 线程）26.7 秒 / 每分钟视频**（均为最好一次；中位 91.3 / 31.1）。
   即一条 3 分钟片子，最好情况也要 **80 秒**、中位 **93 秒**。ffmpeg 现在是 **0.75 秒/分钟**。**差约 36 倍。**

4. **ONNX 三方等价，可以放心自己导。** TF → PyTorch → ONNX → wasm 全链路最大逐元素差 **8.8e-8**（sigmoid 概率空间）。官方 `convert_weights.py --test` 本次 10/10 全部 100% 匹配（README 示例只有 99.2%/98.7%）。

5. **两边有一个共同的结构性盲区：黑底/低对比的渐变。**
   F1 片尾 183–200s 的 7 个人工补刀，TransNetV2 只抓到 **1 个**（ffmpeg 也只抓到 1 个）。
   看图确认：那一段是**黑底文字卡互相叠化**，48×27 缩放后几乎没有信息，模型 p 只有 0.03–0.07。
   F3 结尾的「淡入黑 → 片名浮出」同样漏（p 峰值 0.44 / 0.06），ffmpeg 在 128–136s 一个都没报。

6. **选型判断：不要「全片过模型」，走「ffmpeg 粗检 + 模型只复核可疑段」。** 理由见 §6。

## 3. 准确率对比

**口径**：真值 = `shots.json` 里 `shots[].start`（去掉 0）。匹配用贪心最近邻，两档容差：**±0.2s** 与 **±2 帧**。
TransNetV2 的「切点」= 概率超阈值的连续区间的**中点**（产品已拍板的渐变定义）。硬切时该区间宽度 = 1 帧，中点即该帧。

> **这份真值对 ffmpeg 有利，必须在读数前说清楚。**
> `seedCuts` 是 ffmpeg 出的，`manualCuts` 是人**看着 ffmpeg 结果**补的，`shots[].start` 的**秒数直接抄的 ffmpeg `pts_time`**。
> 所以：① ffmpeg 的时间偏差恒等于 0 是**同义反复**；② ffmpeg 没报出来的刀，只有人眼额外注意到的才进真值，真实召回只会更低；③ ffmpeg 报错的地方，人如果没否掉就会变成「真值」。
> §4 我逐个抽帧看过分歧点，**真值本身有多处错**，逐条列在那里。

### 3.3 有符号偏差（回答「谁偏早」）

| | 样本 | 均值 | 中位 | 分布（帧） |
|---|---:|---:|---:|---|
| F1 ffmpeg@0.1 | 52 | +0.115 | **+0.000** | 0帧×44，±5–6帧×7（快剪簇里配错对） |

**结论**
- **ffmpeg 在硬切上零偏差**（但这是同义反复，见上面的真值警告）。我用像素 MAE 独立复核了两处：134.63s 那刀真实发生在 n4039→n4040（MAE 0.6 → **17.5**），ffmpeg 报 `134.667` = n4040 = **新镜第一帧**，正确。
- **TransNetV2 恒早 1 帧**，纯约定问题（转场帧算旧镜最后一帧）。
- **Nomi 的 0.1s 量化**（`electron/shared/canvas/shotTime.ts` `SHOT_TIME_PRECISION_SECONDS=0.1`）实测位移 **均值 −0.026 帧 / 中位 0.00 / 区间 −1.00～+1.00 帧**（F1，30fps）。**对称，不是系统性偏早。**
- 因此 **之前那条「切点比真实早 2–3 帧」的猜想，在这两条素材上没有复现。**

> 注：把 TransNetV2 统一 +1 帧后，F2 的 F1 值不变（0.989），F1 的从 0.875 降到 0.833——因为 F1 的真值秒数本身有 ±几帧毛刺（见 §4）。**「+1 帧」该不该做，取决于后续用自己重标的真值还是这份。**

## 5. 速度（生死数字）

**口径**：一个窗口 = 100 帧输入 / 产出 50 帧新预测。「秒 / 每分钟视频」按 30fps 折算。
**机器有其它会话占用（load 17–39）**，故给「最好一次 / 中位」两栏；PyTorch 与原生 ORT 是**同一进程内逐窗口交替跑**（30 轮），条件相同。

### 5.1 推理

| 后端 | 线程 | ms/窗口（最好 / 中位） | **秒 / 每分钟 30fps 视频（最好 / 中位）** |
|---|---:|---:|---:|
| PyTorch CPU（官方移植） | 4（torch 默认） | 357 / 465 | **12.9 / 16.7** |
| PyTorch CPU | 1 | 539 / 672 | 19.4 / 24.2 |
| onnxruntime 原生 CPU EP（Python） | 默认 | 412 / 590 | 14.8 / 21.2 |
| **onnxruntime-web 1.21.0 · wasm（Node）** | **1** | **1990 / 2536** | **71.7 / 91.3** |
| **onnxruntime-web 1.21.0 · wasm（Node）** | **4（本机默认解析值）** | **741 / 863** | **26.7 / 31.1** |
| onnxruntime-web · wasm | 8 | 699 / 1051 | 25.2 / 37.8（方差极大，不如 4） |

- ort-web 在本机把 `numThreads` **默认解析成 4**（10 核）。不设 = 4。
- wasm session 加载 240–350 ms（31 MB 模型），一次性。
- **wasm 比原生 CPU EP 慢约 1.8×**（741 vs 412 ms，同为多线程）。
- **wasm 跑起来了，没有算子不支持**——5 维 Conv、ScatterElements、GatherND 全过，无报错。

**wasm 默认线程 26.7 ÷ ffmpeg 0.75 ≈ 36×**（最好情况）；按中位算 **41×**。
顺带：**`scdet` 拿全帧曲线不花额外时间**（2.46s vs 2.53s），上一轮调研的 A1 那一刀成本确认为零。

## 6. 选型判断

**一句话：不要全片过模型，走「ffmpeg 粗检 + 模型只复核可疑段」。**

1. **准确率差距集中在少数几处，不是全片。** F2 上 ffmpeg 只要加一条「≤2 帧合并去重」就从 0.938 跳到 **0.989**，和 TransNetV2 打平——**零模型、零下载、十几行代码**。F1 上 ffmpeg 的 33 个假阳性集中在 4–5 个运镜簇里；44 个真刀它一个不差地抓到了。**95% 的硬切 ffmpeg 本来就对。**
2. **为那 5% 付 36 倍墙钟，换不回来。** 3 分钟片子：ffmpeg 2.3 秒 → wasm 全片 **80 秒（最好）/ 93 秒（中位）**。这不是「慢一点」，是把即时操作变成需要进度条和取消按钮的后台任务。
3. **模型也救不了真正难的那一族。** 黑底文字卡叠化、淡入淡出，TransNetV2 的 p 只有 0.03–0.44，**和 ffmpeg 一起漏**。全片过模型既贵，又恰好不解决用户最容易抱怨的那类漏刀。

**建议动作（按性价比排序，前两条不需要模型）**

| # | 动作 | 依据 | 成本 |
|---|---|---|---|
| **A1** | **切点去重：相邻 ≤2 帧只留分数最高的** | F2：51→46 个，P 0.882→0.978，F1 0.938→**0.989** | 十几行 |
| **A2** | **`MAX_CUTS=120` 改成「先降簇再截断」** | F3 实测 447 刀 → 截断后只覆盖前 52.7 秒，用户拿到残表 | 小 |
| **A3** | 用 `scdet=threshold=0` 拿全帧曲线做自适应阈值/簇合并 | F1 的 33 个假阳性全是运镜簇；**换滤镜零额外耗时**（5.3 实测） | 中 |
| **B** | TransNetV2 **只复核可疑段**（ffmpeg 分数 0.1–0.3 灰区 + 密集簇） | 模型唯一稳定强过 ffmpeg 的地方就是「这簇是刀还是运镜」 | 中高 |
| **C** | 黑底/低对比渐变 → **单独一路 `blackdetect`** | 两边在 F1 片尾都是 1/7 | 中 |

**若一定要全片过模型**，必须接受：3 分钟片 80–93 秒、线程必须 ≥4（单线程 72 s/分钟完全不可用）、切点要 **+1 帧**。

**没做但建议下一步做的**：定义并量一次 B 档的「可疑段」判据——灰区段落占全片多少比例，直接决定 C 方案的真实墙钟。本次未测。
